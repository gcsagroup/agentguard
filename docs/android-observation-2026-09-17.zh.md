# Android：未订阅事件与安装词误报修复

日期：2026-09-17。源码基线 `20d97b78b2fd6c823ffde34194be3b33b7a3d37d` 加本批补丁。最终 Debug 为 **1.1.0-dev.10（1000010）**，包名、APK 路径及专用模拟器保持。固定 macOS App 024 没有重建，91 个文件和模式与原清单一致。

## CI 失败及稳定重现

[CI 35120083681](https://github.com/gcsagroup/agentguard/actions/runs/35120083681) 最终 12 项作业成功、Android 失败。Release 单测 100 项中，“未订阅的点击事件应被忽略”失败；该作业的 lint、APK 和 Release 编译随后被跳过。不能用前批 13／13 覆盖它。

服务在判断事件类型之前就调用 `surveyIfNewSession()`，点击事件虽然最终没有进入正文分支，后台环境扫描已经排队。旧测试立即检查磁盘，扫描慢时会误判通过，快时则失败。先只修改测试同步：等待真实扫描队列排空后再断言，旧生产代码稳定得到 **10 通过、1 失败**。

现在在任何窗口读取、隐私分类或后台扫描之前，只接受配置中订阅的三类事件：文字变化、窗口内容变化和窗口状态变化。其它类型立即返回。测试仍要求“点击不产生记录”，并在检查每会话只扫描一次以及清理前等待队列完成；没有删除断言、延长生产期限或关闭环境扫描。

## 原生复查发现的另一条误报

dev.9 已包含上述事件过滤修正，但在既有 `AgentGuard_API26` 模拟器回到桌面时，实际出现 `CRIT-005` 安装通知。该会话留下 1 次环境扫描和 4 条窗口文字事件，其中 2 条是固定 `Install` 证据；原截图、事件及风险时间戳均保留。

旧文字规则把 `Install` 当作子串，`Uninstall`、`Installed apps`、`Installation complete` 和 `Installer settings` 都会命中。新增回归在旧规则上因 `Uninstall` 稳定失败。最终规则只为英文 `Install` 增加单词边界，保留真正的 `Install`、中文安装提示、付款和明确注入检测；混合输入中的明确注入仍被识别。没有过滤隐藏节点或增加应用白名单。

原始窗口文字没有进入事件文件，因此不能断言具体是哪一个节点的哪段原文触发了旧提醒。观察到的系统 UI 树还包含被 UIAutomation 跳过的隐藏区域；这只是排查线索，不作为已证明的攻击或根因。上述改动限于英文词形误匹配，**不宣称全部普通文字误报已经消除**。
