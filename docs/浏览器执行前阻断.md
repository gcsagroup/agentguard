# 浏览器执行前阻断（首个 GA）

[简体中文](浏览器执行前阻断.md) | [繁體中文](浏览器执行前阻断.zh-TW.md) | [English](浏览器执行前阻断.en.md)

> 结论：首个 GA 在 Chrome / Edge 上采用两条 **block-only** 控制路径。匹配的页面 DOM 动作同步阻断；匹配的网络请求由浏览器静态 DNR 硬阻断。网页内不存在允许、继续、重放或临时例外入口。

## 两条互不混用的控制路径

| 路径 | 当前处置 | 放行边界 |
|---|---|---|
| 浏览器允许扩展注入的 HTTP(S) frame 内的付款／转账 CTA、隐私陷阱个人信息提交 | `document_start` 注入的 isolated content script 在 window 捕获阶段同步 `preventDefault()` 并阻止传播；可显示信息提示 | 网页内**不能放行**，不重放原动作 |
| 付款形状的非只读网络请求 | GA manifest 默认启用静态 DNR `payment_shape_block`，由浏览器在网络层直接 block | 无确认、页面判决、scope 例外或一次性放行 |

两条路径是独立的。DOM 检测没有命中不表示网络会放行；只要请求命中静态 DNR，网络层仍会阻断。反过来，静态 DNR 没有命中，也不能把已被 DOM 门阻断的动作重新放行。

## 页面内提示不是授权 UI

信息提示位于普通页面 DOM 可影响的环境中。敌对网页能够删除、遮挡、仿冒或改变它的可见效果，因此：

- 提示只解释“什么被阻断”和能力边界，不表达或收集授权；
- 没有“允许一次”、继续或重试按钮，页面点击不会产生授权令牌；
- 页面脚本合成事件、`postMessage`、旧 decision/scope 消息或等待超时都不能放行；
- 提示没有显示出来，也不改变已完成的阻断结果。

如果用户理解风险后仍决定继续，唯一支持的流程是进入浏览器拥有的受信扩展管理界面：Chrome 使用 `chrome://extensions`，Edge 使用 `edge://extensions`。用户在那里停用或移除 AgentGuard 后，再自行重新发起原操作。首个 GA 不提供站点例外、动作例外或临时暂停按钮。

## 页面消息不再是信任根

旧版 MAIN-world `guard-page.js` 与公开 `window.postMessage` request/decision/scope 通道已被移除。GA 内容脚本不监听或发布这些公开判决消息，静态 DNR 也没有页面可写的例外。普通网页上下文和页面内信息层均不是授权根。

## 静态 DNR 的精确支持面

规则文件：`apps/extension-chromium/rules/payment-shape-block.json`。

只有同时满足以下条件才阻断：

1. URL scheme 是 HTTP 或 HTTPS；
2. 请求方法不是 GET 或 HEAD；
3. 以下两种 URL 形状至少命中一种：
   - **路径组件**以以下 ASCII 付款标记之一开头，并满足规则的字符边界：`pay`、`payment`、`checkout`、`charge`、`transfer`、`remit`、`purchase`、`orderconfirm` / `order-confirm` / `order_confirm`、`confirmorder` / `confirm-order` / `confirm_order`；路径规则还明确接受核心标记的逐字节百分号编码与 `%2F` 路径分隔符；
   - 查询键为 `op`、`action` 或 `operation`，值明确等于上述付款标记之一并满足字符边界；
4. 浏览器把请求分类为以下资源类型之一。

| 网络 API / 行为 | DNR 资源类型 | 当前声明 |
|---|---|---|
| `fetch()` | `xmlhttprequest` | 支持 |
| `XMLHttpRequest` | `xmlhttprequest` | 支持 |
| `navigator.sendBeacon()` | `ping` | 支持 |
| HTML form 的顶层导航 | `main_frame` | 支持 |
| HTML form 的 iframe 导航 | `sub_frame` | 支持 |

标记匹配大小写不敏感。标记后必须是路径/值结尾或非 ASCII 字母、数字、下划线字符；例如 `/pay-now`、`/%70ay`、`/p%61y`、`/api%2Fpay` 与 `/api?op=pay` 会命中，`/prepay`、`/payment_status` 与 `/api/search?next=/pay` 不会命中。规则随 Chrome / Edge GA ZIP 打包并默认启用，不依赖页面脚本或 Native host。

## 明确不支持或不承诺

- GET/HEAD，即使路径名为 `/pay`；
- 只有请求 body 表示付款；DNR 不检查 body；
- 站点自定义别名、未列关键词、未明确列出的编码/双重编码/混淆形式，以及 `op` / `action` / `operation` 之外的任意查询键或未列值；
- WebSocket、WebTransport 及未列出的资源类型；
- 浏览器未注入内容脚本的页面/协议、直接 `form.submit()` 或不产生被监听事件的脚本路径；已声明的普通子 frame 路径由自动化覆盖，但不据此宣称所有特殊 frame 都可注入；
- 页面提示的完整性、可见性或真实性；它只是可被页面影响的信息层；
- 浏览器之外的原生 App，以及 Firefox / Safari 的首个 GA 支持。

## GA 包与 Native Messaging 边界

- 首个 GA 只交付 Chrome / Edge 共用的 Chromium ZIP。
- Firefox 的 manifest 与相关源码仅作为后续原型保留；发布脚本拒绝 `--firefox`，Firefox 不打包、不提交，也不作为首个 GA 验收门。
- GA manifest 不包含 `nativeMessaging`。商店 ZIP 不含 Native host，也不声明 Native 判决、动态主机阻断或本机审计链能力。

## 自动验证

- `apps/extension-chromium/scripts/gate.test.mjs`：危险动作分类与 DNR 纯逻辑边界。
- `apps/extension-chromium/scripts/content-event.test.mjs`：真实内容脚本事件接线保持 block-only，不重放原动作。
- `apps/extension-chromium/scripts/manifests.test.mjs`：GA manifest 无 Native Messaging、静态规则默认启用、Firefox 不进入 GA 包。
- `apps/extension-chromium/scripts/package-store.test.sh`：Chrome / Edge ZIP 内容与 `--firefox` 拒绝行为。
- `eval/e2e-extension/run.mjs`：Chromium 环境中的 DOM 不执行、旧消息不放行、DNR 在请求到达服务器前阻断和负向不误拦。

离线验证是必要非充分证据。Chrome 与 Edge 的商店候选仍需分别保存安装、升级、权限提示与真实浏览器行为证据。
