# 工具网关（A1）

`crates/guard-gateway`，二进制是 `agentguard-mcp`。设计依据是
[interception-design.md](./interception-design.md) 的 A 层。

## 它改变了什么

在这之前，AgentGuard 是**旁路观察器**：它看到的每一样输入都描述一件**已经发生**的事——
`TYPE_VIEW_TEXT_CHANGED` 是因为文字已经变了，一帧画面上有付款界面是因为付款界面已经画出来了。
判决出来时，还能做的只有记下来和告诉人。

网关改的是**位置**，不是判决逻辑。智能体调 `agentguard.run_shell` 而不是调自己的 shell，于是
网关是那个**执行者**；执行者拒绝执行，是拦截，不是建议。

92 条规则加上 B0 的路径模型，在这条路径上第一次变成能拒绝的东西。

## 但这是协作式控制

一个直接 `std::process::Command` 的智能体框架**完全绕过它**。这不是缺陷，是这一层的定义：

| | 协作式 | 内核执行 |
|---|---|---|
| 谁来拒绝 | 守卫（因为它是执行者） | 内核 |
| 对不配合的智能体 | 无效 | 有效 |
| 本项目现状 | **A1，已做** | B2/B3 `guard-jail`，未做 |

所以每一条响应、`initialize` 的 instructions、`gateway/stats` 都带 `enforcement: "cooperative"`。
本项目在自己的能力表里已经把「通知」和「阻断门」记成同一个勾一次，不能再来一次。

## 判决到行为的映射

| 判决 | 行为 |
|---|---|
| `Allow` / `LogOnly` | 执行 |
| `Alert` | 执行，**并把发现附在结果里**让智能体自己看到 |
| `Block` | **不执行**，返回点名规则的工具错误 |
| `require_confirm` | **挂住调用**等人答；超时**拒绝** |

`Alert` 执行而不是拒绝是有意的：告警的语义是「这值得知道」，不是「这不许做」。把它升级成拒绝，
会让误报的代价变成工作被打断。

## MCP 让确认变得自然

一次 MCP 工具调用是**请求/响应**，而智能体在等。按住响应就是按住动作——不需要内核机制、不抢
输入焦点、也不会把人一起拦住。Aura 的 Critical Node 闸门在这里几乎是免费的，因为协议本身就是
这个形状。

这是网关比观察器强得毫无争议的一处：观察器看到无障碍事件时点击已经发生了，这里动作还没开始。

答案从环回 HTTP 进来（只绑 `127.0.0.1`——一个能远程批准动作的端口就是把闸门送给网络）：

```
curl -s localhost:8790/pending     # 当前待确认的是什么
curl -XPOST localhost:8790/approve
curl -XPOST localhost:8790/deny
```

**超时按拒绝处理。** 这是整个网关唯一不能搞错方向的地方：一个等不到答案就放行的闸门，被攻击的
方法就是等，而等待是免费的。审计里「人拒绝了」和「没人在」是分开记的（`source: human` / `timeout`），
因为这是两件不同的事实。

## 只走 argv，绝不交给 shell

每条命令都以参数向量 `exec`，永远不经过 `sh -c`。这是论文里的 Secure Command Construction
（(A)I Sees §IV-C 的 A7 攻击就是宿主对 VLM 输出用了 `shell=True`），也是 `guard-shell` 元字符检查
存在的前提：如果最终还是交给 shell，挡住 `;` 和 `|` 只是在减少攻击面而不是消除这一类攻击。

有一条测试专门证明这件事：把 `a; touch <marker>` 作为参数传给 `/bin/echo`，然后断言
marker 文件**不存在**——`;` 被当成了字面字符而不是命令分隔符。

## 天花板替代逐次确认

这是 A1 里唯一一处**放松**，而且它是被测试逼出来的。

第一版没有它，结果是：默认策略里 `write_file` 和 `run_terminal` 都属于 `require_confirm`，于是
网关对智能体的**每一次写、每一条命令**都挂起等人答。两个本该通过的测试因此失败——那不是测试
写错了，那是网关在告诉我它不可用。而一个不可用的闸门会被关掉，关掉之后防护是零。这和 B0 自查
时改掉的两处是同一类错误：**把「更严」当成「更安全」**。

天花板可以替代确认，因为人已经答过了——在 `task-plans.yaml` 里，会话开始之前。`scope.paths` 就是
那句事前授权，这正是 Aura §4.4 会话令牌的模型：令牌带着事前批准的范围，范围内不再逐次问。

三条不放松的边界，每条都有单独的测试钉住：

1. **天花板必须已声明。** 没声明就没人答过，照旧挂起。
2. **每个路径操作数都必须可归约且落在授权内。** 通配符、空串、归约不了的东西都不算——
   「证明不了」不是「在里面」。
3. **只对 `SHELL-CONFIRM` 生效。** 引擎自己判的 `require_confirm`（`CRIT-*`：付款、转账）在
   路径那道门之前就返回了，天花板碰不到它；`SHELL-PATH-*` 的 Ask 也不适用，因为那些恰恰是
   「证明不了」。

还有一条容易漏的：**没有路径操作数的命令**（`git status`、`echo`）照旧确认。`all()` 对空集返回
`true`，所以把 `claims.is_empty()` 当成「全部都在里面」是一行就能写出来的严重放松。

## 引擎那道门实际贡献什么

这一段第一版写错了，值得留着说明白。当时注释里写的是「拿 `PLAN-*` / `SCOPE-*` / `CRIT-*`」，
然后一条测试失败了：27 条 YAML 规则**全部**声明了 `platforms`，而网关的 platform 是 `gateway`，
不在任何一条的列表里——三样东西里有一样根本没接上。这正是本项目反复抓到的第二种缺陷形态：
机制存在、被直接测过、被描述成完整的，然后没接上。

准确的说法：

* **引擎自身的判据**（`PLAN-*`、`SCOPE-*`、`SESSION-*`、`FLOW-*`、`AGENT-*`）是 Rust 状态机的结论，
  不是 YAML 规则，不受 `platforms` 影响。这是引擎在这条路上真正贡献的部分。
* **`CRIT-*`** 的 platforms 加上了 `gateway`，所以「这段文本意味着一次付款/转账/永久删除」在网关
  上也会触发。修法是改规则的平台列表，**不是**让网关谎报平台——谎报会把一条 Linux 上经网关发生
  的动作在审计里记成 macOS，和共享 `uitree` 时硬编码 `"macos"` 是同一种错误。
* **`OVL-*` / `ENV-*` / `UI-REVALIDATE` 刻意不扩到网关。** 它们分别需要像素、Android 环境、UI 树。
  有一条测试钉住「只有 `CRIT-*` 带 gateway」，防的是将来有人图省事加到全部 27 条上。

## 怎么用

```
cargo run -p guard-gateway --bin agentguard-mcp -- \
    --rules crates/guard-schema/rules/p0_rules.yaml \
    --shell-policy crates/guard-shell/policies/default.yaml \
    --plans policies/task-plans.yaml --task book_hotel \
    --confirm-port 8790
```

然后在智能体的 MCP 配置里把它作为一个 stdio server 加上。

`stdout` 是 MCP 通道，往里写任何非协议内容都会破坏它，所以整个程序里只有一处 `println!`，
人话全走 `stderr`。

不给 `--plans` 也能跑，但那时没有天花板，写和删只能判成「证明不了」，于是每一次都要确认。

## A1 没有做到的事

**绕过它是可行的。** 见上面那张表。这不是待修的缺陷，是这一层的边界。

**引擎仍然看不到文件操作。** 网关把一次工具调用装进 `EventType::UiTreeDelta` 送进引擎，因为
`EventType` 里**还没有** `FileWrite` / `FileDelete` / `ProcessExec`——那是设计文档的 B1。现在的后果是
命令文本会走文本类规则（注入、异常字符、`CRIT-*`），但走不了任何以「这是一次删除」为前提的规则。

**没有能力令牌。** 非 MCP 的执行器目前接不上，那是 A2。

**执行是同步的、单线程的。** 一次挂起的确认会挡住后面所有调用。对一个逐次确认的闸门来说这是
对的语义，但它意味着网关不能并发服务多个智能体。

**没有在真实智能体上跑过。** 有 24 个单元测试和一条端到端的 stdio 验证（1 执行、3 拒绝，并且
用文件系统状态证实了那三次拒绝是真的），两者都不等于看着它拦下过一次真实的误操作。
