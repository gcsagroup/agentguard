# AGD-020：网关摘要与审计事务修复

日期：2026-09-15。**性能原预算目前为 5/6，AGD-020 继续实施。** 本批修复代码已通过完整仓库测试、真实 SQLite 故障与 Docker 回写回归；读取 p95 仍超标。固定路径 Ver 2.0（012）App 没有重建或替换，本页是新网关的诊断证据，不能借用旧 App 的原生验收结论。

## 已完成的修改

- ARM 网关启用 SHA-256 的运行时硬件检测，并在开发构建中仅优化 `sha2` 算法库。仍计算完整可执行文件的摘要，不用版本字符串代替包身份；不支持对应指令时保留软件回退。
- 无需等待批准的动作在最终资格校验后，将判决和执行开始两条记录放在同一事务中提交，成功后才能派发。待批准判决仍先持久保存；最终校验拒绝的动作仍保存判决和拒绝终态。任一插入失败会回滚整对记录，并禁止当前会话继续执行。
- 表、索引、兼容列和日志身份一起迁移，失败时回滚整次迁移。原 `synchronous=FULL`、`fullfsync` 和 `checkpoint_fullfsync` 均保留。
- 单条与成对追加都在读取链头前取得 SQLite 写锁。加强原并发测试后，旧实现的 50 次追加中有 **40 次失败**，而原测试只检查剩余链是否正确；修复后必须 50 次全部成功且链完整，不能以调用方重放补齐。

新增测试覆盖第二条插入失败时的签名序号与计数回滚、独立连接读回、开始后重启只恢复一次未知、待批准／拒绝判决不能使用执行批次，以及迁移末尾失败时不能遗留半套表。实际读取仍留下判决、开始和终态三个独立事件，来源另行持久保存。
