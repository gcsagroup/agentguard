# 桌面端使用说明

## 先区分三条防护路径

| 路径 | 能做什么 | 不能据此宣称什么 |
| --- | --- | --- |
| 桌面观察 | 读取已呈现的窗口状态，发现风险、提醒并记录 | 不能撤销已发生动作，也不保证事前拦截 |
| Chrome / Edge 扩展 | 对匹配的点击、陷阱表单和特定付款形状请求执行阻断 | 不覆盖所有网站和动作；当前没有网页内允许一次或临时例外 |
| MCP 工具网关 | 对真正经过网关的工具调用执行允许、拒绝或等待确认 | 智能体直接执行可绕过；握手成功不等于客户端接入成功 |

浏览器扩展独立工作，首个 GA 没有 Native Messaging。桌面 App 不会读取扩展状态、代替浏览器授予权限，或自动合并扩展记录。

## macOS：新工作区

当前 macOS 工作区包含六个入口：**总览、主动防护、活动记录、知识库、防护设置、帮助与诊断**。Windows 尚未同步此布局，仍从原界面的守护控件、观察状态、活动时间线和开发者面板进入。

### 第一次开始桌面观察

1. 在总览检查“辅助功能”和“加密活动记录”。辅助功能是必需权限，屏幕录制只增加可选的像素与浮层检测；只给录屏不能启动桌面观察。
2. 从“防护设置 → 桌面观察”打开系统设置，核对总览列出的**当前应用文件名和诊断页路径**。本项目开发、测试和本地模型任务统一使用 `AgentGuard Local Agent Test.app`。
3. 由用户在系统设置授权；回到总览点击“重新检测权限”。App 也会在返回前台时只读刷新，不自动授予权限。若系统要求重启，退出并重新打开同一份 App。
4. 加密记录已就绪且辅助功能可用后，选择任务并点击“开始守护”。任务选择保存在本机，只在下一次会话开始时生效。
5. “结束守护”停止会话与观察器。界面的守护状态依据会话、观察器、心跳及记录可写性计算，不以按钮点击作为成功证明。

当前唯一日常入口为 `apps/desktop-macos/src-tauri/target/debug/bundle/macos/AgentGuard Local Agent Test.app`，标识固定为 `com.agentguard.desktop.macos.localagenttest`，沿用已配置的组织签名身份。版本号随构建递增，应用名称和路径保持不变。早期 acceptance、Production、Recovery 等名称仅属于历史候选；旧条目的权限不能当作当前 App 的授权证据。正式分发仍须满足签名与公证门槛，不为排障批量重置系统权限。

若加密记录尚未就绪，先查看总览专用恢复提示。钥匙串提示由用户处理；历史明文数据只经过明确确认的保留历史升级流程，不删除原始数据库或用空库冒充恢复成功。

若系统开关已开，App 重启后仍显示“未检测到”，应先核对当前 App 签名和系统拒绝原因，停止反复构建。2026-09-15 的本地模型候选确认旧授权的代码签名要求失配，仅切换开关无效；移除失配条目并从准确固定路径重加后，辅助功能生效。录屏另行完成当前 App 的系统授权；同包重启、真实 AX 窗口读取与原生屏幕帧观察均已核对，见[014 权限记录](agd-020-native-014-permissions-2026-09-15.zh.md)。本项目日常仅使用 `AgentGuard Local Agent Test.app`，版本递增不再改变名字，旧包已移出应用目录归档。

### 防护设置的四个标签

- **桌面观察**：权限实际状态、系统设置与重新检测、下一次任务范围。
- **风险处理**：按桌面、扩展、网关说明真实处置；显示当前情报版本与重新加载。网关默认超时 120 秒，未回应拒绝；此处是默认说明，不是某个外部网关的实时配置回读，也没有假保存开关。
- **隐私与记录**：本机加密记录状态、活动摘要导出、数据恢复说明。桌面与扩展记录分开，不提供没有恢复保障的全部清空。
- **通用**：简体、繁体、英文、跟随系统；浅色、深色、跟随系统外观。偏好保存在本机，失败时提示，不修改安全策略。

## 主动防护：怎么接入

### 在桌面启动本地模型任务

在总览或“主动防护”打开“开始本地任务”，通过系统选择器选择一个具体项目目录。先启动本机模型服务，再刷新模型列表；本机验收使用端口 `8000` 上已加载的 `Qwen3.6-35B-A3B-Uncensored-Heretic-MLX-4bit`，桌面不会替你下载或加载模型。

本地任务沿用上述同一份 `AgentGuard Local Agent Test.app`。2026-09-10 已按用户要求使用 `Global Cybersecurity Alliance Limited` 的 Apple Distribution 证书签名，当前机器可正常启动，严格签名检查通过；Gatekeeper 分发评估未通过。早期签名操作见[组织签名记录](agd-m1-organization-signing-2026-09-10.zh.md)，当前版本以总览页脚及最近候选验收记录为准。

1. 默认“只读项目副本”，只提供文件读取和搜索。要生成文件、修改代码或运行测试，选择“修改副本并运行测试”，然后输入任务并启动。
2. 桌面建立断网 Linux 工作区副本，显示实际工具步骤。需要批准时，进入“查看待确认操作”核对最终动作；模型回答只代表本轮结束，仍须检查实际成果。
3. 点击“预览成果”，逐一展开文件的修改前后全文，核对目标与恢复目录，勾选“我已核对全部文件差异、目标原目录及原件恢复目录”后批准本批回写。未批准时原目录不变；发生冲突时保留用户编辑并显示结果。继续下一轮前先处理当前预览。
4. 暂停会撤销当前轮次；恢复后须明确输入追加任务，不会重发中断动作。结果未知的会话不能恢复，需先核查副本与回写记录。
5. “停止”或关闭主窗口会停止本次模型请求和拥有的网关；“断开并停止任务”也会一同停止。共享模型服务继续运行，私有副本和审计记录保留。

这条入口使用桌面自己的本地模型工具循环，只连接 `127.0.0.1`，不继承第三方客户端插件或原生工具。命令的工作目录固定为所选项目根目录，支持中文和空格；子目录文件通过参数引用。它不等于 Codex 或其它客户端接入验收，也不支持远程模型、依赖安装、联网任务或宿主原生应用操作。具体验证与限制见[本地任务专项记录](agd-m1-local-agent-2026-09-10.zh.md)。

### Chrome / Edge

在“主动防护 → 浏览器防护 → 安装与验证”打开随包扩展目录与无害验收资源。当前为本地测试包，不是已发布商店版本。

1. 用户在浏览器受信的扩展管理页安装测试扩展、确认权限并启用。不要从网页里的伪造提示授予权限。
2. 打开随包验收目录，按其中 README 在 `127.0.0.1` 提供测试页面；直接双击 file:// 不作为 HTTP 网页覆盖验收。
3. 普通按钮计数应该增加；“Pay now”只是本地计数测试，没有付款和外部网络动作，匹配阻断生效时付款计数应保持 0。
4. 在扩展自身界面核对记录。桌面端没有连接通道，因此保持“请在浏览器中验证”，不会自动显示已连接。
5. 本版只阻断，不提供网页内放行、动作重放或站点例外。不能将某个测试通过扩大成所有付款都被阻止。

### 智能体工具网关

#### 隔离工作区与差异回写（2026-09-09 续作）

先由宿主按[隔离工具试点](agd-007-snapshot-pilot-2026-09-09.zh.md)启动带持久审计和控制连接文件的网关，再在主动防护页选择该连接文件。App 使用系统文件选择器导入，令牌留在 Rust 内存，不需要查看日志或复制到输入框。

连接后可看到真实会话、工作区、副本位置和回写支持状态。选择工作区预览完整差异；不接受初稿时点击“放弃本次差异”，任务继续在副本修改。核对文件前后内容、模式和恢复目录后勾选应用，再查看逐文件实际结果。

暂停会撤销当前批准并取消工具；恢复维持原范围和副本但更换会话标识，客户端必须使用新标识。停止永久结束本实例。部分完成或结果未知会禁止重复回写，应先核对宿主文件及恢复原件。完整限制与证据见[回写和会话说明](agd-m1-workspace-control-2026-09-09.zh.md)。

该入口目前仍需宿主先启动；下面的既有 Codex 命令生成流程仍属于原生协作式接入，没有自动升级为隔离会话。

#### Codex 本地代码任务（9 月 8 日本机验收入口）

在“主动防护 → 智能体工具网关 → 配置接入”填写项目绝对路径与本次任务。

1. 默认“只读与搜索”，禁止写入、删除和命令执行；需要生成文件或运行测试时，明确选择“读写与测试”。不要授权整个个人目录或系统根目录。
2. 点击“检查并生成本次命令”。App 先握手检查随包网关，再把本次范围存入应用自己的 `gateway-setups` 目录；不会修改项目文件或 Codex 全局配置。该配置在生成后保留，不自动到期；再次生成会创建独立文件。
3. 复制启动命令，在已登录 Codex 的终端执行。当前参数已用 Codex CLI 0.153.4 验证；后续版本需要复验。命令使用已验证的 HTTPS 连接方式并关闭已列出的原生工具入口，工作区外普通文件也受已声明的读取范围限制。
4. 修改工作区、任务或权限后，旧命令立即失效于界面，必须重新生成。之前已复制到终端的命令不会被远程撤销，已启动任务须在原终端停止。
5. “前往确认通道”定位到连接区。隔离模式载入本次控制文件；此处生成的既有原生命令则展开“旧版手动连接”，填写本次进程的端口与日志令牌。连接与生成配置是两件事，不能把“程序检查通过”当成“任务运行成功”；无人应答会超时拒绝。

这条入口依然是协作式网关。读写模式允许的命令并没有系统级文件/网络隔离，路径规则也不能证明任意程序的全部内部行为。确认通道的凭据发现、任务实时状态、脱敏持久审计尚未与此入口打通。详细证据见 [本机验收记录](desktop-codex-setup-acceptance-2026-09-08.zh.md)。

#### 其他 MCP 客户端

在“主动防护 → 智能体工具网关 → 配置接入”点击“检查网关并生成配置”。

- App 启动自己的随包网关，仅进行 MCP 握手与工具列表查询，随后退出该检查进程；不调用工具、不写入测试文件，也不改写任何客户端配置。
- 生成通用 stdio MCP 配置；路径指向**当前安装包**，不会默认授权整个用户目录，也不把确认令牌写进配置。
- 用户选择实际使用的 MCP 客户端，保留原有配置后合并新增服务；若需要写入权限，先明确任务和最小目录，不照搬宽权限示例。
- 重启该客户端后，用无害输入分别验证允许、拒绝、需确认和超时；通过文件/请求的实际副作用核对，不只看提示。桌面检查成功只表示随包程序可启动，客户端状态仍标为“接入尚未验证”。
- **桌面网关确认现已接入。** 隔离网关优先选择本次控制连接文件。原生兼容模式在“旧版手动连接”填写当前进程的本机端口和 32 位确认令牌；该模式令牌从本机 stderr 日志获取，只填入 App，不发送到网页、聊天或报告。旧版网关没有状态接口时需更新随包程序。
- 确认通道连接后，查看当前编号、完整操作、风险判据和剩余期限。拒绝可直接点击；批准前必须勾选已核对，批准只针对当前请求。新请求不会继承旧勾选或回执。网关的批准回执不等于工具执行成功，最终结果在发起调用的客户端核实。
- 令牌输入提交后清空，只在当前后端连接的内存保留，不写入设置；断连、App 退出后不自动重连。通道故障或过期会禁用批准；手动断开不等于立即拒绝，但无人回答时网关最终超时拒绝。回执不明不会自动重试，可能已执行，须到调用端核对。
- 此通道与旧桌面“继续监控”独立；只连接一个网关进程。它不验证具体客户端、不会自动合并网关记录到桌面活动页，也不绕过 `Block` 判决。详见[工具网关](工具网关.md)。

## 活动记录与诊断

“活动记录”展示桌面会话摘要；最近活动只展示规则标识与来源，不展示外部正文。导出是本地摘要操作，界面显示结果路径。构建版本、时间、实际 App 路径、验收数据目录及开发者控件集中在“帮助与诊断”，路径默认折叠。

桌面自检使用本机构造的假事件，不联网、不付款。它只证明规则、提醒和记录链路，**不是观察器已工作或外部动作已阻断的证据**。收到桌面提醒后，应到执行动作的原应用核实结果；暂停只影响后续受保护处理。

## 当前验收边界

新 UI 的本地编译、界面测试或真实启动不等于可发布。网关确认可在本机独立验收，但指定客户端接入、macOS 实际授权后的连续观察、正式签名、公证与隔离安装仍需单独证据；Windows、Android、iOS 和各浏览器商店也各自验收。详见[发布证据](release-evidence.md)。
