# 桌面端使用说明(macOS / Windows)

这份文档回答四个问题:**这是什么、怎么开、怎么知道它真的在工作、它做不到什么。**
它对应桌面应用里那张「怎么用」卡片 —— 卡片是三步速览,这里是完整版。

真机反馈促成了这份文档:此前应用主界面只有一个「开始会话」按钮和一行
`规则 27 · intel 2026.07.30 · AX=false · Capture=false · SCK=idle`,没有任何说明。

## 这是什么

AgentGuard **不替你操作任何东西**。它在旁边看着 AI 智能体(浏览器里的、桌面上的)对这台机器
做了什么,遇到高危动作**在动作发生之前**按住、弹一个必须回答的确认层,并把每条判决写进本地审计。

它**不是**杀毒软件、不是防火墙、不是通用沙箱,也不是"零间隙实时监控":桌面观察路径包含采样与轮询,
间隙里发生的事可能看不到。完整边界见 [README](../README.md) 的「必须理解的边界」一节。

## 一、授权(只有 macOS 需要)

macOS 上要两项系统权限,少一项就少一路观察:

| 权限 | 给了它什么 | 没给会怎样 |
|---|---|---|
| 辅助功能(Accessibility) | 读**窗口内容**:控件文字、表单字段、按钮标题 | 读不到界面文字,表单与付款按钮类规则全部失效 |
| 屏幕录制(Screen Recording) | 读**屏幕画面**:透明浮层、隐写像素、画面上的文字(OCR) | 读不到画面,浮层与隐写类规则全部失效 |

两项都没有时,应用会如实显示**「防护范围:仿真」**——只有仿真事件与浏览器扩展那条路在起作用。
这不是错误提示,是它拒绝假装在保护。

应用里第一步的两个按钮会直接把系统设置打开到该点的那一页,不用自己找四层路径。

> **未签名构建的已知问题。** 如果系统设置的列表里根本找不到 AgentGuard,或者开关点了不生效、重启后
> 又变回关:这是 **ad-hoc / 未签名构建**的正常表现 —— macOS 把这两项授权钉在签名身份上,身份不稳定,
> 授权就留不住。正式签名(Developer ID + 公证)的版本才稳。当前仓库尚未完成签名与公证,
> 见 [release-evidence.md](release-evidence.md)。

Windows 上不需要授权任何权限:读窗口内容(UI Automation)、抓屏(GDI)、读屏上文字(Windows.Media.Ocr)
都不走 macOS 那套逐项授权。会变的是这三样在**这台机器上**可不可用 —— 应用里的「实时观察」卡片
逐项写出可用/不可用**以及原因**。

## 二、开始守护

点「**开始守护**」。这一下做三件事:

1. **开一次会话。** 会话是审计与策略的边界:每条判决按会话归档,导出报告也按会话导出。
2. **启动你授权过的观察器。** macOS 上授权了辅助功能就开窗口内容观察(AXObserver 推送 + 兜底轮询),
   授权了屏幕录制就开抓屏;Windows 上观察随会话启动。**结束守护时它们一起停** —— 不会"结束了还在采集"。
3. **套用任务上限(可选)。** 上面的「本次任务」下拉选了就同时限定这次会话能做什么:选「订酒店」,
   这次会话里发起转账会被拦;不选就是不限定。

状态灯与「现在在看什么」那行是**从事实推出来的**,不是从"你点过按钮"推出来的:

| 状态灯 | 意思 |
|---|---|
| 未在守护 | 没有会话。 |
| 需要授权 | 会话开着,但没有任何观察器能跑(macOS 两项权限都没给)。 |
| 守护不完整 | 会话开着、观察器却没在跑,或心跳过期,或审计写不进去 —— **不会显示成绿色**。 |
| 守护中 | 会话 + 观察器在跑 + 心跳新鲜 + 审计可写,四条同时成立。 |
| 有一条确认等你 | 有高危动作被按住,等你回答。 |
| 已暂停 | 上一次拒绝之后引擎暂停了这条会话;点「恢复暂停」继续。 |

## 三、遇到风险时会发生什么

高危动作(付款、转账、隐私陷阱表单、透明浮层里的注入……)会弹出一个**必须回答**的确认层:

- 点「**先不要,暂停任务**」(Windows 壳子上这个按钮就叫「先不要」):动作被按住,不放行。这是默认焦点所在的按钮。
- 点「**允许这一次**」:只放行这一次,不是永久授权。
- **两分钟没人回答**按拒绝处理,并写一条 Timeout 回执 —— 不会悄悄消失,也不会默认放行。
- 键盘:Tab 只在弹层内循环,Esc 等于「先不要」;读屏用户会听到播报。

每条判决(放行、告警、阻断)都进本地审计:哈希链、可逐条签名。看得见的入口是应用底部的
「活动时间线」,以及「导出摘要」。

### 想立刻看到它工作:自检

第三步里的「**自检:模拟一次付款拦截**」按钮会喂一条**本机构造的假事件**给引擎:确认层会真的弹出来,
时间线上会真的多一条判决。它**不会**真的付款、**不联网**,而且它**不是观察** —— 它证明的是
"规则会触发、确认层会找到你",不是"这台机器正在被观察"。

## 什么都没发生?按顺序查

1. **状态灯是「未在守护」** → 还没点「开始守护」。
2. **是「需要授权」或横幅写着「防护范围:仿真」** → 回到第一步授权;若列表里找不到本应用,见上面
   未签名构建那一段。
3. **是「守护不完整」** → 灯下面会列出原因(观察器没在跑 / 心跳过期 / 审计写不进去),照着那条处理。
4. **状态是「守护中」但时间线一直空** → 正常:没有可疑动作就没有判决。用**自检**确认链路通着。
5. **想确认观察器真的在动** → 展开「开发者面板(演示与诊断)」:那里有原始状态行
   (`AX=… · Capture=… · SCK=…`)、单次观察按钮和判决原始日志。主界面刻意不显示这些。

## 开发者:在 Linux 上把壳子跑起来

不需要 Mac 也能验证"前端 ↔ 真后端"这一层:`make shell-run-linux`(要 Xvfb + xdotool + webkit2gtk-4.1)
会编译壳子、无头跑起来、点一遍「开始守护 → 自检 → 先不要 → 结束守护」并留五张截图;
Windows 壳子加 `SHELL_NAME=windows`。
**它不能替代真机**:Linux 上 TCC 授权、AXObserver 推送、ScreenCaptureKit 抓屏全是桩
(`mac_capabilities()` 恒 false),Tauri 走的是 WebKitGTK 而不是 WKWebView。脚本头部逐条写明了
它证明什么、不证明什么 —— 第一次这么跑就抓到一条 Playwright 桩测不出来的裸术语泄漏。

## 它做不到什么(如实)

- **拦不住不经过它的东西。** 桌面确认层覆盖的是引擎看得见的动作;直接调系统 API、或在观察间隙里
  完成的动作,它拦不住。
- **不是零间隙。** 像素捕获是采样;macOS 的树观察有推送,但兜底仍是轮询。
- **浏览器里另算。** 页面内的付款/表单拦截由 Chromium 扩展在页面上同步完成(装了扩展才有);
  原生消息路径是**异步**的,只能事后通知,不能撤销已经发生的操作。
- **Android 是事后通知。** 伴生应用不能阻止第三方应用已经执行的动作。
- **真机验收尚未走完。** 签名、公证、以及各平台逐条验收清单的状态见
  [release-evidence.md](release-evidence.md) 与 `docs/acceptance-*.md`;当前发布判断是 **No-Go**。
