# iOS：移除一次放行与重放，修正伪造提示绕过

日期：2026-09-17。源码基线 `99dc358490ca4f978eaaadb14c96c309bec8ab3a` 加本批修改。App 和 Safari Extension 保持原名称、Bundle ID，构建号一起从 1 递增为 2。**本轮修正发布前的代码差距，不代表 I1–I6 或 TestFlight 已通过。**

## 对照原要求发现的差距

[iOS 验收 I3](acceptance-ios.md) 明确要求风险动作在执行前被阻断，页面没有“允许一次”或自动重放。原内容脚本却仍创建“仅允许一次”按钮，在用户选择后放入 `bypassOnce`，再调用原控件的 `click()` 或表单的 `requestSubmit()`。当前产品说明也仍描述旧门控，和正式验收要求不一致。

同时，脚本仅凭页面元素的 `data-agentguard-webshield-overlay` 属性跳过检查。网页可以给自己的付款控件加上相同属性，导致点击不被检查。原测试只检查危险事件最初是否被取消，没有继续点击提示或验证伪造属性的后果；其中一项源码断言甚至要求存在 `requestSubmit()`。

新增四个行为回归在原代码上全部失败，旧 18 项仍通过。真实 Chromium DOM 夹具另实际点击“允许一次”并观察到付款处理器及模拟请求执行；带伪造属性的另一付款按钮也执行。旧日志与旧内容脚本保留。

## 修改后的行为

- 风险点击／提交仍在同步监听器里被取消。已启用状态下立即发送最小化 `blocked` 事件，提示只提供关闭；关闭、Escape、状态后续改变都不会重放原操作。
- 用脚本实际创建的宿主对象识别自己的提示，网页属性不再构成跳过检查的依据。没有扩大域名白名单或关闭检测。
- 普通动作保持可执行；只有原生端明确回报 `disabled` 时，之后新发起的动作按原约定放行。`unknown`／`unavailable` 继续阻断已识别的风险候选。
- Swift 合同新增 `blocked`，原 `allowed`／`cancelled` 保留原含义，历史数据不改写。新版内容脚本不再生成放行事件；三语提示和新阻断记录文案同步。同步三语产品说明与生成能力矩阵。
