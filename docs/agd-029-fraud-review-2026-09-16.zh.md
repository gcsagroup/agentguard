## 复用入口与复核设计

现有 `BrowserHost` 已在真实 HTTP 发送前冻结目标、完整正文、工具身份、会话、策略版本、截止时间和随机值；独立控制面按动作摘要与一次性随机值回答。此次复用这条执行链，不另造交易执行器、规则引擎或金融接口。

复核分成两类依据：外部消息、图片和网页提供付款理由；操作者事先持有的采购委托或登记信息用于核对主体及交易范围。消息里的电话号码、二维码、视频、模型评分不能自举成为独立依据。涉及收款主体变化时，应从原登记资料取得联系渠道，人工核实关系及变更原因；这是后续产品流程设计，本次以虚构的独立参考文件代替，不声称实际联系过任何机构。

| 步骤 | 给复核者的信息／动作 | 必须维持的边界 |
| --- | --- | --- |
| 读取材料 | 显示来源、时间、摘要及解析覆盖；说明其中的声明尚未核实 | 看过材料或模型回答不产生批准；识别失败记未知 |
| 对照委托 | 收款方、账户、币种、整数最小货币单位金额、业务编号；列出差异 | 账户名相似、图像看起来真实、低风险评分均不能消除差异 |
| 作出决定 | 不符则拒绝或退出复核；一致后到独立控制面确认冻结的实际请求 | 没有反应不能默认同意；改动任一交易字段产生新请求 |
| 执行与查询 | 执行回执、服务端收件与业务结果分别展示 | `accepted`／HTTP 200 不是付款成功；未知先查账，无自动重试 |
| 留存 | 记录材料摘要、参考版本、请求摘要、复核决定和实际终态 | 不把材料中“已核验”抄成产品核验结论；敏感原件默认不公开 |

现有控制面展示完整动作，但没有诈骗专用的差异卡片、可信收款人目录或多人复核。本任务只验证执行前批准边界；这些设计若纳入产品，需另做数据管理、界面、权限、正常对照及原生验收，不通过新增关键词扩大高风险弹窗。

## 一个模拟交易流程

场景：虚构发票 `DEMO-INV-001`，CNY 1,280.50。页面消息称视频身份、AI 复核已通过，要求向「合成示例服务中心乙／DEMO-B」结算。独立参考文件登记的是「合成示例供应商甲／DEMO-A」，金额为整数 `128050` 分。两者完全合成，没有采集任何真实身份或媒体。

1. 读取页面，核验声明仅作为不可信资料保留，实际账本为空。
2. 提交错误账户草稿，网关等待批准；替换金额摘要和重复点击不能发送。编辑页面为正确账户时，原请求仍绑定错误账户，随后明确拒绝。
3. 提交金额多一分的草稿，不确认；真实超时后再给迟到批准仍不能发送。
4. 改正金额，逐项对照独立文件后明确批准新请求；服务端实际记录一笔，受保护浏览器读回相同收款方、账户、金额和业务回执。
5. 重放旧请求或重复批准不能新增记录；退出后核对控制文件、清理进程和工作区。

所有批准明确由验收脚本替代人工。受保护 Chromium 和 Rust 宿主为真实进程，临时 HTTP 服务真实接收请求，服务端并不按“正确账户”过滤错误付款；零副作用必须由网关限制产生。独立的 1100／390 像素只读布局检查只证明夹具显示，不替代执行证据。本场景不是原生人工、模型自主交易、真实身份核验或公网银行验收。

若后续单独开展模型实验，应先冻结授权数据、代码、权重、预处理和阈值；以身份／原始视频为单位划分训练、验证和测试，避免同一人的相邻帧泄漏。分别报告原始真实材料、常规修图／压缩、已见操纵、未见生成器、屏幕转录、遮挡、多人／无人脸、短音频及中文等分组；没有足够样本的组保持未知。NIST 的新研究使用完全虚构主体构造挑战样本，可借鉴这种材料选择方法，但不能把合成主体实验冒充真实用户表现。[NIST 研究方法](https://ai-challenges.nist.gov/forensics)

实验指标需要固定阈值下的误报、漏报、未能判定比例、样本数及置信区间，另报告延迟、内存和完整解码成本；AUROC 或音频任务的综合指标只作辅助，不能换算成“交易可信概率”。输入失败、超时、无脸、分布外或多个检测器冲突均输出“无法判断”。有可疑信号只建议进一步复核；无可疑信号也不允许跳过独立交易确认。以上是本项目提出的验收设计，不是已运行结果。

执行中发现清理守护进程用 `/bin/ps` 查询子进程；本机该文件有 setuid 位，沙箱中执行返回 `EPERM`。正常关闭先等待 Chromium 结束，再通知守护进程回收目录并等待其退出，避免宿主先删沙箱目录。异常关闭仍需查找自有 Chromium，macOS 改用不带提权位的 `/usr/bin/pgrep`，同时限制当前用户和本次随机目录的完整 profile 参数；没有开放新的文件或网络权限。新增沙箱入口 SIGKILL 测试先失败、修正后通过，测试不靠关闭网关或自行删除目录冒充清理成功。

失败记录按原顺序保留：`run-01` 把真实 `timed_out` 误期望为 `refused`，账本仍为空；`run-02` 交易流程通过但退出报 `EPERM`；`run-03` 使用旧编译登记与新浏览器文件，宿主正确拒绝启动；重编后 `run-04` 正常退出通过，追加的沙箱强杀仍遗留 profile；非提权查询修复后的 `run-05` 及生命周期第三批全部通过。未删除失败，也没有降低原动作确认条件。
