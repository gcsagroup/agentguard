# AGD-027：连续容器事件与读取分段

日期：2026-09-16。基线 `b1b9928`，使用同一冻结开发 CLI `9af1137e…`。本批为诊断，不替代原 30 次性能验收；未修改产品同步或隔离方式，固定 App 022 未构建。

## 方法与结果

前批事后读取 Docker 事件缓存缺失第一轮，故本次在每轮读取之前开启事件流，结束后才终止采集器。预声明固定两轮，每路 5 次预热和 100 次计时读取；开始前校验总轮次等于执行顺序长度，并核对脚本、镜像和候选摘要。计时期间不运行本任务的构建或测试。

三路共 600 次计时读取和 30 次预热，内容均正确。两轮分别取得 107 个完整容器生命周期：1 个 VM 预检、1 个网关启动探针及 105 次独立读取。210 个读取容器按创建顺序与请求一一对应，生命周期均完整且退出为零；再按预声明的 20 ms 宿主／daemon 时钟容差核对包含关系，不能只凭容器总数宣称请求已对齐。

| --- | ---: | ---: |
| 原生读取 p95 | 10.01 ms | 11.30 ms |
| 隔离读取 p95 | 309.23 ms | 306.76 ms |

容器内进程 start → die 的 p95 为 46.67／44.44 ms，create → start 为 86.60／89.27 ms，die → destroy 为 25.08／21.01 ms。各列分位数不是同一个请求，不能相加重建整体 p95。

这次没有复现前批 895.55 ms 的隔离 p95，不能据此宣称那个长尾已修复。正常请求约一半时间在 create → destroy 之外；它仍包含 Docker CLI、主机处理、持久审计和协议往返，尚未细分到系统调用，不能全部归因于 Python 启动或磁盘。原生 p95 仍在原 10 ms 预算附近或以上，AGD-027 保持未通过。

## CI 的 EOF 夹具修正

提交 `442f401` 的 [macOS workspace 作业](https://github.com/gcsagroup/agentguard/actions/runs/35070437352/job/104710448863)中，`派发后故障保留未知边界并禁止再次调用` 的 EOF 模式得到 Timeout，而期望 Disconnected。此前超时、半条响应均正确，EOF 服务已就绪；不能把它归为解释器尚未启动，也不与 `dbb9401` 的桌面 `starting` 超时混为同一已解决原因。

原夹具只调用 `sys.exit(0)`，协议输出仍可能在解释器清理期间保持打开。先为 EOF 模式加入一秒可控的退出清理延迟，保留原调用期限，实测稳定得到同样的 Timeout／Disconnected 断言失败；原始失败保存。随后让 EOF 模式先显式关闭 stdout，再开始延迟退出；现在验证的确实是管道 EOF，同时仍要求宿主回收尚未退出的服务、保留已派发未知边界并禁止第二次调用。

此变更只在 Python 合成夹具中；没有扩大 300 ms 调用期限、2 秒回收断言或接受 Timeout 作为 EOF 通过，也没有修改产品传输逻辑。stdio 专项 11 项通过、1 项显式忽略。可控复现证明了夹具存在这种歧义，不证明托管机那次实际花了一秒做相同的退出清理；最终 CI 结果仍需独立观察。冻结性能候选的源码清单包含该测试文件，因此本批 241 输入一致性结论止于 `b1b9928`，后续测试夹具修正不能冒称仍与旧清单逐字相同；原 CLI 与 App 字节未改。

修正后网关库默认并发完整运行 247 项通过、6 项显式忽略，仓库不变量 23 项通过；固定 App 的 91 个文件与原清单再次一致。忽略项不计完成，完整计划与发布状态保持。
