# AGD-027：会话缓存写入对照

日期：2026-09-16。基线 `71f700b`。结论：暂停会话计数缓存更新能够减少 WAL 写入页数，本批延迟也有改善信号，但基线本身波动明显，尚未证明稳定收益；**不将这个实验用于产品，不改变兼容行为或原性能门槛。**

## 实验范围

执行前冻结四轮顺序：原方案 → 暂停缓存更新 → 暂停缓存更新 → 原方案。每轮新建独立合成数据库，以同一冻结诊断 CLI `75163aa9…` 完成 5 次预热、100 次计时读取。两轮实验库只增加一个 `BEFORE UPDATE` 触发器，跳过 `agent_sessions` 的可变计数更新；执行事件、来源事件、哈希链和执行前后两次持久提交均仍由原 CLI 产生。计时期间没有运行本任务的构建或测试。

暂停缓存更新不是兼容的产品改动：当前会话摘要从事件行重新计算，但历史字段仍有兼容用途。实验库中的缓存计数停留为零，不能交给旧版使用，也不能覆盖用户的工作区。全部操作只发生在本批新建的合成目录。

## 结果与判断

420 次读取正文完全一致，四个数据库共 1,684 条审计的事件顺序、哈希链、结果摘要及提交计数核对通过。

该诊断 CLI 没有配置签名者，实际签名字段为空，本批不提供签名真实性证明。冻结运行器的一处注释误称“签名事件”，以实际字段及本说明为准；保留原计划与运行器摘要，不改写采样来源。

| 轮次 | 方式 | 计时读取 p95 | 普通请求新增 WAL 帧中位数 | 缓存计数 |
| --- | --- | ---: | ---: | ---: |
| 1 | 原方案 | 14.94 ms | 28 | 315 |
| 2 | 暂停缓存更新 | 9.26 ms | 26 | 0 |
| 3 | 暂停缓存更新 | 9.89 ms | 25 | 0 |
| 4 | 原方案 | 9.99 ms | 28 | 315 |

每帧对应 4,096 字节数据页。表中帧统计只计没有观察到检查点或 WAL 重用的请求；每轮另有 3／3／3／4 次观察到转换，全部仍保留在总体延迟分母。不能用某次请求的帧数代表整段运行，也不能把两组不同数据库的页布局差异全归因于缓存。

预声明要求两轮实验的 p95 均低于 10 ms，且比两侧基线 p95 均值降低至少 15%，才值得进一步研究兼容实现。本批满足这个探索条件，但两侧原方案从 14.94 ms 降到 9.99 ms，说明时间相关波动不小；后一个原方案与实验结果接近。因此它只能提供后续假设，不能证明稳定因果收益，更不能作为原预算验收通过。没有为取得通过而删除基线失败、调整同步或合并执行前后的提交。
