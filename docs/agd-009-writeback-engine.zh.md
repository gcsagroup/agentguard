# AGD-009：快照差异与回写引擎

日期：2026-09-09。当前结果：单个授权根内的普通文件可以生成完整差异、核对批准摘要并回写，原件保留在授权根外的私有恢复目录。**多文件不是事务；并发冲突、中途取消和无法确认的结果分别报告，不能把本引擎的通过范围扩大为完整 M1 或发布验收。**

## 接口与接入顺序

```rust
HostBaseline::capture(host_root: &Path) -> anyhow::Result<HostBaseline>
WritebackEngine::attach(baseline: HostBaseline, snapshot_root: &Path)
    -> anyhow::Result<WritebackEngine>
WritebackEngine::preview(&mut self) -> anyhow::Result<Preview>
WritebackEngine::apply(&mut self, approved_digest: &str) -> ApplyReport
WritebackEngine::apply_with_cancel(
    &mut self,
    approved_digest: &str,
    cancelled: &dyn Fn() -> bool,
) -> ApplyReport
```

`capture` 必须在创建副本之前，`attach` 必须在复制完成后、首个工具执行之前。引擎检查宿主没有在复制期间改变，并核对起始副本的文件正文、目录拓扑和链接目标。每个可写授权根使用一个引擎；工作区编号、会话状态、操作者凭据、单次批准与取消代次由网关控制层维护。

预览在引擎内保存完整字节和元数据；调用者只能提供此前预览的摘要，不能提交一份自行构造的清单替换宿主基线。`Preview` 与 `ApplyReport` 支持 JSON 序列化，预览包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `digest` | 绑定预览、宿主基线和当前快照清单的 SHA256 |
| `workspace_root` | 此引擎绑定的宿主物理目录 |
| `recovery_directory` | 预览时确定、纳入摘要的同级恢复目录 |
| `changes` | 相对路径、`create / modify / delete`、修改前后版本 |
| `before / after` | 完整 UTF-8 正文或二进制 SHA256、字节数、Unix mode；不存在的一侧为 null |
| `total_body_bytes` | 所有修改前后正文的实际字节总量，二进制也计入 |
| `atomic` | 固定 false，不能把批量提交显示为原子事务 |
| `limitations` | 必须向操作者保留的能力限制 |

UTF-8 文本不截断；包含空字节或无效 UTF-8 的文件显示二进制摘要，引擎内部仍保留完整字节。上限为单文件 256 KiB、每次预览修改前后正文合计 1 MiB、100 项变更；任一超限直接失败。起始扫描另限制 20,000 个对象和 16 MiB 正文。它们是首版小工作区的明确边界，不是静默筛选规则。

当前快照实现会把文件权限收缩到 0600 或 0700。引擎同时保留宿主模式和副本初始模式：副本模式未被任务修改时，回写保留原宿主模式；任务确实修改模式时，预览显示完整目标模式。特殊权限位拒绝。当前仅接受宿主用户拥有的普通文件，修改时保留原组号。

## 路径与输入边界

授权根按物理路径逐级打开并持有目录描述符；macOS 的既有系统别名可以归一化，用户创建的根／祖先符号链接不接受。扫描和文件操作均使用相对目录描述符的 `openat`、`fstatat`，父目录与最终文件均不跟随链接。根、祖先和内部父目录 inode 在操作前重新核对。

已有符号链接作为不透明对象记录链接目标与身份，不读取目标正文。只要宿主和副本里的原有链接保持不变，它们不会妨碍其它普通文件的差异预览；链接创建、删除、置换和内容变化均拒绝。Socket、FIFO、设备和其它特殊对象拒绝。

首版只支持**既有目录内新增文件、修改普通文件和删除普通文件**，不创建、删除或替换目录，也不应用目录模式变化。目录新增需求应在后续独立设计和验收后开放。

原子替换会产生新 inode，因此引擎拒绝携带未支持扩展属性、ACL 或文件系统特殊标志的对象，避免丢失安全元数据。macOS 自动附加的 `com.apple.provenance` 来源属性单独允许，替换后由系统标记新的写入来源；不把它说成已原样复制全部元数据。

## 回写、取消与恢复

开始回写前核对全批宿主清单和批准时的完整快照清单，包括正文、模式、inode 和修改时间。宿主被编辑、同内容文件被另一 inode 替换、根或父目录改变、批准后快照改变，都会使本次预检失败。正文发布使用预览时保存的字节，不重新从可能已经变化的快照路径取得替代内容。

恢复目录位于授权根的父目录下，随机名称、0700，必须与授权根在同一文件系统；跨设备时拒绝。**网关还必须核对该恢复目录不在任何其它只读或可写授权范围内**，否则禁止回写。引擎只知道自己的单个根，不能代替多根授权层作此检查。

每个修改或删除先把当前目录项排他移入恢复目录，随后核对被取出的真实 inode、正文和 mode。创建／修改的发布使用 macOS `RENAME_EXCL` 或 Linux `RENAME_NOREPLACE`；不支持时失败，不回退到能覆盖目标的普通 rename。原始 inode 不被原地写入；已有硬链接保留原内容，任务修改获得新的 inode。

如果取出的实际原件不符合基线，或发布前发生取消，引擎尝试把原件排他移回原名；原名被并发创建的文件占用时绝不覆盖，保留恢复原件并报告未知。恢复成功后同步原父目录和恢复目录，再记录恢复完成。

取消回调在开始前、每项准备正文前、每项备份前及发布前检查。开始前取消没有原文件副作用；已有文件完成后取消报告部分完成，不自动撤销先前操作。应用成功后重新核对宿主与本批结果一致，再更新两份基线，支持下一轮预览和回写。

恢复目录内的 `manifest.json` 记录预览摘要、原相对路径、`old-N` 原件、`new-N` 待发布正文和每项阶段。清单先写新文件、同步，再替换清单并同步目录；移动或发布前后均保存阶段。清单不保存批准 nonce 或令牌。崩溃后应先停止该工作区动作，根据清单同时核对宿主原路径、恢复原件和待发布文件；禁止无条件覆盖式恢复。

| `ApplyReport.outcome` | 含义 |
| --- | --- |
| `applied` | 全批已完成，并通过最终核对；仍不是多文件事务 |
| `conflict` | 本批没有已确认完成的文件，预检或当前操作未能满足条件；恢复记录说明是否取出并恢复过原件 |
| `partial` | 部分文件已完成，后续项冲突或取消；已完成项不自动回滚 |
| `unknown` | 文件操作可能已发生，恢复位置、持久化或最终身份核对无法确认；必须停止后续动作并核实 |

逐文件结果包含 `applied / conflict / not_applied / unknown`、说明和恢复原件路径。原件移动后发生的错误不会转成不带副作用信息的普通异常。是否将工作区锁定，由网关根据部分或未知状态执行。

## 无法提供的并发保证

macOS 与 Linux 的 rename 接口都没有“仅当目标 inode 与正文摘要仍等于指定值时替换”的比较交换操作。排他发布保证不会覆盖已占用的新目标名，取出后核对可以发现检查与取出之间的对象置换；它们不能把多步修改变成单个原子条件替换。

其它进程已经持有的旧文件描述符、同 inode 硬链接写入，以及对父目录的并发主动改名，仍可能与回写重叠。引擎不改写旧 inode、保留恢复原件并反复核对路径身份，检测到不一致则报告冲突或未知；**不能据此承诺对所有同用户并发写入者实现完全隔离**。需要这种保证的工作区，必须先停止其它写入者，或采用能提供更强事务／版本语义的文件系统服务。
