# 上线评估

写给决定"这东西能不能放出去"的人。**结论在最前面,理由在后面。**

判断的标准不是"功能够不够多",而是三件事:

1. 我们对外说的话,有没有一句是代码做不到的。
2. 它拦不住的东西,使用者会不会以为它拦得住。
3. 给错了人用,后果有多严重。

---

## 结论

**可以作为 `1.0.0-rc` 发布,面向明确的三类使用者;不可以作为"安全产品"卖。**

差别不在功能强弱,在**承诺的性质**:

- 它现在能诚实地承诺的是**可观测性与可追责性** —— 看见了什么、判成了什么、写进了
  一条防篡改并可归属的审计链。
- 它**不能**承诺的是**不可绕过的强制力** —— 除了一个很窄的例外(Linux 上由它自己
  启动的进程的文件系统边界)。

一个买"防护"的人,拿到的是一个"记录 + 劝阻"的东西。这个差距不是靠更多规则能补上的,
它是架构层面的:**大部分层是合作式的 —— 智能体不经过它就绕过了。**

所以能不能上线这个问题,取决于对谁说话。

意图)、`DELETE_TOKENS` 里曾有 `ri` 和裸 `format`、默认策略曾让网关每一次写都挂起等确认。
三个都是"更严"变成"更不安全"的实例。

## 不可以说什么

这一栏比上一栏重要。

**不能说"拦截危险操作"。** 只能说"在它经过的路径上拦截"。工具网关(`guard-gateway`)
是 MCP 服务器,智能体**自愿**把工具调用路由给它;直接 `exec` 就绕过了。这是设计,不是
缺陷 —— 但它不能被说成"拦截"。

**不能说"沙箱"。** 除了 Linux 上、由 `agentguard-jail` 自己启动的进程。macOS 的
`sandbox-exec`、Windows 的受限令牌 + Job Object 都还是设计文档(B3),没写。Android 在
没有 root 的情况下做不到,永远。

**不能说"防止数据泄露"。** 出口代理(C1)是设计,没写。它看得见网络元数据,拦不住连接。

**不能说"零信任"或"不可绕过"。** 适配器的断言仍然可以被本机任何拿到 API 令牌的
调用方**伪造出来**;变了的是伪造的**方向**:伪造"有风险"只能制造误报,而伪造
"干净"去清掉一个已锁存的 Critical 风险 —— 那个方向关上了(见
[适配器断言签名.md](./适配器断言签名.md))。

Android 伴生应用 —— 唯一在产出环境调查、也就是这个机制唯一真正要保护的那条路 ——
现在**会签**了:ECDSA P-256,私钥留在 Android Keystore 的 TEE / StrongBox 里不出硬件。
代价照说:公钥是**每设备一把**,不填进注册表的话它的调查仍然算未签名(可加风险、
不可清风险);两个桌面外壳还没接;FFI 依然完全无认证 —— 它伪造不出"干净",
但可以随意增加风险,也就是可以制造误报。

**不能说"实时"。** macOS 是 1.5 秒帧 / 2.5 秒树的轮询,Windows 是 2.5 秒。两次轮询之间
发生的事看不见。

**不能说漏检率等于论文里的 ASR。** 语料是确定性的,回路里没有真实智能体。
`docs/eval-methodology.md` 里写了这条,不能在对外材料里丢掉。

**不能说 Android 能阻断。** 它是**事后通知**,不是阻塞确认框。事件已经发生了。

**不能说身份已经在用。** `require_attestation` 默认关闭,而且没有任何已发布的适配器
会签会话。身份机制是完整且被测过的,但**目前没有一个真实部署在用它**。

## 给谁用是负责的

### 1. 研究者与评测方

**负责。** 这是它最强的形态。语料、覆盖矩阵、四篇论文的映射、可复现的门禁,
外加一个会自己报出自身缺口的自检命令。

### 2. 开发与预发环境里的智能体

**负责。** 观测 + 审计 + 合作式确认,在这个场景里价值是真实的:开发者想知道自己的
智能体在干什么,而不是想把它关起来。Linux 上还能顺手拿到一个真的文件系统边界。

### 3. 内部试点(受控设备、知情的运维)

**有条件负责。** 条件是三条,缺一条就不负责:

- 跑过 `agentguard preflight` 并处理掉 FAIL(至少要换掉夹具密钥)。
- 运维读过"不可以说什么"那一栏,并且明白**合作式**是什么意思。
- 事故预案里不包含"AgentGuard 会拦住它"。

---

## 给谁用是不负责的

**面向消费者的安全产品。** 消费者读不到也不该读这份文档;他们会以为装了就受保护。
合作式的层在这个场景里等于零 —— 恶意智能体不会自愿路由。

**受监管环境的合规控制项。** 拿它当"防数据外泄"或"访问控制"的证据是错的:
出口代理不存在,而文件系统边界只在 Linux 上、只对它自己启动的进程有效。

**对抗性场景 —— 假定攻击者知道守卫在场。** 一个知道 AgentGuard 在的攻击者会:
不经过网关(合作式)、伪造适配器事件(未签名)、在轮询间隙动作(1.5–2.5 秒),
或者干脆不用被约束的那个进程。这些都不是零日,是**已记录的架构边界**。

**替代人的判断。** 关键节点的确认框是给人看的。人如果一路点"同意",它什么也没做。

## 一次外部评审(codex)之后:哪些是真的,改了什么

评审结论是 **No-Go**,这个结论**成立**。下面按"评审说了什么 / 核实结果 / 做了什么"排,
包括评审说错的地方和评审没看到的地方。

### 已核实为真,已修

| 评审提的 | 核实 | 修法 |
|---|---|---|
| 没有任何 git 历史,结论无法追溯 | 真。`git status` 报 not a repository | git init + 基线提交;逐个核对过 `intel/keys/secret.hex` 等未进索引 |
| `cargo fmt --check` 68 个文件不合规 | 真,而且它**完全不在** `make check` 里 | 接进门禁。接进去那一次立刻暴露一条被旧折行藏住的 clippy 错误 |
| preflight 的退出码被 Makefile 忽略 | 真(`-cargo run ...`) | 改成期望结论基线:多一条或**少一条**都拦。少一条尤其要拦 —— 删掉一项检查会让它的结论消失,而"少了一条 WARN"看起来像修好了什么 |

| macOS 路径判决 8 个失败 | 真。已在 Linux 上用写死的 macOS 形状输入复现 | 见下 |
| README 称"实时拦截",和本文件矛盾 | 真 | 已改,并加测试盯住那几个词 |

### 评审说得不够准的地方

- **"1 FAIL、5 WARN"** vs 本机的 4 WARN:同一份配置,差的那条是 `jail.*` ——
  Linux 上有 mount namespace 报 `jail.backend`(PASS),macOS 上报 `jail.unavailable`
  (WARN),**id 本身**就不一样。两次评审看的是同一套配置。preflight 基线因此把
  这类"随机器而变"的检查记成族名,换平台不假警,但删掉整族照样拦。
- **`_to_delete/agentguard-iter27.tar.gz`**:本机快照里没有这个目录,也没有任何
  tar.gz。评审自己也提到仓库被外部刷新过。已在 `.gitignore` 里防上。
- **macOS 路径 bug 被描述成"错误命中敏感目录"**,那只是两个方向里安全的那一半。
  危险的是另一半:一条写成 `/etc/**` 的策略拿到 `/private/etc/passwd` 时前缀匹配
  **不成立**,规则静默地不生效。所以修法不是往敏感目录表里继续加别名(那是打地鼠,
  而且只修得了误报那一半),而是把两边归一到同一个空间。

### 评审没看到的

- **第三处 `innerHTML`**:Chromium 扩展的 popup.js。评审只报了 macOS,
  Windows 外壳和这个扩展是同一个洞。是那条**类级别**的测试抓出来的,不是逐个找的。
- **`csp: null` 在 Windows 外壳上也有。**
- **情报信任根的私钥有没有被 .gitignore 排除,以前没有任何检查。** 注册表那边
  早就有 `agent.keys.publicly_known` / `adapter.keys.publicly_known` 在盯夹具密钥,
  情报这边一直没有对应的。文件权限防的是本机其他用户,防不了"私钥跟着发布物发出去"
  —— 后者更严重,而且从 git 历史里去掉一个文件很难。新增 `intel.secret.unignored`(FAIL)。
- **`check-macos-paths` 这个 target 只查编译,不查路径语义。** 一个叫这个名字的
  target 打印 PASS,读的人会合理地以为 macOS 路径处理验过了 —— 而那 8 个失败全是语义。
  已拆成 `check-macos-cfg` 和 `check-macos-path-semantics`,后者是纯函数 + 写死的
  macOS 形状输入,**在 Linux 上也跑**。
- **适配器签名机制在评测集里一条覆盖都没有。** 场景格式压根表达不了"这个事件的
  签名验过了"。已加 `via_verified_adapter`。

### 应用身份那条改了什么

以前:`resolve_app_identity` 直接信事件里的 `signer_sha256`。而应用签名证书摘要是
**公开**的 —— `apksigner verify --print-certs`、`codesign -dv` 就能打出来。它是标识符,
不是秘密。于是包名伪造只是换了一层:从"随便填一个包名"变成"填一个查得到的摘要"。
持本机 API 令牌的调用方能伪造成已注册应用,拿到 `Verified` 身份和 HIGH 数据放行。

讽刺的是,这个洞在**项目自己的覆盖矩阵**里写着:那条 note 的第 (1) 条原文是
"引擎从事件上读 `signer_sha256`,所以保证住在适配器那边,不在这里" —— 描述了一个洞,
然后把它留在那里。

现在:摘要的证明力**不超过**携带它的适配器(`AdapterIdentity::may_grant_trust`)。
这和环境调查那条是**同一条**规则,只有一处定义。降级只砍 `Verified`,不动
`SignerMismatch` —— 证据**反对**一个声明的时候,谁送来的都算。

代价照说:已发布的部署里没有一个适配器会签,所以**现在没有任何应用能达到
`Verified`** —— 一次真实的已验证身份也报不进来。那是功能代价,不是安全洞,
preflight 用 `adapter.keys.absent` 报着。

**这一改我自己引进了一个回归,是项目自己的评测集抓到的**:中途换签名者的检测
读的是 `prev.is_verified()`,降级之后它变成 false,于是**换人不再被发现**。
一个修复换来了另一个洞 —— 正是上面那条不对称在提醒的形状。改成
`had_matching_digest()`,并且没有去动那个场景的断言。

### 还没做的(评审的第 5 步)

macOS / Windows / Android 的签名安装包、公证、真机端到端验收 —— 一个都没做。
这些在这个环境里做不了(没有 Apple / Microsoft 签名证书,没有真机)。
**上线判断仍然是 No-Go**,阻塞项换成了这一条。

## 第二轮独立对抗复核:我自己引入了一个越界

方法和第一轮一样,但换了目标:审 macOS 路径折叠、WebView 修复、私钥权限这三处。
**关键是它读的是消费者,不是我改的那一行** —— 第一轮就是这么找到洞的。

### 最严重的一条是我上一轮制造的

macOS 卷别名折叠我做成了**无条件**生效,理由写着"Linux 上没有
`/System/Volumes/Data` 这种路径"。那是**对文件系统的假设,不是函数的性质**,
而且没有任何东西在保证它。后果已经跑出来了:

```text
天花板        /tmp/ws
操作数        /System/Volumes/Data/tmp/ws/pwned.txt
守卫判决用的  /tmp/ws/pwned.txt        <- 折过的 → 判成在天花板内,还跳过了人工确认
执行方写的    /System/Volumes/Data/tmp/ws/pwned.txt   <- 原始的
```

在 macOS 上两者是同一个 inode(firmlink),不分叉。在 **Linux** 上是两个文件 ——
而 `guard-gateway` 和 `guard-jail` 恰好跑在 Linux 上,后者的执行器还自带
`create_dir_all`,能把这个目录形状**创建出来**。而且签名审计行里记的是折过的路径,
也就是一个从未被写入的路径。

折叠是一条 **macOS 的文件系统事实**,不是可移植的归一化。现在按平台开关
(`VolumeAliases`),而"在 Linux 上也测得到 macOS 语义"靠**注入**实现,
不靠让它到处生效。上一版为了后者牺牲了前者。

### 而且那个折叠原本一条测试都没盯着

复核用变异测试证明的:把折叠从 `resolve()` 里**整段删掉**,`cargo test` 和
`make check-macos-path-semantics` 全绿。原因是所有别名测试都直接调那个辅助函数,
或者调 `sensitive_target`(它自己独立折一次)。**危险的那一半 —— 工作区包含判定 ——
从来没被走过。**

我上一轮还写了一条名叫"天花板和目标经过卷别名之后仍然可比"的测试,文档注释宣称它
钉住的是"`check_filesystem_scope` 把两边都过一遍 `resolve`"。它调的是辅助函数,
既没调 `resolve` 也没调 `check_filesystem_scope`,而且不在 Makefile 那张钉住清单里。
删掉折叠它照样绿 —— 正是这个仓库反复提防的"机制存在、被直接测过、然后什么都没接上"。

|---|---|---|
| 审计库口令仍是"写完再 chmod" | `fs::write` + 事后 `set_permissions`,chmod 结果被 `let _ =` 丢掉,而且 `exists()`/`write` 都**跟随符号链接** —— 一条预种的链接能让守卫把口令写到别处,或者把别人的文件内容**当成口令读回来** | 已改成原子 0600 创建 + 拒绝符号链接 + 目录 0700 |
| macOS 上 `$TMPDIR` 被判成系统目录 | `$TMPDIR` 是 `/var/folders/<散列>/T/`,而 `/var` 在敏感表里 —— 于是**每一次**写临时文件都是 Critical + 要人确认。先前就存在 | 已放掉这一个窄例外(至少五段,只覆盖 `T/`、`C/` 那一层往下) |
| 前端不变量测试自己有它要防的毛病 | 写死四个文件(漏了两个 `i18n.js`)、`if !exists { continue }` 会静默空转、只禁 `innerHTML` 一个词 | 改成扫目录 + 数量下限 + 禁一整类 sink(11 个) |
| 写在配置里的 CSP 不是实际生效的那份 | Windows 外壳 index.html 有内联 `<style>`,靠 Tauri 注入的 nonce 才渲染得出来 —— 读配置的人会以为内联样式被挡住了 | 样式搬进 styles.css;新增不变量禁止内联 `<style>` |

六条修复每条都做了变异测试。有两次变异测试当场证明我的**测试**不合格:
一次是合并后的严重度掩盖了内层的 `[ALLOW: Allowed]`,一次是我自己的降级修复
掩盖了大小写那个洞。

### 两轮下来的规律

两轮复核找到的洞,没有一个是"改错了那一行"。全部是**改的那一行没有覆盖到所有
消费者**,或者**测试没有走真实入口**。我自己那两轮的盲点完全一致 ——
写完修复、写完测试、跑完变异测试,然后停在那里,没有回头问"还有谁在读这个值"。

## 第三轮独立复核:门禁本身大半是戏

这一轮审的是**检查检查的东西** —— preflight 基线、仓库不变量测试、release-gate 脚本、
cargo-deny。复核给出的一句话诊断比清单更值钱:

> **用子串 `contains` 顶替解析。**

`contains("script-src 'self'")` 顶替"脚本来源只有 self";`contains("make X")` 顶替
"CI 真的跑了 X";`contains("|| true")` 顶替"没有任何东西吞掉退出码";
`-e "$path"` 顶替"签名验过了"。每一个都能被"在匹配到的前缀后面加点东西"、
一个空格、一个注释符,或者把路径指向 `/tmp` 打败。

### 最严重的一条

`--strict` 发布门禁 —— 这个仓库里**唯一**有权说"可发布"的代码路径 —— 用的是
`[ -e "$path" ]`。于是:

```bash
export AGENTGUARD_EVIDENCE_MACOS_CODESIGN=/tmp ...
./scripts/release-gate.sh --strict
→ 结论:自动检查与证据检查全部通过。   exit 0
```

一个目录满足了代码签名证据。脚本自己的开头写着"一个把未验证说成通过的门禁,
比没有门禁更糟"。现在三条都要过:普通文件、非空、内容里出现该项的判据关键字
(codesign 要 `satisfies its Designated Requirement`,公证要 `Accepted`,
apksigner 要 `Signer #1 certificate`)。关键字不防伪 —— 它防的是**手滑**:
指错路径、指到空文件、指到上一条命令的输出。

### 两条**永远不可能失败**的断言

- `!csp.contains("http://") || csp.contains("http://ipc.localhost")` —— 两个配置都含
  `http://ipc.localhost`(IPC 必需),所以右边恒真。
- `api.token.weak` 是一条 **Fail**,而它的 id 落在"随机器而变"的族里。于是
  `AGENTGUARD_API_TOKEN=dev-secret make preflight` 会同时打印
  `[FAIL] …是公开的示例值` 和 `preflight 基线一致`,退出 0 ——
  在一个 `/v1/pause` 能停掉守卫的 API 上用示例令牌,门禁判绿。
  而且 `--write-baseline` 之后基线文件**逐字节不变**,连"评审时问一句"的机会都没有。

  修法:`Fail` 永远不进族折叠。族折叠的正当理由只有"同一份配置在不同机器上结论不同",
  而一条 Fail 是配置本身坏了,和跑在哪台机器上无关。

### `.PHONY` 让每个被改名的门禁变成一句 PASS

`Makefile` 第一行把 36 个目标声明成 `.PHONY`,而 GNU make 认为**没有规则的 phony
目标已经是最新的** —— 直接退出 0。把 `coverage:` 改个名,`make coverage` 打印
"Nothing to be done" 并成功,release-gate 照样打 PASS。十一道门禁全压在这个行为上。
现在 `gate()` 先问一句 `make -n <目标>` 有没有输出 "Nothing to be done"。

(这个修复的第一版也不合格:我原本检查"输出是否非空",而那句话本身就是输出。
变异测试当场发现。)

### 其余

| 条目 | 修法 |
|---|---|
| 注释掉的 `# run: make check-shells` 满足了"CI 覆盖了它" | 解析 YAML,只在真正的 `run:`/`uses:` 值里找 |
| `continue-on-error:  true`(两个空格)躲过检查;13 种吞法只抓到 3 种 | 读解析出来的 YAML **值**:只有字面 `false` 才算不吞;`\|\| :`、`\|\| exit 0`、`set +e` 等一并覆盖 |
| 等效物白名单接受 `""`(`contains("")` 恒真)和 `"run"` | 要求 ≥12 字符且含空格 |
| `check:` 用续行时解析出一个反斜杠当 target 名 | 先拼续行,并要求 target 名长得像 target 名 |
| 只验 "CI ⊇ make check",于是 `make check` 可以被掏空 | 加一条:`make check` 必须仍然包含那九道门禁 |
| Makefile 前缀 `-`(原始罪发生的地方)没人看着 | 新增一条测试扫 Makefile 的门禁配方 |
| 前端 sink 扫描 12 种绕法漏 11 种(行内任意 `//` 截断整行、`read_dir` 不递归而 `frontendDist` 是整个 `src/`、`setAttribute('onclick',…)` 被自己的注释宣称"已修好"而实际没有) | 字符串感知的注释剥离、递归扫描、扩到 `.ts/.cjs/.jsx/.tsx`、精确文件数、禁 `setAttribute` |
| release-gate 的计数用 `-lt` 下限 → 加一道门禁就买到删一道的额度 | 改成精确相等 |
| `--stict` 打错一个字母就静默退回软模式 | 未知参数直接退出 2 |

`deny.toml` 和 CI 的 lint job 是这一轮**唯一**没被打穿的:git 源、非许可、banned crate
三种都真的会让构建红,`all-features` 这个键 cargo-deny 会严格校验(不认识的键直接报错,
不是静默忽略),cargo-deny-action 的退出码就是 cargo-deny 的退出码。

### 顺带修掉的一个真 bug

把扩展 popup 的内联 `<style>` 搬成 `popup.css` 之后,商店打包脚本用的是**显式文件清单**
—— 少了一个 `cp`,装出来的扩展没有样式,而所有测试都是绿的。已加进清单,并新增一条
不变量:popup.html 引用的每个本地文件都必须在打包清单里。

### 一个说清楚的边界

前端 sink 扫描是**文本 lint,不是 JS 解析器**。`el["inner"+"HTML"]` 换个拼法就绕过,
`setTimeout(某变量, 0)` 分不出字符串和函数引用。它挡手滑和顺手的写法,挡不住刻意绕 ——
这一点写进了测试的文档注释,免得有人以为有了它就不用 review 前端改动。CSP 是第二道,
正是为这类残余存在的。
