## 3. 候选冻结与正式执行规则

1. AGD-006/008/012 合入且相关测试通过后，root 生成新的源码／产物清单。冻结时间必须早于正式 50 任务、100 循环和 30 分钟；仅冻结 `--binary` 路径不足。
2. `agd-workspace-session.mjs` 从源码根读取规则、策略和矩阵，并导入 `apps/protected-browser/execution-contract.mjs`。正式执行应在完整冻结源码副本中进行，同时绑定这些依赖及锁文件；不得一边修改其依赖一边沿用同一候选名。
3. 清单包括：完整 Git HEAD及脏改动归属、源码文件摘要、执行器二进制 SHA-256、App 整包清单及签名身份、浏览器运行时与 ZIP／扩展身份、固定镜像、规则／策略、模型 ID／版本／加载参数、验收器源码及矩阵、已声明任务／数据出口范围、性能预算。
4. 每套正式验收使用新的输出目录，保存开始／结束时身份和实际脚本副本。旧结果只读保留。候选或规则变化后，新开结果批次；不能把不同候选的成功项拼成一个分母。
5. 普通测试失败允许修复后新候选复验；首次失败仍保留。出现未授权宿主修改、未批准网络提交或凭据泄露时停止后续同类动作、保全精确现场，不能继续累计“通过率”。
6. 本地合成控制面可批准预声明合成任务，其凭据只能由宿主验收器持有；不能把这种批准写成人工原生验收。真实 App／浏览器控制页批准另外保存操作证据。本独立核对不读取原生控制凭据。
7. 核对清理必须以本次 PID、端口、控制文件、浏览器私有资料目录与快照挂载关系判断；全机 `killall`、关闭 Docker 或删除所有临时目录均不属于测试清理。

| T45 | Node／超时恢复：缩小任务 | 故意超时脚本与可完成的小输入 | 运行触发实际期限 → 核对停止 → 显式改成有界处理 → 交付 | 超时任务不再运行；最终结果完整，无迟到文件 |
| T46 | 文件／断连恢复：重新完成 | 转换输入与未提交草稿 | 中途断开stdio → 核对旧会话不能恢复 → 新实例读取宿主并重新处理 | 旧请求不自动重发；新批准后才有正确宿主成果 |
| T47 | 文件／暂停恢复：继续同一工作 | 原输入及已完成的快照中间稿 | 操作员暂停 → 核对待执行取消 → 同授权恢复新会话 → 完成终稿 | 授权与快照不扩张；旧批准失效，最终成果正确 |
| T48 | 文件／待批准崩溃恢复 | 需要批准的候选动作和固定目标 | 待批准时SIGKILL → 新实例重建 → 旧批准拒绝 → 显式重做交付 | 未批准动作无开始／回写；新操作员批准后成果正确 |
| T49 | Python／执行中崩溃恢复 | 已启动转换与可检查的输出标记 | SIGKILL → 等旧容器停止 → 核对未知回执与宿主状态 → 显式重做 | 原动作不自动重试、无迟到宿主写入；新成果正确 |
| T50 | 文件／新建冲突：换名交付 | 候选 result.txt；用户同名新建文件 | 预览 → 用户新建同名文件 → 冲突保留 → 候选改名再批准 | 用户文件逐字保留；仅另名成果新增，无覆盖 |

所有原始缺陷、预期失败与恢复结果均入同一任务记录，不删去难项或改题重试。原 `--tasks` 的退出条件为 50/50，这比开发计划的 ≥95% 更严；最终同时保留脚本终态、实际分母、失败原因及里程碑判断，不能把非零退出自动改成成功。

## 5. 补齐浏览器任务，避免 50 项口径遗漏

开发计划明确要求正常任务包含浏览器。当前 50 项工作区矩阵没有浏览器任务；最省改动的方案是保留原 50，再追加下面 10 项，**在正式执行前声明联合正常任务集为 60 项，最低完成数 57，目标 60/60**。任一安全负例失败或硬前置缺失均不能靠 57 项通过抵消。浏览器自动化审批、原生控制页实际操作与模型自主表现分别标明来源。

B01～B10 由 AGD-006/012 的统一会话实现提供新运行入口；当前旧浏览器脚本仍为独立会话，因此尚不能直接作为这些联合流程的正式入口。所有业务采用独立合成站点、固定正文和真实服务端账本，不向真实收件人提交。

## 6. 100 次循环、30 分钟与性能

### 6.1 当前已有真实运行入口

以下命令应在**新冻结源码副本根目录**执行，`AGD_VERIFY_BINARY` 指向 root 本轮新冻结的绝对二进制路径，`AGD_VERIFY_OUT` 指向从未存在的新证据根。这里不给旧 `8e3408…` 候选重新跑正式计数，也不预填未产生的新路径。

```bash
node scripts/acceptance/agd-workspace-session.mjs --tasks --binary "$AGD_VERIFY_BINARY" --out "$AGD_VERIFY_OUT/tasks-50"
node scripts/acceptance/agd-workspace-session.mjs --cycles --cycle-count 100 --binary "$AGD_VERIFY_BINARY" --out "$AGD_VERIFY_OUT/cycles-100"
node scripts/acceptance/agd-workspace-session.mjs --faults --binary "$AGD_VERIFY_BINARY" --out "$AGD_VERIFY_OUT/faults"
node scripts/acceptance/agd-workspace-session.mjs --soak --soak-seconds 1800 --binary "$AGD_VERIFY_BINARY" --out "$AGD_VERIFY_OUT/soak-30min"
```

首次接入发生变化时先用代表性的 T43/T48/T50、10 次循环或 60 秒运行定位兼容问题；这些短测不计正式 50、100 或 30 分钟。接口未变化且没有新疑点时，不重复做已通过的短测。

现有 `apps/protected-browser/soak-check.mjs` 将结果写到固定的 `out/soak-report.json`，并使用独立浏览器会话。不得直接覆盖旧证据并称为新统一会话验收；应从新冻结副本运行或由接入工作线提供不覆盖旧输出的统一会话入口。

### 6.2 必须分别满足的计数

| 验收 | 预声明构成 | 必须记录和核对 |
| --- | --- | --- |

30 分钟连续运行和实际系统休眠分开执行。不能把休眠时间、不同候选或中断前后两段运行拼接成连续 30 分钟。故障恢复期间记录失败、未知、人工等待、重新连接和业务核实各自耗时；不以最终一次成功覆盖故障。

### 6.3 建议在 M1 候选冻结时采用的预算

沿用 [M0 基线中已声明的草案](agd-002-performance-baseline-2026-09-09.zh.md)，本轮冻结时由 root 固定：同一 1 KiB 文件正式每路 30 次全部正文一致；原生 read_file p95 ≤10 ms，隔离 read_file p95 ≤500 ms；Docker VM 已运行时单次网关启动原生 ≤100 ms、隔离 ≤2000 ms；每路网关 RSS 采样峰值 ≤32 MiB。只报告实际测得的分位数；每路一次启动不能称启动 p95。

新增统一浏览器、代理、预览／回写、大工作区扫描另测分段，不把模型生成、人工确认或远程站点耗时混成网关开销。容器 256 MiB 配置不等于实测峰值；VM、模型及全机内存分别列出。预算失败保留实值，先修复或给出明确不兼容边界，不能测完放宽阈值后宣称原门槛通过。

| AGD-018 | 知识库与执行规则分离的签名更新、灰度、撤销和受控恢复 | 有效／无效签名、旧包降级、兼容拒绝、部分更新失败、撤销后回滚到已知良好；使用测试密钥，不读取发布私钥 |
| AGD-019 | 实际可点击的手法→案例→规则→平台→证据和记录页 | 无证据不补画攻击阶段，告警／阻断／未知分别显示；空数据、失效引用、升级失败可理解 |
| AGD-020 | M2 正常资料与攻击变体分开统计的独立报告 | 隐藏／可见注入、工具描述／返回投毒、同名工具、裁判模型操纵均有真实效果核对；M1 权限与正常工作不退化 |
| AGD-021 | 一种受控持久记忆存储，保存内容、来源、标签、期限、版本、批准引用 | 重启保留；直接修改存储被拒或识别；损坏／撤销不会变可信 |
| AGD-022 | 真实记忆读写及一个文档型 RAG 接口 | 检索带出处和版本；过期／撤销不影响新任务；不可访问第三方内部记忆标未覆盖 |
| AGD-023 | 经认证主体的父子委托及权限交集 | A→B→C 实际递权失败，跨会话／主体／旧序号重放失败；私钥不交给隔离任务；认证失败不派发 |
| AGD-024 | 深度、次数、输出规模和可测费用预算 | 并发分支原子扣减、父撤销使未开始子任务失效；不可测费用只用调用／时间限额，不能伪造金额 |

| AGD-026 | 来源查看、隔离／撤销、版本恢复与委托树停止入口 | 恢复保留旧标签；已完成外部动作标不可撤回／待补偿；正常用户能完整操作空态、失败态与恢复态 |
| AGD-027 | 支持平台／版本的 M3 内部候选报告 | 跨重启、密钥撤销、正常任务、故障、恢复和受影响 M1/M2 全部核实；内部通过不等于发布 |

测试密钥只用于明确合成服务与数据库；发布密钥、真实个人数据和生产账号不是这些本地开发验收的必要条件。协议、记忆存储和 RAG 的首个实现由 root 按原有限范围选择，普通实现选择不需要逐项重新询问用户。

### 9.2 RC 的 12 类真实材料

| 平台／材料 | 必需真实条件 | 本机目前能做／不能替代的部分 |

`scripts/release-gate.sh --strict` 要求已提交且 clean 的同一候选，并现场校验上述 12 类材料；普通开发的脏改动清单不能替代。发布材料必须满足 [release-evidence.md](release-evidence.md) 的路径、完整commit、有效期、身份和摘要闭包约束；命令输出成功不是材料可伪造的理由。

### 9.3 GA 的额外外部事实

`--ga` 在 RC 之上再要求 7 类：六端 SBOM／许可证与 NOTICE、六端隐私／商店声明、同一候选系列真实 **14×24小时** Beta、两个不同完整commit独立RC、五个不同责任人对同一产物集审批、六个真实下载／商店渠道首启 smoke、真实5%→25%→100%扩量与回滚判断。它们不能由一次本机运行、重复计数、模拟器、同一人换名字或回填时间产生。

发布、商店上传、外部账号变更、真实收件和分发应按用户已有授权处理；若没有这些授权或实际账号／设备／责任人，继续完成本地可验证的开发成果，交付具体缺项的 No-Go，不索取或记录私钥／密码。

## 10. 最少需要外部补齐的事项

目前无需用户逐项选择普通代码结构、有限MCP协议或测试算法。真正不能凭本机自主补齐的事项仅为：

1. **真实系统事件的执行条件**：承载准确App的可中断测试窗口、可靠唤醒／网络恢复路径，以及经过真实非回环路径的自有目标服务。若既有授权和环境已具备，root直接执行；缺少时只询问缺失的具体条件。
2. **最终发布事实**：六渠道SKU是否按既有范围发布、对应设备／发布身份／商店账号与五方审批、14天Beta及分阶段扩量。开发计划任务可以交付No-Go审核结果，但不能据此声称用户获得了GA上线。
3. **AGD-031的外部需求**：没有共享对象时先保留条件性；若要实际外发，需要明确接收系统及授权。本地往返设计与正常／异常样例可先完成。

原定义中的两个差异必须保留：现有50任务不含浏览器，需本文件第5节补齐；AGD-028～031原本是条件性扩展，AGD-032是独立发布判定，不可一面保留原定义一面把全部平台GA上线当成这些有限任务的默认通过条件。
