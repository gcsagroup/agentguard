# 瀏覽器執行前阻斷（首個 GA）

[简体中文](浏览器执行前阻断.md) | [繁體中文](浏览器执行前阻断.zh-TW.md) | [English](浏览器执行前阻断.en.md)

> 結論：首個 GA 在 Chrome / Edge 上採用兩條 **block-only** 控制路徑。符合條件的頁面 DOM 動作會同步阻擋；符合條件的網路請求由瀏覽器靜態 DNR 硬擋。網頁內不存在允許、繼續、重播或暫時例外入口。

## 兩條互不混用的控制路徑

| 路徑 | 目前處置 | 放行邊界 |
|---|---|---|
| 瀏覽器允許擴充功能注入的 HTTP(S) frame 內的付款／轉帳 CTA、隱私陷阱個資提交 | `document_start` 注入的 isolated content script 在 window 擷取階段同步 `preventDefault()` 並阻止傳播；可顯示資訊提示 | 網頁內**不能放行**，不重播原動作 |
| 付款形狀的非唯讀網路請求 | GA manifest 預設啟用靜態 DNR `payment_shape_block`，由瀏覽器在網路層直接 block | 無確認、頁面判決、scope 例外或一次性放行 |

兩條路徑互相獨立。DOM 偵測沒有命中不表示網路會放行；只要請求符合靜態 DNR，網路層仍會阻擋。反過來，靜態 DNR 沒有命中，也不能把已被 DOM 閘門阻擋的動作重新放行。

## 頁面內提示不是授權 UI

資訊提示位於一般頁面 DOM 可影響的環境中。敵對網頁能夠刪除、遮蔽、仿冒或改變它的可見效果，因此：

- 提示只解釋「什麼被阻擋」與能力邊界，不表達或收集授權；
- 沒有「允許一次」、繼續或重試按鈕，頁面點擊不會產生授權權杖；
- 頁面腳本合成事件、`postMessage`、舊 decision/scope 訊息或等待逾時都不能放行；
- 提示沒有顯示出來，也不改變已完成的阻斷結果。

若使用者理解風險後仍決定繼續，唯一支援的流程是進入瀏覽器擁有的受信擴充功能管理介面：Chrome 使用 `chrome://extensions`，Edge 使用 `edge://extensions`。使用者在該處停用或移除 AgentGuard 後，再自行重新發起原操作。首個 GA 不提供網站例外、動作例外或暫停按鈕。

## 頁面訊息不再是信任根

舊版 MAIN-world `guard-page.js` 與公開 `window.postMessage` request/decision/scope 通道已移除。GA 內容腳本不監聽或發布這些公開判決訊息，靜態 DNR 也沒有頁面可寫的例外。一般網頁上下文與頁面內資訊層都不是授權根。

## 靜態 DNR 的精確支援面

規則檔案：`apps/extension-chromium/rules/payment-shape-block.json`。

只有同時符合以下條件才阻擋：

1. URL scheme 是 HTTP 或 HTTPS；
2. 請求方法不是 GET 或 HEAD；
3. 以下兩種 URL 形狀至少符合一種：
   - **路徑元件**以以下 ASCII 付款標記之一開頭，並符合規則的字元邊界：`pay`、`payment`、`checkout`、`charge`、`transfer`、`remit`、`purchase`、`orderconfirm` / `order-confirm` / `order_confirm`、`confirmorder` / `confirm-order` / `confirm_order`；路徑規則亦明確接受核心標記的逐位元組百分號編碼與 `%2F` 路徑分隔符；
   - 查詢鍵為 `op`、`action` 或 `operation`，值明確等於上述付款標記之一並符合字元邊界；
4. 瀏覽器把請求分類為以下資源類型之一。

| 網路 API / 行為 | DNR 資源類型 | 目前聲明 |
|---|---|---|
| `fetch()` | `xmlhttprequest` | 支援 |
| `XMLHttpRequest` | `xmlhttprequest` | 支援 |
| `navigator.sendBeacon()` | `ping` | 支援 |
| HTML form 的頂層導覽 | `main_frame` | 支援 |
| HTML form 的 iframe 導覽 | `sub_frame` | 支援 |

標記比對不區分大小寫。標記後必須是路徑／值結尾或非 ASCII 字母、數字、底線字元；例如 `/pay-now`、`/%70ay`、`/p%61y`、`/api%2Fpay` 與 `/api?op=pay` 會符合，`/prepay`、`/payment_status` 與 `/api/search?next=/pay` 不會符合。規則隨 Chrome / Edge GA ZIP 封裝並預設啟用，不依賴頁面腳本或 Native host。

## 明確不支援或不承諾

- GET/HEAD，即使路徑名稱為 `/pay`；
- 只有請求 body 表示付款；DNR 不檢查 body；
- 網站自訂別名、未列關鍵詞、未明確列出的編碼／雙重編碼／混淆形式，以及 `op` / `action` / `operation` 之外的任意查詢鍵或未列值；
- WebSocket、WebTransport 與未列出的資源類型；
- 瀏覽器未注入內容腳本的頁面／協定、直接 `form.submit()` 或不產生被監聽事件的腳本路徑；已聲明的一般子 frame 路徑由自動化涵蓋，但不據此聲稱所有特殊 frame 都可注入；
- 頁面提示的完整性、可見性或真實性；它只是可被頁面影響的資訊層；
- 瀏覽器之外的原生 App，以及 Firefox / Safari 的首個 GA 支援。

## GA 套件與 Native Messaging 邊界

- 首個 GA 只交付 Chrome / Edge 共用的 Chromium ZIP。
- Firefox 的 manifest 與相關原始碼只作為後續原型保留；發布腳本拒絕 `--firefox`，Firefox 不封裝、不提交，也不作為首個 GA 驗收門。
- GA manifest 不包含 `nativeMessaging`。商店 ZIP 不含 Native host，也不聲明 Native 判決、動態主機阻斷或本機稽核鏈能力。

## 自動驗證

- `apps/extension-chromium/scripts/gate.test.mjs`：危險動作分類與 DNR 純邏輯邊界。
- `apps/extension-chromium/scripts/content-event.test.mjs`：真實內容腳本事件接線保持 block-only，不重播原動作。
- `apps/extension-chromium/scripts/manifests.test.mjs`：GA manifest 無 Native Messaging、靜態規則預設啟用、Firefox 不進入 GA 套件。
- `apps/extension-chromium/scripts/package-store.test.sh`：Chrome / Edge ZIP 內容與 `--firefox` 拒絕行為。
- `eval/e2e-extension/run.mjs`：Chromium 環境中的 DOM 不執行、舊訊息不放行、DNR 在請求到達伺服器前阻擋，以及負向不誤擋。

離線驗證是必要非充分證據。Chrome 與 Edge 的商店候選仍須分別保存安裝、升級、權限提示與真實瀏覽器行為證據。
