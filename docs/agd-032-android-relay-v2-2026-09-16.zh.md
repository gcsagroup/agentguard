# AGD-032 前置：Android Relay v2 与模拟器复验

日期：2026-09-16。源码基线：`db63e2c12cae41f1aa7bf43700d46c94db57d977`。**已实现桌面响应认证，并在专用 API 26 模拟器上验证连接、错误公钥拒绝和会话结束后的迟到响应处理；正式 Android A1–A4 仍未验收。** Release 中继继续关闭，未安装或操作在线实体手机。

## 本轮修改

手机请求仍由 Android Keystore 设备密钥签名；桌面 `/v2/events` 必须先验证已注册身份，再解析和处理事件。响应使用独立桌面密钥，绑定请求摘要、随机挑战、路径、状态、时间及完整正文；手机使用用户固定的公钥验证后才解析判决。错误签名、错误公钥、过期、重放、重复头、重定向和超限响应均不能成为成功连接。协议、配对与剩余边界见 [Relay v2](relay-v2.md)。

手机使用一个有界发送队列，不自动重试。关闭、更换配对或结束会话后，旧响应不能更新成功时间或触发新引擎通知。开发者设置允许先填写完整配对、再启用；旧 v1 启用状态不迁移。原生操作另发现后台成功状态未刷新到界面：偏好监听与前台时间刷新现已修正，断连也能及时显示。

验收脚本采用临时独立响应密钥及 v2 配对，拒绝旧 CLI；仅删除自己的临时私钥和端口转发。偏好快照按 XML 元素遮盖旧明文及加密令牌，解析失败不导出原文。Debug 开发结果仍不能产生正式验收 PASS。

| 场景 | 实际结果与证据 |
| --- | --- |
| 双向认证 | 通过真实设置界面保存桌面公钥和令牌，登记手机公钥；新会话请求由 Keystore 签名，Rust 验证，Android 验证桌面响应。`prefs-dev8-connected.xml` 成功时间为 1789569156164，界面显示 Protecting，桌面 verified 增加。 |

| 在途 Critical 响应 | 模拟器 WebView Shell 打开仓库本机付款夹具，未点击付款。代理暂扣真实 `CRIT-001 / Block / require_confirm=true` 签名响应；观察服务随后断开，会话结束，再放行响应。结束读回 1789569660270，响应放行 1789569660278，等待约 409 ms。会话仍关闭，成功时间保持 1789569659292，进程仍存在，无引擎确认通知 1005。本地线索通知 1002 仍在，不能将它误算为迟到的引擎通知。 |

迟到响应的结束触发是 **UIAutomation 导致观察服务解绑**，不是模拟手动 Stop。API 26 上 `uiautomator dump` 会抑制其他辅助功能服务，已由有／无该操作的对照以及服务、会话记录确认；Android [UiAutomation 文档](https://developer.android.com/reference/android/app/UiAutomation)说明默认抑制行为。因此正常会话验证期间使用截图、受限偏好读回和桌面接口，不再把抓取 UI 树造成的解绑误判为应用自行停止。此结果不覆盖每个 OEM 或其他版本的绑定行为。

实际付款夹具只提供中继与通知生命周期信号，不证明第三方应用中的支付被执行前拦截。桌面测试审计是未签名哈希链，不是签名或 SQLCipher 审计；响应签名由单独公钥独立核对。原始记录位于 `.artifacts/android-relay-v2-2026-09-16/`，公开索引见 [证据摘要](evidence/android-relay-v2-2026-09-16.json)。
