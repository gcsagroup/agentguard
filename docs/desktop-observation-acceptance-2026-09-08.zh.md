# 桌面观察告警修复与本机验收

日期：2026-09-08。状态：源代码、回归测试及候选包无害自检通过；候选包真实屏幕观察仍待独立系统授权。

## 实际复现

此前已授权的 `AgentGuard Test.app` 实测可以启动桌面观察、停止并再次启动。第一次停止后，总览为“未在守护”，开发者诊断为 `AX=true · Capture=true · SCK=idle`，活动中出现 `SESSION-END`。第二轮启动出现多条 `OVL-007` 强制确认；选择暂停后可见“已暂停”，恢复后又出现同类告警。最后正常退出该包，结束本轮观察。

本次未投放攻击样本，告警依据包括低对比度标记及变化的 OCR 片段。这不足以证明实际桌面没有其他风险，但说明不能把“弹出告警”当作检测准确的验收结果。

## 原因与修复

1. 低对比度像素统计被直接升级为高危阻断。现在仍保留 `OVL-007` 中等级别告警及原始判定线索，但不要求用户仅凭这项统计强制确认。一个没有文字的灰色细条纹输入也能触发该统计，新增测试固定这一证据边界；并未调整像素阈值来绕过测试。
2. 桌面壳把两次连续观察当作“决策时”和“执行前”的画面，在普通文字变化时制造 `UI-REVALIDATE`。已移除这项错误比较和对应缓存。真正执行路径的 `Engine::revalidate_ui` / `process_with_revalidate` 保留，动作执行前的画面变化仍要求确认。
3. 规则原先只按匹配字符串长度选择，较长的启发式标记会盖过较短的中文注入或付款内容。现在先保留阻断、确认要求，再在相同级别内按文字长度选择。新增混合输入回归确认中文注入、英文注入与付款规则不会被低对比度标记盖过。

低对比度告警减少强制弹窗是判定边界修正，不代表完成所有隐藏文字攻击检测。未知或仅在像素中出现、未被 OCR 正确识别的指令，仍不能据此声称会被阻断。
