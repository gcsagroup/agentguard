# 桌面端使用說明(macOS / Windows)

這份文件回答四個問題:**這是什麼、怎麼開、怎麼知道它真的在工作、它做不到什麼。**
它對應桌面應用裡那張「怎麼用」卡片 —— 卡片是三步速覽,這裡是完整版。

真機回饋促成了這份文件:此前應用主介面只有一個「開始工作階段」按鈕和一行
`規則 27 · intel 2026.07.30 · AX=false · Capture=false · SCK=idle`,沒有任何說明。

## 這是什麼

AgentGuard **不替你操作任何東西**。它在旁邊看著 AI 智慧體(瀏覽器裡的、桌面上的)對這台機器
做了什麼,遇到高危動作**在動作發生之前**按住、彈一個必須回答的確認層,並把每條判決寫進本機稽核。

它**不是**防毒軟體、不是防火牆、不是通用沙箱,也不是「零間隙即時監控」:桌面觀察路徑包含取樣與輪詢,
間隙裡發生的事可能看不到。完整邊界見 [README](../README.zh-TW.md) 的「必須理解的邊界」一節。

## 一、授權(只有 macOS 需要)

macOS 上要兩項系統權限,少一項就少一路觀察:

| 權限 | 給了它什麼 | 沒給會怎樣 |
|---|---|---|
| 輔助使用(Accessibility) | 讀**視窗內容**:控件文字、表單欄位、按鈕標題 | 讀不到介面文字,表單與付款按鈕類規則全部失效 |
| 螢幕錄製(Screen Recording) | 讀**螢幕畫面**:透明浮層、隱寫像素、畫面上的文字(OCR) | 讀不到畫面,浮層與隱寫類規則全部失效 |

兩項都沒有時,應用會如實顯示**「防護範圍:模擬」**——只有模擬事件與瀏覽器擴充功能那條路在起作用。
這不是錯誤提示,是它拒絕假裝在保護。

應用裡第一步的兩個按鈕會直接把系統設定開啟到該點的那一頁,不用自己找四層路徑。

> **未簽署建置的已知問題。** 如果系統設定的清單裡根本找不到 AgentGuard,或者開關點了不生效、重開後
> 又變回關:這是 **ad-hoc / 未簽署建置**的正常表現 —— macOS 把這兩項授權釘在簽署身分上,身分不穩定,
> 授權就留不住。正式簽署(Developer ID + 公證)的版本才穩。目前儲存庫尚未完成簽署與公證,
> 見 [release-evidence.zh-TW.md](release-evidence.zh-TW.md)。

Windows 上不需要授權任何權限:讀視窗內容(UI Automation)、抓螢幕(GDI)、讀螢幕上文字(Windows.Media.Ocr)
都不走 macOS 那套逐項授權。會變的是這三樣在**這台機器上**可不可用 —— 應用裡的「即時觀察」卡片
逐項寫出可用/不可用**以及原因**。

## 二、開始守護

點「**開始守護**」。這一下做三件事:

1. **開一次工作階段。** 工作階段是稽核與策略的邊界:每條判決按它歸檔,匯出報告也按它匯出。
2. **啟動你授權過的觀察器。** macOS 上授權了輔助使用就開視窗內容觀察(AXObserver 推送 + 兜底輪詢),
   授權了螢幕錄製就開抓螢幕;Windows 上觀察隨工作階段啟動。**結束守護時它們一起停** ——
   不會「結束了還在採集」。
3. **套用任務上限(可選)。** 上面的「本次任務」下拉選了就同時限定這次工作階段能做什麼:選「訂飯店」,
   這次工作階段裡發起轉帳會被攔;不選就是不限定。

狀態燈與「現在在看什麼」那行是**從事實推出來的**,不是從「你點過按鈕」推出來的:

| 狀態燈 | 意思 |
|---|---|
| 未在守護 | 沒有工作階段。 |
| 需要授權 | 工作階段開著,但沒有任何觀察器能跑(macOS 兩項權限都沒給)。 |
| 守護不完整 | 工作階段開著、觀察器卻沒在跑,或心跳過期,或稽核寫不進去 —— **不會顯示成綠色**。 |
| 守護中 | 工作階段 + 觀察器在跑 + 心跳新鮮 + 稽核可寫,四條同時成立。 |
| 有一條確認等你 | 有高危動作被按住,等你回答。 |
| 已暫停 | 上一次拒絕之後引擎暫停了這條工作階段;點「恢復」繼續。 |

## 三、遇到風險時會發生什麼

高危動作(付款、轉帳、隱私陷阱表單、透明浮層裡的注入……)會彈出一個**必須回答**的確認層:

- 點「**先不要,暫停任務**」(Windows 殼子上這個按鈕就叫「先不要」):動作被按住,不放行。這是預設焦點所在的按鈕。
- 點「**允許這一次**」:只放行這一次,不是永久授權。
- **兩分鐘沒人回答**按拒絕處理,並寫一條 Timeout 回執 —— 不會悄悄消失,也不會預設放行。
- 鍵盤:Tab 只在彈層內循環,Esc 等於「先不要」;讀螢幕使用者會聽到播報。

每條判決(放行、警示、阻斷)都進本機稽核:哈希鏈、可逐條簽章。看得見的入口是應用底部的
「活動時間軸」,以及「匯出摘要」。

### 想立刻看到它工作:自我檢查

第三步裡的「**自我檢查:模擬一次付款攔截**」按鈕會餵一條**本機建構的假事件**給引擎:確認層會真的彈出來,
時間軸上會真的多一條判決。它**不會**真的付款、**不連網**,而且它**不是觀察** —— 它證明的是
「規則會觸發、確認層會找到你」,不是「這台機器正在被觀察」。

## 什麼都沒發生?按順序查

1. **狀態燈是「未在守護」** → 還沒點「開始守護」。
2. **是「需要授權」或橫幅寫著「防護範圍:模擬」** → 回到第一步授權;若清單裡找不到本應用,見上面
   未簽署建置那一段。
3. **是「守護不完整」** → 燈下面會列出原因(觀察器沒在跑 / 心跳過期 / 稽核寫不進去),照著那條處理。
4. **狀態是「守護中」但時間軸一直空** → 正常:沒有可疑動作就沒有判決。用**自我檢查**確認鏈路通著。
5. **想確認觀察器真的在動** → 展開「開發者面板(示範與診斷)」:那裡有原始狀態行
   (`AX=… · Capture=… · SCK=…`)、單次觀察按鈕和判決原始日誌。主介面刻意不顯示這些。

## 開發者:在 Linux 上把殼子跑起來

不需要 Mac 也能驗證「前端 ↔ 真後端」這一層:`make shell-run-linux`(要 Xvfb + xdotool + webkit2gtk-4.1)
會編譯殼子、無頭跑起來、點一遍「開始守護 → 自我檢查 → 先不要 → 結束守護」並留五張截圖;
Windows 殼子加 `SHELL_NAME=windows`。
**它不能取代真機**:Linux 上 TCC 授權、AXObserver 推送、ScreenCaptureKit 抓螢幕全是樁
(`mac_capabilities()` 恒 false),Tauri 走的是 WebKitGTK 而不是 WKWebView。指令碼開頭逐條寫明了
它證明什麼、不證明什麼 —— 第一次這麼跑就抓到一條 Playwright 樁測不出來的裸術語洩漏。

## 它做不到什麼(如實)

- **攔不住不經過它的東西。** 桌面確認層涵蓋的是引擎看得見的動作;直接呼叫系統 API、或在觀察間隙裡
  完成的動作,它攔不住。
- **不是零間隙。** 像素捕獲是取樣;macOS 的樹觀察有推送,但兜底仍是輪詢。
- **瀏覽器裡另算。** 頁面內的付款/表單攔截由 Chromium 擴充功能在頁面上同步完成(裝了擴充功能才有);
  原生訊息路徑是**非同步**的,只能事後通知,不能撤銷已經發生的操作。
- **Android 是事後通知。** 伴生應用不能阻止第三方應用已經執行的動作。
- **真機驗收尚未走完。** 簽署、公證、以及各平台逐條驗收清單的狀態見
  [release-evidence.zh-TW.md](release-evidence.zh-TW.md) 與 `docs/acceptance-*.md`;目前發佈判斷是 **No-Go**。
