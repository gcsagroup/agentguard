# Cross-browser scope for the first GA

> Conclusion: the first GA supports Chrome and Edge only, using one shared Chromium ZIP. Firefox remains a source prototype and is not packaged, submitted, or used as a first-GA acceptance gate. Safari is a separate product line. Native Messaging is disabled in the GA browser package.

## First-GA support scope

| Item | Chrome | Edge |
|---|---|---|
| Release package | `agentguard-extension.zip` | Same ZIP as Chrome |
| Page scanning | Isolated content script at `document_start`; every HTTP(S) frame where the browser permits injection | Same as Chrome |
| High-risk DOM actions | Block-only before execution; no in-page release | Same as Chrome |
| Static payment DNR | Enabled by default; hard-blocks only the declared keywords, HTTP(S), non-GET/HEAD methods, and resource types | Same as Chrome |
| Native Messaging | GA manifest has no `nativeMessaging` | GA manifest has no `nativeMessaging` |
| Acceptance | Separate Chrome store-candidate evidence | Separate Edge store-candidate evidence |

The Chrome manifest's `minimum_chrome_version` matches the DNR capability it uses. Edge uses the same `chrome.*` APIs, manifest, content scripts, and rules. Shared source and ZIP do not replace separate install, upgrade, permission-prompt, and runtime acceptance on each browser.

## Shared security boundary

- In HTTP(S) frames where the browser permits injection, matching payment or transfer clicks and privacy-trap personal-data submissions are synchronously stopped and never replayed.
- An in-page notice is only a page-removable, coverable, or imitable information layer, not authorization UI.
- If a user truly needs to continue, they must disable or remove protection from `chrome://extensions` or `edge://extensions` and independently repeat the action. There is no in-page “Allow once” or temporary exception.
- Static DNR is an independent block-only network layer. It covers only the listed payment-path keywords, HTTP(S), non-GET/HEAD methods, and `xmlhttprequest`, `ping`, `main_frame`, or `sub_frame` resources.
- Static DNR also explicitly covers the listed byte-wise percent-encoded path variants and queries where `op`, `action`, or `operation` equals a payment marker. It does not inspect bodies and does not claim body-only intent, custom aliases, unlisted encoded or obfuscated forms, arbitrary query keys or values, WebSocket/WebTransport, or other resource types.
- Page `postMessage`, legacy decision/scope messages, and ordinary page DOM are not trust roots.

See [Browser pre-execution blocking](浏览器执行前阻断.en.md) for the exact keywords, character boundary, and negative surface.

## Firefox: source prototype, not a first-GA product

The repository retains `manifest.firefox.json` and compatibility source as a starting point for future development. Their presence does not mean shipping support:

- `package-store.sh --firefox` must fail and must not produce a Firefox store package;
- first-GA release gates, acceptance checklists, and launch conclusions must neither require nor cite a Firefox PASS;
- Chrome / Edge E2E results are not Firefox runtime evidence;
- the existence, version parity, or structural-test success of Firefox prototype files cannot be promoted into a “Firefox supported” claim.

If Firefox enters a later release, its manifest, DNR behavior, permissions, store package, and real-browser acceptance must be completed separately before the support matrix changes.

## Native Messaging: disabled for GA

The GA manifest explicitly does not request `nativeMessaging`, and the Chrome / Edge ZIP contains no Native host. Host source, installer templates, and experimental connection code may remain in the repository, but they are not first-GA runtime paths, store capabilities, or acceptance evidence. The first GA claims no Native verdicts, dynamic-host blocking, host notifications, or local audit chain.

## Safari: separate product line

Safari Web Extension delivery uses a separate Xcode app shell, Extension target, and Apple signing flow. It does not use this Chromium ZIP and is outside the first-GA browser scope defined here.

## Verification boundary

`make check-extension-gate` should verify the Chrome / Edge package, block-only DOM behavior, static DNR, absence of Native Messaging from the GA manifest, and rejection of Firefox packaging. Automation passing is not a real-browser PASS for a Chrome or Edge store candidate; final status requires new evidence bound to each candidate, not a historical report.
