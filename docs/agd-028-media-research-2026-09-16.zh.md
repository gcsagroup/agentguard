# AGD-028：文档与图片隔离解析研究

日期：2026-09-16。本文是实现前研究与验收约束，**不是格式支持或解析安全的验收结果**。当前产品仅声明 UTF-8 TXT／MD 检索。M3 长测期间只核对代码和一手资料，未安装解析器、更新执行镜像或修改当前候选。

后续已开始按此范围实现隔离解析组件，六种格式的组件与固定入口结果见[实现记录](agd-028-media-parser-2026-09-16.zh.md)。本研究的历史时间点不改写；RAG 接入和原生验收仍未完成。

## 现有入口与选择

`crates/guard-gateway/src/memory.rs` 的正文上限为 32 KiB；`rag_import` 已有授权目录、快照、宿主来源及独立存储批准。现有 `Material::Document.document_sha256` 绑定 UTF-8 正文，不能把转换后的文本摘要冒充原 PDF／Office 文件摘要。桌面 OCR 策略服务于屏幕帧，不代表已有文档文件 OCR 接口。

建议使用**按格式调用、离线运行的解析子进程**，接入现有受控快照和 RAG 批准。产品只接收解析器的有界文本及覆盖说明，原文件摘要、正文摘要、解析器版本分别记录。沿用一个项目执行镜像；如需更新依赖，按原镜像的更新流程构建和验证，保留此前候选证据。

| 方案 | 已核对事实 | 本项目取舍 |
| --- | --- | --- |
| MarkItDown | 支持 PDF、Office 和图片转换，也包含 URL、插件及可选云端集成；OCR 插件可以使用 LLM Vision，缺少客户端时可能跳过 OCR | 可参考其格式适配器；不能把通用转换器或本地模型清单中的同名服务直接作为安全边界，不能静默跳过 OCR 后显示完整覆盖 |
| pypdf 文本层 + Office 格式适配器 | PDF 文本提取可能需要大量解压和内存；pypdf 不执行图像 OCR。Office XML 还需独立限制实体、解压规模和复杂度 | 初始接入优先明确的本地格式入口；选定依赖后再冻结实际版本、摘要及资源消耗，宿主进程不直接解析不可信文件 |
| Pillow + 本地 Tesseract | Pillow 提供像素及解压警告，但仍建议进程隔离；Tesseract 有独立的简中、繁中、英文识别数据及速度／精度选项 | 图片元数据与 OCR 分别报告状态；显式启用所需语言，限制像素、尺寸、帧数和总输出，不能把空识别结果解释为无风险 |

以上工具能力来自 [Microsoft MarkItDown](https://github.com/microsoft/markitdown)、[pypdf 文本提取文档](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)、[Python XML 安全文档](https://docs.python.org/3/library/xml.html#xml-security)、[Pillow 安全文档](https://pillow.readthedocs.io/en/stable/handbook/security.html)和 [Tesseract 识别数据说明](https://tesseract-ocr.github.io/tessdoc/Data-Files.html)。选型与接入方式是本项目的工程判断；文档中的示例和版本不作为已安装版本证明。

## 拟冻结的支持范围

小范围接入应同时覆盖 PDF、现代 Office 和图片，不能只交付 TXT 换名：

| 输入 | 拟读取内容 | 必须显示的未覆盖部分 |
| --- | --- | --- |
| PDF | 文本层及有界文档元数据，保留页号 | 扫描页图像、字体映射或版面导致的遗漏；无文本页单独标记，不自动判为安全 |
| DOCX | 正文、表格及所支持的附属文本部件 | 未解析部件、嵌入对象和图像；不执行宏、链接或脚本 |
| XLSX | 单元格文本，公式作为文本；明确所读工作表 | 不计算公式，不刷新外部连接；不能用旧缓存值假装重新计算结果 |
| PPTX | 幻灯片及所支持的备注文本 | 未解析的嵌入对象、图片和动画，不运行活动内容 |
| PNG／JPEG | 有界元数据、图像 OCR | OCR 语言、识别不确定性、不可见编码和未覆盖像素内容；多帧及其他格式另行声明 |

旧二进制 Office、受密码保护文件、宏专用格式及音视频不通过改后缀进入这些入口。音视频按原 AGD-028 要求另列子任务和估算。上述格式表仍需落实为代码、可核对输出和真实隔离验收。

## 限制与失败语义

实现时冻结并记录输入字节数、页数／工作表／幻灯片／ZIP 条目上限、单条目与总解压上限、XML 深度、图像像素／尺寸／帧数、正文和元数据输出上限，以及实际进程／内存／CPU／墙钟限制。不得仅凭压缩文件小于输入上限就允许无限解压。

现有执行器提供无网络、只读根、去除 capabilities、64 进程、256 MiB 内存及 30 秒执行限制；是否足够需要实测，不能为使样例通过而静默提高限制。依赖缺失、解析错误、资源超限、空结果及不支持格式须分别返回明确状态。超时或崩溃后回收自有进程，下一份正常文件仍可解析。

输出必须说明“已解析的层”和“未覆盖的层”。解析成功只说明提取操作完成；文本、元数据和 OCR 结果继续携带不可信来源及原限制标签，没有修改宿主策略、权限或批准的能力。记录和界面不得把 `parsed` 映射成“安全”。

## 接入与验收要求

1. 原文件从已经授权的快照读取；原文件字节摘要与解析结果绑定，隔离任务不能读取宿主密钥或操作者连接文件。
2. 本地格式入口不获取 URL、外部关系或云服务；实测 DNS／网络及目录外文件读取失败，不能只引用配置开关。
3. 存储时同时绑定原路径、原字节摘要、提取摘要、解析器身份、格式、覆盖及限制；已有 TXT／MD 历史继续可读，不迁移或重写原审计。
4. 每个格式使用预声明的正常中文／英文样例、包含指令文字或隐藏文本的攻击样例及截断／畸形／超限样例，比较实际输出；保留页／表／幻灯片出处。
5. 用合成 ZIP／XML 膨胀、超大像素声明、资源超限和实际进程故障核对失败状态、宿主文件不变、无越权网络副作用及正常文件恢复；不运行真实恶意样本。
6. 受控读取、独立批准、RAG 来源与撤销后新任务过滤一起验证；解析器输出不能绕开现有网关控制。
7. 完成后再更新产品格式声明、文档与固定 App；仍需准确候选、必要回归、真实操作及签名／资源核对，不能用本研究标记 AGD-028 完成。
