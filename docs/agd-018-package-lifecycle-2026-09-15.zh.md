# AGD-018 签名包、持久状态与 CLI 验收

日期：2026-09-15。状态：进行中。知识包与规则包格式、持久更新仓库及实际管理 CLI 已实现；生产网关的策略切换、撤销后旧批准失效和来源接线仍待完成。以下结果不代替这些产品工作，不代表原生 App 或完整 AGD-018 验收。

## 当前已实现

`guard_intel::package` 区分 `knowledge` 和 `rules` 两类包。知识包保存既有知识库目录，保持 `authorization_effect=none`；即使签名正确也不能转换为可执行规则。规则包包含既有 `RuleSet` 与检测情报 `ThreatBundle`，不接收知识库字段或嵌套情报签名。兼容入口要求完整规范字段，拒绝静默丢弃旧类型允许的额外字段。

签发沿用 Ed25519，公钥由宿主固定提供。包版本为三个无前导零的整数段；签名覆盖整个发布正文：类型、流、递增序号、安全代次、读取协议兼容范围、生效／到期时间、灰度配置、安装内容或撤销／恢复目标。JSON 对象递归排序，数组顺序保留，加入独立域标识后 SHA-256，再签名；不同顺序和空白不改变含义。所有层级的重复字段、浮点数、未知字段、尾随消息、过深 JSON 及超过 4 MiB 的输入均拒绝。`sha256:` 和未签名内容不能替代 Ed25519。

首版读取协议为整数 **1**。`min_reader` 与 `max_reader` 是签名保护的包读取协议范围，不冒充 macOS App 版本范围。新更新只有在宿主当前时间位于签名有效期内才接受，签发有效期最多七天；已经接受的包重启后重验签名和原接收记录，不把发布到期误当成自动撤销。

灰度使用宿主固定设备标识、更新流和签名盐生成稳定分组，比例为 0～10000 个基点。相同盐增加比例保留原已选设备；包或模型不能改变宿主设备身份。未入选时保留原有效包与安全下限，但仍记住新序号，不能随后重放更旧发布。

`PackageStore` 将签名更新流水与可重建的激活状态放入同一个 SQLite 事务。仓库固定签发公钥、类型、流和设备；每次读取均重新验签流水并按顺序重建状态，状态与实际内容从同一读取事务获得。写入者使用立即事务读取最新序号，不能凭各自的旧缓存覆盖较新状态。索引、签名正文或接收记录损坏时拒绝加载。

普通更新须高于已接受发布序号、不低于安全下限，且不能降低历史最高已安装版本；相同版本只能对应曾接受的准确内容。同一内容摘要不能重写原安全代次或兼容范围。结构、签名、兼容、时间或数据库写入失败都不消费序号，不替换当前有效包。

撤销必须覆盖所有灰度分组，并永久记录准确内容摘要；即使从未安装过该摘要，也会阻止之后安装。撤销当前包后有效包为空，调用方必须停止使用旧包，不自动选择历史包。恢复是另一个独立签名更新，必须指向本机曾成功接受且未撤销的准确摘要，仍不能低于安全下限；恢复较早版本不会重置历史最高版本或发布序号。

首版仓库保留最多 256 条更新、64 MiB 签名流水，达到上限拒绝覆盖历史。它防止更新渠道重放旧包；宿主仍须保护仓库路径，不能将此机制称为能抵抗本机管理员删库或恢复历史磁盘快照。知识和规则正文保存在各自包仓库中，不冒充执行审计日志。

## 实际命令

`guard-cli package` 提供以下命令，均无自动网络获取、认证发现或后台更新：

| 命令 | 作用 |
| --- | --- |
| `sign --release … --secret … --out …` | 对完整规范发布正文签名，只能创建新输出文件。 |
| `inspect --package … --pubkey …` | 验签、显示类型及摘要；不安装、不消费序号。 |
| `init` | 按宿主固定身份创建新仓库，Unix 权限 0600；不能重新初始化已有仓库。 |
| `apply --package …` | 在已有仓库应用安装、撤销或恢复的签名发布。 |
| `status` | 对完整流水重新验签，显示有效包、最高序号、安全下限和撤销摘要。 |
| `evaluate --event …` | 每次从仓库读取当前规则，用真实 `guard-core::Engine` 处理给定事件；无有效包或知识类型均拒绝。只产生判决，不执行外部动作。 |

`init`、`apply`、`status`、`evaluate` 共同要求 `--store`、`--pubkey`、`--stream`、`--kind rules|knowledge`、`--device-id`。这些参数应来自可信宿主配置，仓库应位于 Agent 可写任务目录之外。查询或应用命令不会在路径缺失时隐式创建空仓库。

旧 `intel-fetch` 等接口保持原范围，它们没有因此自动获得新仓库的防回滚、灰度或撤销语义。生产网关接线完成前，不应把本模块的能力算到仍走旧加载路径的应用上。

## 验证结果

新增 **14 项签名包测试、16 项仓库测试**，包括两线程真实并发写入、重启读取、索引／正文损坏、写入触发器失败、类型混淆、未知字段、兼容／过期、稳定灰度、撤销及安全下限。全仓 62 组共 **1415 项通过、14 项忽略**；桌面库 **122 项通过、9 项忽略**。严格 Clippy、格式、能力矩阵与三套依赖图检查通过。只增加既有 `guard-schema` 和 `rusqlite` 依赖关系，没有引入新第三方包；SQLite／SQLCipher 使用宿主原有链接模式。

自有 CLI 实操 **20/20 通过**，没有使用示例二进制替代实际 CLI：

- Node 独立签发由 Rust 验证，Rust 签发再由 Node 验证；完整控制正文和内容摘要一致，签名输出不覆盖已有文件。
- 多个独立 CLI 进程读取同一磁盘仓库，版本 1／2／3 分别产生对应的真实引擎判决；合成支付硬拒绝正对照保留。
- 篡改签名、旧序号、不兼容、过期和错误流均不改变有效包。灰度零比例保留旧版本，推广后才使用新版本。
- 对真实 SQLite 插入设置失败触发器，更新失败后旧包仍可读、原规则仍阻断、没有半提交；恢复写入后继续推进。
- 撤销后新进程拒绝执行；独立签名恢复准确旧包，已撤销／未接受／低安全代次的恢复均拒绝。
- 真实知识库在独立仓库安装成功，但不能用于规则执行，也不能覆盖规则仓库。
