## 1. 开发目标与首批范围

首批交付：**用户从桌面选择授权工作区并启动一个受保护任务；代码在经过验证的隔离环境中运行；危险请求由独立控制面批准；用户能看到实际执行结果及对应威胁手法。**

按两条工作线推进，共用事件和证据格式：

- 执行控制：会话、隔离、凭据、批准、审计、桌面和浏览器接入。
- 威胁知识库：Taxonomy、Kill Chain、Technique ID、案例、检测规则、回归样本及覆盖记录。

第一批实施范围为 AGD-001～AGD-013；首批验收通过后再进入内容来源与 MCP 治理。持久记忆、多 Agent、多媒体和原生系统联动都有明确后续任务，不同时开工。

现有 Windows、iOS、Android、Chrome/Edge 的承诺范围和发布门槛继续保留。分期聚焦不等于取消其他平台；也不能拿代码执行试点替代全产品 GA。

## 2. 排期假设与里程碑

以下人员配置用于原排期估算。本轮实际由主任务统筹、集成和复审，三名 subagent 分别承担后端实证、执行契约／审计、知识库与桌面／浏览器适配，随后交叉复核。

| 角色 | 工作职责 |
| --- | --- |
| A：系统与引擎开发 | 执行隔离、网络与凭据、事件来源、信息流和记忆存储 |
| B：接入与产品开发 | 会话与批准、桌面与浏览器接入、MCP、知识库及审计接线 |

默认 A、B 各一名全职开发，Q 一名测试；开发任务估算含自测与代码评审，独立验收另列。工期用开工后的工作周表示，不指定未经确认的开工日期。默认已有可用 Linux 测试环境及当前 Mac；若需要从零开发和分发本机虚拟机管理功能，须先根据 AGD-002 结果重估，不能算进“已有后端”。

| --- | --- | --- | --- |

里程碑是工程验收门：满足证据即可进入后续开发，不要求用户为每个普通实现细节重复确认。发布、外部账号变更和真实业务操作仍按既有授权范围处理。

## 3. 当前基线及必须关闭的缺口

本轮核对的 Git HEAD 为 `b53387ebb67ecdef56f1322e4e3628a5fc66977c`，包含既有未提交变更。历史 `_push/agentguard` 路径不能作为当前开发／发布依据。

上一轮已保存的基线为：相关 8 个 crate 测试 708 通过、2 忽略；正常操作 50/50；结构化文件工具能拒绝越界，但获准执行的脚本可读写目录外临时文件。见 [测试汇总](../.artifacts/threat-capability-plan-2026-09-09/validation-summary.json) 和 [边界复现](../.artifacts/threat-capability-plan-2026-09-09/runtime-boundary-report.json)。这些结果是后续对照，不是本轮重跑或新功能验收。

M1 的首要关闭项：

1. 脚本内部文件访问、子进程和网络调用必须受实际执行环境约束。
2. Agent／MCP 服务不能读取批准凭据或自行扩大任务范围。
3. 批准须绑定最终动作，写文件不能只显示路径和字节数。
4. 网关要持久记录实际结果，不能只生成判决或依赖内存日志。
5. 用户能分辨“仅观察”“网关控制”“隔离控制”和“当前未覆盖”。

落点：`crates/guard-gateway/src/{exec,gate,server,confirm}.rs`、`guard-jail`、`guard-shell`、`guard-audit`、`apps/desktop-macos`、`apps/protected-browser`。先复用现有模块；AGD-002 的选型证明需要独立组件时再新增执行后端，避免先建通用框架。

**执行后端的具体约束：**默认不共享宿主用户目录、SSH Agent、Keychain、个人浏览器资料、剪贴板和容器管理 Socket。M1 可先用工作区快照在隔离环境中运行，再由宿主核对差异后应用回原目录；回写检查原文件摘要，出现冲突不覆盖用户编辑，创建／删除也走同一授权过程。确需直接挂载时单独验收共享目录与链接边界。

**Agent 自身的旁路：**若客户端还有未受控原生终端、文件或网络工具，界面只能声明已覆盖入口；要标为隔离会话，实际可执行代码的客户端和第三方服务必须处于可验证的隔离范围，或由可信接入方式取消旁路。MCP 子进程不能因为客户端开启沙箱就自动被视为受隔离。

**模型数据出口：**模型 API 的令牌尽可能由独立服务持有；发送给远程模型的工作区内容是单独的数据流。启动会话时定义允许发送的数据范围，测试日志、提示内容和工具结果中的标记是否越过该边界。

### 里程碑硬门槛

1. **安全结果**：指定负例中未授权文件修改／网络提交为零；目录外读取验证覆盖结构化工具和解释器两条路径。缺日志不能推断没有副作用。
2. **正常工作**：M1 至少 50 个完整、预先列明的受支持任务，完成率 ≥95%（50 个时至少 48 个）；包含改代码跑测试、失败恢复和浏览器任务。未经预声明的不兼容任务不能事后从分母删除；需确认的授权工作不等于误报，确认次数单列。
3. **恢复可靠性**：至少 100 次任务／连接循环和 30 分钟运行，覆盖批准、拒绝、断连和重启；同时做实际休眠、进程崩溃和网络中断，不能用循环总数代替故障种类。
4. **证据完整性**：记录实际工具、目标摘要、策略版本、批准、执行与业务结果；重复提交、未知结果和补偿动作有独立状态。
5. **性能**：M0 固定测试机器和输入，测网关新增 p50/p95 延迟、内存上限及恢复耗时；M1 前冻结预算。模型生成、用户等待和远端业务耗时不混算为网关开销。

每个阶段新增能力都要有正常、攻击、失败恢复三类验证；M2/M3 复验其影响到的 M1 任务，不能用安全强化掩盖正常任务退化。通过只说明指定场景，不宣称未知攻击零漏报。

## 8. 交付纪律、回滚与任务状态

状态统一为：`待开始 → 开发中 → 待验收 → 已完成`；环境或输入依赖缺失记“阻塞”，记录条件和独立可继续项。一个任务只有代码、必要测试、实际效果和相应说明均齐全才能标已完成。

每项交付至少包含：任务 ID、实际修改路径、威胁 ID、运行证据路径、风险／未覆盖说明及撤销方法。运行证据使用独立目录 `eval/out/<任务ID>/<候选摘要>/`（拟新增约定），版本库保留脱敏索引及复现说明，原始输出与测试凭据按现有忽略规则保存，不把账号材料提交。

AGD-001 先处理工作区来源与现有变更归属，再创建需要的 `codex/` 工作分支或隔离工作树；不能从干净 HEAD 开新分支后遗漏当前所依赖的未提交能力。分支／提交按可审查变更拆分，不要求为每个测试步骤创建一个分支。

回滚原则：策略与情报包恢复到经独立授权的已知良好版本；存储迁移先备份、保留版本兼容与恢复验证；会话结束撤销令牌和未执行批准；已发出的外部请求不自动补发。旧文档 [文档实现差距修复计划](开发计划-文档实现差距修复.md) 中已修复内容不重复实施，未完成发布义务由 AGD-001/032 关联清点，不直接改历史勾选。
