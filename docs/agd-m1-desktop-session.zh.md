## 使用路径

1. 由宿主按选定任务配置启动隔离会话，生成独立的 `control.json`。
2. 桌面进入“主动防护”，选择连接文件，或填入文件的绝对路径，然后导入连接。旧的端口／令牌输入收在“兼容连接（原生网关）”。
3. 在“会话与工作区结果”选择已有工作区，核对原目录和任务快照。这里不能扩大授权范围；客户端是否在工作也不能只从控制连接判断。
4. 点击“预览待回写文件”，展开每个文件的修改前后全文，核对目标原目录、原件恢复目录及动作摘要。二进制内容仅显示字节数、权限和摘要，不假装提供文本差异。
5. 不接受时可直接“放弃本次差异”：只拒绝本次回写，保留任务快照和活动会话，重新预览仍可查看差异。勾选完整核对后才能回写。界面显示会话最近回写结果、每个文件的状态、原因和恢复位置。部分应用、冲突、未知均有单独结果，不折算为成功。
6. 暂停会撤销当前与待确认动作。恢复保留授权和快照，但生成新会话编号，旧批准失效；客户端需要新的会话标识继续。永久停止不能恢复。断开确认通道仅断开桌面连接，不等同于停止宿主任务。

选择工作区、生成授权并直接从桌面启动客户端，尚未在本轮实现；仍依赖宿主先启动。第三方客户端恢复兼容、系统休眠／网络故障恢复与完整 M1 场景由各自联合验收记录判定。

## 安全边界

- 连接文件必须是当前用户所有、权限精确为 `0600` 的普通文件，最多 8 KiB；读取父路径和末端时均拒绝符号链接，拒绝目录、管道、相对路径、错误字段、外部地址及实例不匹配。导入令牌只留在 Rust 中，不返回 WebView。
- 工作区 API 只使用导入文件对应的 IPv4 环回实例；确认状态保留 2 秒总期限，工作区操作使用 15 秒总期限。完整 JSON 上限 4 MiB，超过上限整条拒绝，不截断后批准。
- 完整预览与 `ApprovalBinding.action.parameters` 逐值一致；校验会话、工作区、目标、工具服务、工具名、期限、批准编号、批准随机值和动作 SHA-256。文本正文还核对字节数与 SHA-256。原件恢复目录也参与绑定。
- 回写前重新获取会话状态，核对未使用的预览，发送批准编号、动作 SHA-256 和 Rust 保存的随机值。本地在发出前消费批准；未知回执不重发，界面保留本次提交的目标与恢复位置供核对。
- 暂停／恢复／停止先核对 POST 回包的服务、协议、实例和会话身份，再 GET 获取完整状态，避免 POST 未返回完整状态字段时把已生效的操作误报为未执行。放弃回写使用同样的完整批准绑定和一次消费规则，最终 GET 必须确认该预览已失效。
- 慢操作不占用连接锁，暂停／停止可以并行撤权；操作代次阻止旧回包恢复批准。实际写入前的最终串行和撤销检查由宿主承担，点击暂停不能承诺撤回已经开始的写入。
- 多文件回写不是原子事务；恢复目录提供原件恢复依据。界面显示的“会话最近结果”不冒充当前下拉框所选工作区的新回执。
