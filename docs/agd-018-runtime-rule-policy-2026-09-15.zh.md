# AGD-018 生产网关规则包切换

日期：2026-09-15。本轮将上一批签名仓库接入实际 `agentguard-mcp`，覆盖内建文件／命令、本地与远程 MCP、宿主回写、受保护浏览器 DOM 和 HTTP。知识包仍不能执行。原生 Ver 1.0（010）App 没有重新构建或替换，本次是 CLI 后端验收；F13 保持暂缓、未验收。

## 操作者使用方式

先使用[包管理 CLI](agd-018-package-lifecycle-2026-09-15.zh.md)初始化规则仓库并应用签名发布。新建宿主私有配置，示例字段如下；公钥为准确 32 字节 Ed25519 公钥的 Base64，流名和设备标识须与初始化一致：

```json
{
  "store": "/宿主私有目录/rules.db",
  "public_key_base64": "替换为实际公钥的Base64",
  "stream": "agentguard.rules.production",
  "device_id": "替换为宿主固定标识"
}
```

配置和仓库均须为当前用户拥有、权限 0600 的已有普通文件；父目录不能让其他用户写入，路径不能含用户符号链接。两个路径必须位于任务读／写授权目录之外。启动参数加入 `--rule-package-config /宿主私有目录/rule-package.json`，同时提供已有的隔离镜像、审计和宿主控制参数。缺少有效包、固定身份不一致、文件缺失或权限不合规均拒绝启动；客户端工具参数不能更改配置。

运行中继续使用 `guard-cli package apply` 应用安装、灰度、撤销或恢复发布。新动作读取当前已验证状态，无需重启网关。更新成功才表示已提交；遇到 `database is locked` 表示该次更新没有提交，原策略仍有效，应在活动动作结束后再由操作者重新提交。`status` 是只读检查，活动动作期间也可查询。

## 实际保证

- 规则包作为附加约束层。允许规则不能覆盖宿主硬拒，确认要求不能降低；更新只替换规则内容，保留主引擎的会话、已用预算和来源状态。写文件正文也参与规则检查。
- 动作摘要同时绑定启动规则／路径策略／计划摘要、固定签名者及宿主身份、包内容摘要、发布序号和安全下限。恢复相同旧内容也产生新绑定，旧批准不能复活。
- 实际派发前取得规则许可，直到动作返回才释放。许可持有 SQLite `BEGIN IMMEDIATE` 事务，普通日志和 WAL 模式都阻止更新与旧策略动作交错提交。跨线程派生 HTTP 可复用同一代次事务，不重新争抢写锁。
- 等待单次批准时不新占用策略事务。若 DOM 动作本身还在运行并等待其派生 HTTP，外层动作的许可会继续持有；此时更新可能明确超时失败。它不表示可以取消已在远端发生的副作用。
- 撤销导致无有效包时，新动作全部拒绝；不会自动选择历史包或重开会话。回写须重新预览并批准；暂停／停止等宿主安全控制仍保留。
- 执行日志保存包内容摘要、运行绑定摘要、发布序号和安全下限，并与该动作的完整摘要相连。流名、正文、自定义说明和宿主路径不直接写入审计。知识及工具内容始终不因此获得指令授权。

该机制约束启用配置的生产 CLI。旧 `intel-fetch`、未启用此配置的网关、010 App 和其他平台入口不会自动获得相同行为。宿主启动时的第三方清单发现沿用原有独立配置授权；模型工具调用及其初始化使用本次规则许可。仍不宣称抵抗本机管理员删除／替换整个私有仓库或恢复磁盘快照。

## 保留的失败与修正

初次组件测试因默认 Xcode 要求重新接受许可而无法链接；显式指定已有 Command Line Tools 后继续。网关和桌面合成 Python 端点清空环境后曾误入开发工具代理，现测试端点使用显式工具选择或实际解释器，未放宽产品的子进程环境白名单。首轮全仓检查发现能力矩阵未生成，补齐后三语矩阵与源码一致。

`runtime-01` 的旧预览验收器没有识别新增规则包回执，保留完整参数核对后扩展了预期字段。`runtime-02` 发现状态查询争抢写锁，已将已有仓库的身份读取改为只读事务并增加运行中查询测试。`browser-01` 原先试图从刻意隐藏输入值的读取结果证明字段未改，现合成页面以真实输入事件显示草稿，并核对其未变化。早期候选与失败日志全部保留，未混作最终候选证据。

组件夹具初版为空规则，不符合既有签名发布协议，改为有效合成规则后完成实测。独立核账初版误写“动作记录数大于 80”，实际准确为 80；修正为逐条要求每个动作都有规则来源，并对全部 80 条重算绑定，未豁免任何动作。两次核账日志均保留。
