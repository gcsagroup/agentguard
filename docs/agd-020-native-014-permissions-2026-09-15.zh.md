## 为什么反复授权仍显示未检测到

通过 Computer Use 核对，系统设置中的 `AgentGuard Local Agent Test.app` 辅助功能开关已打开，但固定路径的 Ver 2.0（014）App 仍显示“未检测到”。这两个状态确实不一致，不能归因于用户没有打开开关。

系统 `tccd` 日志对当前标识和辅助功能服务明确报告：`Failed to match existing code requirement`。进程归属指向准确 App；源码每次查询都会调用 `AXIsProcessTrusted()`，界面显示该真实结果。日志位于 `.artifacts/m2-native-performance-2026-09-15/permissions-14/tccd.log`，第 113 行及第 39、46、105 行相互印证。

当前 014 与保留的 012 具有相同的 designated requirement，使用同一组织证书；严格签名检查通过。这只能证明这两份 App 的当前要求一致，不能证明系统保存的更早授权与之匹配。没有读取到受保护的 TCC 数据库，尚不能还原旧记录的确切要求或形成时间。

此前排查未把“系统开关”“当前签名身份”“实际读取窗口”逐项闭环，反复构建并不能修复这条旧授权绑定。确认原因后保留同一份 014，不再为权限问题反复打包或重签。

用户随后移除了旧辅助功能条目，22:44:02 的系统日志记录删除。重新读取设置后，执行器通过“添加”和准确完整路径选中当前 014 App；系统显示开关开启，当前 App 随即显示两项“已授权”和“桌面观察已就绪”。没有在聊天中索取或保存密码，没有修改其他 App 的权限；用户操作产生的旧 M1 条目变化与执行器操作分开记录。

结束守护后出现 `SESSION-END`，SCK 为 `idle`。再修改合成文稿，间隔后复核仍未守护、重复观察计数保持 114；没有新的观察条目。这是一次有限的原生启动、读取和停止检查，不替代完整 macOS 时序清单、长时运行、F13 或下一次重新构建后的权限检查。合成文稿通过 TextEdit 保存到本批证据目录并关闭，未保存在用户 iCloud 文稿目录。
