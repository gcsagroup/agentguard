日期：2026-09-09。状态：**同一候选的50个完整任务、100次完整循环、50项独立负例与30分钟持续测试均已通过。**

本轮仅使用脚本新建的临时工作区、合成输入、本机已安装的 Docker 镜像及本地控制接口。既有 78 项隔离检查和 50 项操作对照保留原报告，不充当下列 50 个完整任务。生产代码由主任务及其他工作线实现；本线负责独立启动器、预期成果、实际文件核对和故障证据。

## 计数和完成条件

每个完整任务必须完成：选择独立工作区与授权 → 经 MCP 读取输入 → 完成该任务的多步处理／修复 → 在快照内核对成果 → 操作员查看完整差异 → 绑定本次预览批准回写 → 核对宿主实际成果及未授权路径未改 → 停止会话。一个文件读取、一次断言、一个 Python/Node 子检查或一个工具调用均不单独算任务。

任务 T01～T40 是不同的本地数据处理／项目维护目标；T41～T50 是发生拒绝、冲突或中断后仍交付正确成果的用户流程。后十项不能因为“拒绝成功”就算完成，必须继续完成表内明确的最终成果。安全负例另计，不加入正常任务成功率。脚本化流程证明受保护会话能完成这些预先声明的工作，不证明模型能独立编写任意程序。

任务成功须同时满足成果语义、精确文件集合、内容与权限核对；`ApplyReport.outcome` 必须为 `applied`。`partial` 或 `unknown` 会留下明确证据并停止自动操作，不能按成功计数，也不能自动重试已发出的回写。所有任务的输入与程序、候选二进制、策略、镜像和脚本均记录摘要。

## 安全负例与真实故障

独立负例至少覆盖：缺失／错误操作员令牌；MCP 伪造 workspace 接口；换任务名／来源；旧会话批准；错误 review ID、摘要、随机值；预览过期、正文变化及重复 apply；宿主修改／删除／并发新建；宿主与快照父目录链接置换、硬链接别名；暂停／停止／EOF 后请求；任务运行时尝试读取控制文件、访问宿主标记或继承凭据。

每个拒绝都核对真实宿主树与独立目录标记。回写前的冲突应为零修改。回写批次不是原子事务：若写入过程中发生真实竞争，允许 `partial`／`unknown` 准确描述已发生的授权修改，但必须保留恢复信息、停止后续写入、绝不覆盖并发新对象或自动重试。这种结果不能算正常任务成功，也不能用“已拒绝”掩盖先前副作用。

真实故障分别登记，不能用大量循环替代：工具超时；操作员暂停／停止；stdio EOF；待批准阶段SIGKILL；执行中SIGKILL；审计事务失败；宿主正常编辑冲突；新建冲突；父路径置换；Docker 中本测试容器被停止。只停止由本次快照挂载关系确认归属的测试容器，不停止 Docker 服务或其他容器。

**系统休眠、真实物理／系统网络中断、准确身份的桌面 App 故障恢复及外部模型数据出口不由这些合成脚本证明。** 它们单独留在 M1 联合验收清单；本地控制接口超时不能改名为真实断网。

## 100 次循环与 30 分钟运行

候选、镜像和 operator schema 冻结后才启动长期测试。100 次循环的每次都具有独立连接标识，完成 initialize、读取状态、任务输入处理、预览与确认、宿主核对、停止／重建及凭据撤销核对；不能把100次ping记成100次任务循环。以十种预先声明的流程各重复10次：正常交付、拒绝后新交付、暂停待批准、暂停运行任务、永久停止、stdio断连重建、预览变化重建、宿主冲突后重建、只读拒绝检查后明确给予新会话写权限、连续两次独立提交。

30分钟检查记录单调时钟的实际起止与间隔，不回填运行时长。使用一个连续存活的独立只读会话每15秒做一次心跳／状态核对，同时每分钟另建一个有实际文件成果的完整任务；穿插预先登记的暂停／恢复、拒绝、断连重建及崩溃事件。记录连接数、完成任务数、失败种类、最长无响应间隔、网关／自有容器峰值及遗留数量。工具单次等待最多60秒，持续运行期间每分钟向主任务报告进展。

100循环和30分钟两项分别报告，若合并一次执行则同时满足两个独立计数且保留对应样本；不为凑满计数把失败重试算新成功。长期运行异常立即保存 evidence；安全负例一旦出现未授权宿主修改，停止后续危险动作并保留现场。

## 已冻结接口与待就绪项

operator HTTP v1 使用独立控制连接文件中的凭据。`GET /workspace/status` 返回当前实例／会话、状态、工作区和待复核摘要；`POST /workspace/preview` 接收 `workspace_id`；`POST /workspace/apply` 仅接收 `review_id`、`review_sha256`、`review_nonce`。操作员放弃预览使用 `POST /workspace/discard`，输入与apply相同三绑定，消费该预览并记录拒绝、保持会话继续。暂停、恢复、停止分别使用 `/workspace/pause`、`/workspace/resume`、`/workspace/stop`。恢复维持原授权和快照，创建新session ID；停止及stdio EOF不能恢复。409和503均不触发动作自动重试。

预览还携带完整 `ApprovalBinding`：工具固定为 `agentguard-host-control/workspace_apply`，目标为原工作区，参数包含 workspace ID 与完整 Preview（含恢复目录）。启动器独立计算 ActionSnapshot 规范字节的 SHA-256，逐项核对会话、工具版本、预览正文、期限和随机值，才允许调用 apply。参数替换、错误随机值、跨会话旧预览和经 MCP 调用同名 operator 方法均有独立负例。

恢复后，工具请求的 `params._meta.agentguard_session_id` 必须携带新宿主会话 ID；缺失或旧 ID 均应拒绝，旧排队消息不能进入新会话。该 ID 是非秘密的状态标识，不授予权限。启动器更新当前 ID 后才发送新工具请求；负例直接构造缺失／旧标记请求，核对真实文件没有改变。

Preview 展示完整文件版本、创建／修改／删除、SHA、字节数和权限；二进制文件只显示摘要与大小，不能声称已逐字审阅。ApplyReport 的 `applied`、`conflict`、`partial`、`unknown` 与逐文件结果分别核对。全部请求／响应有4MiB上限。启动器会先验证控制文件不位于授权工作区、权限0600、协议版本与localhost端点；令牌与批准随机值只在内存中使用。

短预检采用 `--cycle-count 10` 或 `--soak-seconds 60`，报告会明确标记不满足100次／30分钟验收。正式命令使用 `--tasks`（50项）、`--cycles`（默认100次）与 `--soak`（默认1800秒），每次须指定同一冻结候选和独立新输出目录。T42预览正文变化后的合法拒绝可以是非200，或200加 `outcome: conflict`；两种均须核对宿主零变化，不能仅凭HTTP判成功。

执行前必须预先声明矩阵，不能提前把任何任务标记通过；交付时须分别给出同一候选的实际通过数、失败／未测项及独立输出目录。
