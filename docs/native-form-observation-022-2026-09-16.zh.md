# 固定 App 022：输入框跨应用误报修复与原生复验

日期：2026-09-16。源码基线：`5028b0757fac16cbe98221dd508f8f0d29cd2b35`。当前固定 App 为 Ver 2.1（022），原路径、Bundle ID、组织签名及工作区不变。

## 结论与原因

普通 Safari 安装说明的真实读取链路已取得证据；本轮同时复现并修复了另一个正常操作误报。021 的 AX 树把“输入框已有内容”转换为 `FormFill`，桌面壳却把它交给真实填写路径。隐私引擎将未分类的 `unknown` 键保守视作高敏感键，随后把 Finder 和 Safari 的同名键当成跨应用传输；没有值相同、来源相同或智能体实际填写的证据，仍产生 `PRIV-XAPP`。

修复只由可信原生观察器调用路径选择，不接受事件元数据自报。观察到普通输入框时记录 `UI-FIELD-OBSERVED / LogOnly`，不生成 Profile 数据来源、跨应用污点或智能体填写评分。明确隐私陷阱、非必需个人字段、文字注入、受控规则包和企业策略仍参与判断；真正的填写、网关或普通事件仍走原保护路径。共享引擎接受两种桌面平台，但本批只接线并实测 macOS，不能算 Windows 产品复验。

## 步骤与实际结果

1. 用准确 021 开始观察，打开 Finder 路径框并打开 Safari 本机合成页面 → 保留误报基线。
2. 修正可信观察入口，测试正常观察与真实填写互不污染 → 核心、桌面回归。
3. 原路径更新为 022，保留旧包归档，检查资源与签名 → 同包启动及重启核对两项权限。
4. 重复正常场景，再打开只有合成注入文字的页面 → 以真实审计、trace、界面记录核对结果。
