# 消费者化界面(E16):不许把裸术语怼给用户

产品是给人用的。这一轮改造前,界面上的真实文案是:「最近检测:`invisible_injection, prompt_injection` · 页面标题」、
「触发规则: INTEL-DOMAIN」、「转发到桌面端(Native Messaging)」、「权限引导(TCC)」、任务下拉里是
`book_hotel`、确认弹层标题「执行前拦截」而且整层硬编码中文。这些词对写代码的人是精确的,对用户是噪音。

## 改成了什么

**1. 人话词典是单一真相源**(`apps/extension-chromium/guard-strings.js`)。
每个 finding 种类、每个拦截规则 ID、每种执行前门,都映射成「人话标题 + 一句解释(+ 两个按钮各自的后果)」,
三语齐全(en / 简体 / 繁体)。popup 和页内确认层都从这里取词。技术标识(`INTEL-DOMAIN`、`payment_cta`)
只出现在可展开的「为什么被拦?」详情里,给排障和反馈留门。

**这不是文案约定,是被测试钉住的性质**(`apps/extension-chromium/scripts/strings.test.mjs`):

- content.js 源码里每个 `kind:` 字面量,词典必须有三语词条(新增检测忘配人话 → 测试红);
- guard-schema `events.rs` 里每个 `*_RULE_ID` 常量,词典必须有三语词条;
- guard-gate 会阻断的每个 kind,必须有确认层文案(标题/正文/允许后果/取消后果);
- 三个语言包键集合一致,中文包不许有未翻译的英文残留。

**2. 确认弹层(产品最重要的 10 秒)**:标题是「这一步要付款了」这样的人话;两个按钮各自写明后果;
「先不要」是视觉主按钮 + 默认焦点 + Esc(安全的选择最顺手);「允许这一次」做成红字次按钮;
语言跟随 popup 设置(此前整层硬编码中文)。

**3. popup 信息架构**:第一眼是「正在守护这个页面 · 今日:发现 X 项 · 拦截 Y 次」;最近列表人话化 + 相对时间;
拦截名单第一行是「已知的恶意网站」这样的人话,规则 ID 收进详情;语言/桌面端连接收进「设置」;
空状态从「暂无检测记录」改成解释性的「一切正常……遇到风险动作时会先拦下来问你」。

**4. 桌面壳子分层**:仿真注入、AX/SCK 探测轮询、企业策略、决策原始日志收进默认折叠的「开发者面板」;
任务下拉给人话名(「订酒店」,value 仍是 profile id);「Phase 2」副标题、「TCC」「重载 Threat Intel」
「Critical Confirm」等术语全部人话化;补齐了 zh 包里的英文残留(如 Optional PII)。

## E17:安装引导、无障碍、通知人话化

**引导页**(`onboarding.html`,首次安装自动打开,升级不打扰):三张卡讲清它保护什么,
一个交互演示让用户先见一次确认弹层——演示用的是**真渲染器 + 真词典**(guard-modal.js /
guard-strings.js),不是截图,词典改了演示自动跟上;结尾交代 popup 在哪、桌面端连接是可选的、
"发现默认留在本机"。

**弹层共享渲染器**(`guard-modal.js`,从 content.js 抽出,内容脚本与引导页演示共用):
role=alertdialog + aria-modal + 反射的 ariaLabel/ariaDescription(不用被禁的字符串属性 API);
打开焦点落「先不要」,Tab/Shift+Tab 锁在弹层内循环,Esc=先不要,关闭后焦点还原到触发元素;
深色模式自带完整色板(弹层浮在任意网页上,不能借页面的颜色)。

**通知**:标题走三语词表;正文第一眼是规则的人话名(如「付款/转账确认」),引擎消息跟在
后面,技术 ID 收进末尾括号——不再是 `[CRIT-001] …` 开头。popup 的宿主判决记录同样人话化。

## E18:复审补漏

- **徽章生命周期**:打开 popup 即清除徽章(看过了就不该继续挂着);Critical 暂停徽章「‖」例外,
  暂停没解除提醒不消失。此前 "!" 一旦点亮永远挂着,用户没有任何办法消掉。
- **壳子词表完整性测试**(`eval/shells-i18n.test.mjs`,进 `make check-shells`):键三语一致、
  index.html 的 data-i18n / main.js 的 t("...") 引用的键都存在、`action.*` 动态键四个取值齐、
  中文无英文残留。`t(缺键)` 会把 key 名渲染到界面上(E16 前 macOS 真发生过),不报错不崩溃,
  只有这类测试或肉眼能看见。已突变验证(删掉 guard.task 词条 → 两条测试红)。
- **桌面时间线人话化**:第一眼是「已拦截/提醒/已放行/已记录」而不是引擎枚举 `Block`;
  rule_id 挪进 meta 行。
- **popup 可重开引导页**(设置 → 查看功能介绍),给错过首装引导的人留门。
- **STORE.md 重写**:旧文案还在说"只有桌面端能阻断"(E2 之前的状态),且权限表漏了
  declarativeNetRequest 与 notifications 的用途说明(商店过审阻断项)。

## 阶段 B:状态灯只说真话(报告 P0-3)+ 重复观察折叠(P2-3)

真机报告的原症状:界面写着「守护中」,而那一刻 AX 轮询没开、SCK 没在采、或者审计库写不进去。
原因是壳子把 `session_active` 一个布尔直接翻成「守护中」——会话开了 ≠ 有人在看。

现在「什么叫在守护」是 `guard_core::observe_state` 里的一个纯函数,壳子只把事实喂给它:

> **守护中(active)** ⇔ 有会话 ∧ 至少一个观察器在运行 ∧ 最近一次观察在 10 秒内 ∧ 审计可写 ∧ 没有待确认 / 暂停 / 观察器报错

其余每种「不满足」对应一个状态和一组机器可读的原因码,前端查词表翻成人话列在状态灯下面:
`未在守护`(没会话)、`等你决定`、`已暂停`、`需要授权`(没有任何观察器可用)、`正在启动观察…`
(启动宽限 8 秒内还没心跳)、**`守护不完整`**(会话开着但观察器停了 / 心跳过期 / 审计写不进去 /
观察器报错——**这是以前显示成绿灯的那种情况,现在是橙的**)。审计可写性来自引擎:`Engine` 记住
最近一次审计写入失败(`audit_error`),写成功即清空——它描述「现在能不能写」,不是历史。

同一份状态机同时驱动 macOS 和 Windows 壳子;`eval/shells-i18n.test.mjs` 从 `observe_state.rs`
源码抠出全部状态和原因码,对两个壳子的三语词表逐一点名——Rust 端多加一个状态而词表没跟上,
门禁就红(已突变验证:删一个 `state.degraded` 词条 → 两条测试红)。

**重复观察折叠**:报告实测 106 秒 75 条审计记录(ScreenCapture 40、OVL-007 37)——屏幕没变,
SCK 每 1.5 秒交一帧,每帧都过引擎、都写审计。现在 SCK/AX/UIA 轮询路径上的事件先过
`guard_core::event_dedup::Aggregator`:同一语义内容(`event_type | source_app | ui_text 等规则真正读
的元数据`,每帧必变的 `frame_digest` / `low_opacity_ratio` 不进指纹)30 秒内只过引擎一次;窗口过后
仍在,放行一条并把折叠计数写进审计元数据 `repeat_count`——审计里是「这 30 秒同一画面出现了 N 次」
一行,不是 N 行。**内容变一个字就是新事件,立刻放行**;折叠只吃一字不差的重复。会话开始/结束、
演示注入、扩展转发的事件不经过它(那些本来一次一条)。状态行显示「已折叠 N 条重复观察」。
同一模块的仿真测试用报告的节奏(106 秒、1.5 s 帧 + 2.5 s AX)把 110+ 条候选压到 ≤ 8 条。

顺带修了报告第 4 条:`last_ui_event`(弹窗/TOCTOU 复验用的「上一帧」)以前是单个值且跨会话不清,
SCK 帧和 AX 快照交替到达就互相判成「UI 在决策和执行之间变了」→ UI-REVALIDATE 风暴;演示注入的
支付事件也被拿去和上一帧比,得到 UI-REVALIDATE 而不是 CRIT-001。现在**按 source_app 分开比**、
会话边界清空;会话结束同时解除 SESSION-PAUSED(它是会话级状态,消息原文就是 "Session paused")。

## 阶段 C:后台高危确认不能悄悄等着(报告 P1-4)

窗口隐藏或最小化时,以前一条高危确认只是 emit 给一个没人看的 WebView。现在:
确认到达时把主窗口拉到前面并聚焦;macOS 菜单栏图标旁显示「‖ N」,Windows 改窗口标题;
**两分钟没人拍板按「先不要」处理**并写 `Timeout` 回执(弹层里写着这句话,状态行说出发生了几次);
待确认落盘(不含观测文本摘录),重启后上次遗留的逐条写 `Timeout` 回执再清掉——重启不是静默丢弃。
超时后再点「允许」是 Stale,不放行任何东西。

没接的(如实):系统级通知(macOS 通知中心 / Windows toast)。它需要一个 Tauri 通知插件,
这个容器编不到它、也验不了它在真机上的行为;先用窗口拉前 + 托盘/标题这两条能在代码里验到的路。

## 视觉冒烟:`make ui-preview`

逻辑测试钉不住"用户实际看到什么",所以有一个真渲染 harness(`eval/ui-preview/`):
无头 Chromium 渲染确认弹层(付款拦截 / 越界)与 popup(有数据 / 空 / 英文 / 设置态),
截图落在 `eval/ui-preview/out/`(gitignore,改 UI 后跑一遍肉眼对比),同时做行为断言:
「先不要」真的挡住页面处理器、「允许这一次」真的重放动作、popup **可见**文本无裸术语
(`innerText` 尊重可见性——details 折叠时技术标识必须不可见,展开后必须可见)。
断言经突变验证:让 popup 泄漏一个裸 kind,两条断言立刻红。

它是**开发工具,不进 release-gate**:门禁必须在最小容器可复现,这个需要 playwright + Chromium。
真机验收(`acceptance-runbook.md`)才是发布证据。

## 边界(不假装)

- 词典的覆盖率测试靠**源码字面量提取**(正则找 `kind: "..."` / `*_RULE_ID = "..."`),不是类型系统。
  动态拼出来的 kind 它看不见——目前仓库里没有,新增时提取正则要跟着看一眼。
- popup 的「今日发现/拦截」计数来自最近列表缓冲(有条数上限),是"今天界面上看到的",不是审计库统计。
- 桌面壳子的判决日志(开发者面板里)仍显示原始 `action [RULE-ID] message`——那是给开发者的,刻意保留。
- 三语文案的**质量**(翻译地道与否)测试保证不了,测试只保证"有、齐、是中文/非裸术语"。
- 状态机的**输入**在壳子里采集(心跳原子量、观察器标志、引擎 `audit_error`),那部分只能在
  真机上跑到:Linux 容器能编译两个壳子并跑它们的单元测试,但 `#[cfg(windows)]` 的 UIA 轮询体
  和 macOS 的真 AX/SCK 回调不在其中。Windows 壳子把聚合/心跳逻辑抽成了平台无关函数并有测试,
  `cfg(windows)` 里只剩一行调用;macOS 的两条轮询路径没有这层抽取(它们本身在 Linux 上可编译)。
  「状态灯在真机上确实随观察器启停变色」的最终判定是真机验收(`acceptance-macos.md` /
  `acceptance-windows.md`),不是这里的测试。
- 折叠只在观察器轮询路径生效;「重复观察结束」的恢复摘要只进开发者日志,**不进审计**——
  审计里的持续摘要是带 `repeat_count` 的周期行。
