## 测试发现并修复的问题

最初只处理普通页面请求时，后台 Worker 不进入相同网络拦截。固定版 Playwright 的 Worker 网络观测需显式启用；现在按真实 Worker 请求来源拒绝，不以覆盖 `navigator.serviceWorker.register` 冒充完整拦截。回归直接调用其原型方法，验证注册脚本与后台提交均未到达服务器。

扩展还曾因 headless shell 没有加载、启动时 API 尚未就绪导致验收失败；已固定完整 Chromium 可执行文件，并等待真实扩展运行状态。没有把这些失败改成跳过。

## 继续执行：崩溃故障注入与客户端接入

发现真实缺陷：执行器被 SIGKILL 后，调试连接释放暂停中的请求，本机服务器实际收到 1 条未批准 POST。现已改为浏览器默认走拒绝代理、检查后由独立通道转发，并增加独立清理守护进程。修复后的故障注入验证为 0 条提交、控制服务不可达、临时凭据及浏览器目录删除。另验证移除拦截后原始浏览器仍无法直连本机业务服务器；这不代表所有非 HTTP 出口或系统进程已隔离。

转发回归验证两个 Set-Cookie 正常进入浏览器，其中 HttpOnly 保留；后续请求携带浏览器 Cookie；删除浏览器 Cookie 后，独立通道不复用历史 Cookie。原有人工批准、拒绝、Worker、重定向和 UI 操作回归全部通过。

真实客户端：本机 Codex CLI 0.139.0 使用临时工作目录、忽略用户配置，关闭其他工具，仅连接本机无害站点。工具已发现，但导航和状态均返回 `user cancelled MCP tool call`，未读到页面、未填写或点击。配置本次进程的非交互批准策略后仍出现同一结果，取消来源尚未确定。该部分为 **未通过**，不能以服务器 0 提交或 CLI 退出 0 冒充成功。已留下 `codex-client-check.mjs`，必须实际完成五种工具调用才判通过；失败会非零退出。此测试依赖本机登录和模型调用，因此未放入无账号 CI。
