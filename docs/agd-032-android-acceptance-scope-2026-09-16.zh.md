# AGD-032 前置：Android 开发复验与正式验收边界

日期：2026-09-16。源码基线：`7b4b26bf07b72809eb28e866b59c4273efad998a`。**已修正旧脚本可能把 Debug 中继检查写成通用验收通过的问题；正式 Android A1–A4 仍未通过。** 本批未操作真实设备，没有更改 Release 能力或发布要求。

## 发现的问题

现有 Release 通过 `EXPERIMENTAL_RELAY_ENABLED=false` 关闭 Relay v1，因为返回判决尚未认证。正式发布要求仍包含设备事件、桌面验签与判决回传的 A1–A4；因此签名文件和设备齐备也不足以完成这组验收。

旧 `android-e2e.sh` 却默认构建／安装 Debug 包，所有检查通过时输出 `AGENTGUARD_ANDROID_E2E=PASS`。此外，它先截断已有结果文件；即便没有设备、尚未创建任何端口转发，退出清理也会尝试移除 8788／8790 的转发。这些行为可能混淆候选性质或破坏此前证据和环境。

本机还确认两个可执行问题：`date +%s%3N` 返回带 `3N` 的字符串，无法作为后续 Python 的毫秒整数；目标 SDK 检查仍允许 35，与当前候选 36 不一致。旧脚本及对照结果完整保留。

## 修正

- 默认调用在查询设备前返回正式 `BLOCKED`。开发中继复验须显式选择 `--development-relay` 并指定新证据目录；目录已存在时立即退出，不清空或删除原记录。
- 开发结果使用 `AGENTGUARD_ANDROID_RELAY_DEV`，保留真实设备／模拟器区分；即使开发检查通过，正式标识仍为 `AGENTGUARD_ANDROID_E2E=BLOCKED scope=release`。三语手册同步说明原 A1–A4 的未完成代码条件。
- 仅清理由本轮成功建立的转发；建立前发现对应端口已有映射即停止。新证据目录使用仅当前用户可访问的权限。
- 使用已有 Python 依赖生成整数毫秒时间；从已安装 APK 读取的目标 SDK 必须达到 36，设备 API ≥ 35 的独立条件保持。

这些修改没有实现响应认证，没有使 Release 开启中继，也没有把原正式要求缩减为 Debug 或本地提醒验收。

## 验证

Debug／Release 各 15 套、91 项测试通过，均为 0 失败、0 跳过；两套 lint 各 0 个问题。Gradle 已将 shell 脚本纳入测试输入，最终复验中两套测试实际重跑。新增测试实际执行 shell 入口或脚本中的结果汇总函数，覆盖默认拒绝、旧目录保护、无设备时不清理转发，以及成功／阻塞／失败的开发结果不能产生正式 PASS。

独立替身检查对照旧／新脚本：旧脚本截断合成历史记录并调用两次转发移除，修正后原记录不变且无 adb 调用；旧汇总函数输出正式 PASS，修正后只输出开发 PASS 与正式 BLOCKED。SDK 35 在旧检查通过、新检查失败；SDK 36／设备 API 34 仍受阻，SDK 36／API 37 的合成输入可通过开发条件。旧时间值非数字，新值为整数毫秒。

另以替身在线设备执行修正脚本前半流程，已有 8788 映射时停止；没有改写或删除映射，没有启动桌面 API。所有替身 adb 均位于临时目录，未连接真实设备；本批不计 Android 原生或端到端通过。原 Debug APK 的 SHA-256 仍为 `05495b0373b0119df3ef50479e781381e013dabee2f11aefc81fcc079e877dcc`，未重建。

原脚本、当前源码、报告、替身对照和输出位于 `.artifacts/android-acceptance-scope-2026-09-16/`，公开摘要见[证据索引](evidence/android-acceptance-scope-2026-09-16.json)。此前[本地候选准备](agd-032-android-local-preparation-2026-09-16.zh.md)的 Release 签名失败、设备用途待确认，以及 AGD-027 性能失败、F13 暂缓、28／1／1／2 任务计数和发布 No-Go 均保持。
