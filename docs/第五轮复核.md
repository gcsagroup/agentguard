## 一、守卫自己会崩,或者自己会静默

### 1. `mask_credentials` 混用两个坐标系:panic + 静默泄漏 + O(n²)

一个函数同时错了三件事,根因是同一处:它在小写副本 `hay` 上找关键字,却把得到的偏移当作
**原串 `s`** 的偏移用。`str::to_lowercase` 不保长度 —— 27 个码位会变宽或变窄。

* **panic**:偏移前移时切在多字节字符中间。`log_safe("Ktoken")` —— 六个字符 —— 就够了。
  触发字符不是生僻货:`İ` 是土耳其语高频字母(`İletişim`、`İstanbul`),`K`(KELVIN)、
  `Å`(ANGSTROM)、`Ω`(OHM)是正常单位符号,`ẞ` 是德语大写 ß。随机对抗语料里
  **5.96% 的输入 panic**。而这条路在 `Engine::process_gated` 里,整个 workspace 没有一处
  `catch_unwind` —— panic 一路 unwind 出守卫的事件循环。
* **静默泄漏**:偏移后移足够多时 `end == v`,替换被跳过,凭据**一个字节都没变**地留在输出里。
  redactor 报告成功并泄漏。
* **O(n²)**:小写副本在循环**内**重建,`format!` 每次重建整串。100 KiB 的 `token=a `
  走一次 `process_gated` 要 **8.3 秒**。

修法是让它只有一个坐标系:关键字全是 ASCII,所以直接在原串上做大小写不敏感的**字节**比较。
而因为 ASCII 字节永远不会出现在多字节 UTF-8 序列内部,**每个偏移都天然是字符边界** ——
不需要任何 `is_char_boundary` 守卫,因为一个都不需要。

修复后:128 KiB 从 14.23 秒降到 4.6 毫秒(约 3000 倍),20 万条随机串 0 panic、0 泄漏,
而且 `log_safe(log_safe(x)) == log_safe(x)` 从"20 万条里 12 条不成立"变成 0 条 ——
顺带修好了 `confirm.rs` 依赖的那个幂等性假设。

### 2. 一次被批准的 `run_shell` 就能让整个网关 panic 退出

`detail.truncate(MAX_OUTPUT_BYTES)` 在非字符边界上截断会 panic,而网关主循环**就是**
`main`。65519 字节 ASCII stdout + 16 字节 stderr 头 = 65535,stderr 首字符是 3 字节 UTF-8,
第 65536 字节落在字符内部。差一个字节就正常。

零人工交互即可达:只要部署声明了 paths 天花板(即推荐配置),`ceiling_authorises` 事前
授权掉 `SHELL-CONFIRM`。智能体连响应都收不到,网关消失。而非 ASCII 输出对本项目是常态 ——
规则、日志、报错本身都是中文。同一个文件里 `ReadFile` 那条路一直是对的(先切字节再
`from_utf8_lossy`),只有这条不是。

### 3. 三处手写的拒绝服务

| 位置 | 实测 | 原因 |
|---|---|---|
| `entity::scan_api_secrets` | 400 KiB 的 `AKIA` → `Engine::process` **31.6 秒**(基线的 2750 倍) | `run` 在 `anchored` 判定**之前**就扫到字符串末尾,而这些工作全部白做 |
| `TaintLattice::derive` | 256k 父节点(1.9 MB body)→ 引擎互斥锁被握 **61 秒** | `Vec::contains` 在父节点循环里去重 |
| `canonicalize_existing_prefix` | 1 MB 操作数 → `evaluate` **26.4 秒** | 每轮弹掉一个分量再对整条路径重做 `canonicalize` |

三处的模块文档都写着"单遍线性,因为手写的 DoS 不比正则 DoS 好"。都不成立。

`derive` 那一条顺带引出一个判断:超量父节点**拒绝**而不是截断 —— 丢掉多余的父节点会丢掉
它们的污点,那是不安全方向,一个值会比它的输入更干净。

### 4. 网关在输出超过管道容量时死锁 30 秒,然后把成功报成失败

先在 `try_wait()` 上轮询等子进程退出,退出之后才读管道。写满 64 KiB 的子进程阻塞在 write
上、永不退出,于是必然走到 30 秒超时被杀。60000 字节 → 2.8ms/ok;70000 字节 → **30.008
秒**/失败。三个后果:成功的命令被错报成失败;`MAX_OUTPUT_BYTES` 这条"输出上限"在 stdout
路上根本到不了(死锁先发生,文档承诺的截断保护是空的);而执行是同步单线程的,所以一次
调用把**全部**判决停住 30 秒。

## 二、守卫被静默地关掉

### 5. `guard-nm-host`:五个静默的 fail-open,而这个文件有 0 个测试

它是一条信任边界 —— stdin 上的一切来自浏览器扩展,威胁模型是被攻陷的扩展或任何能启动这个
二进制的本地进程。218 行,零测试。

**(a) 一个不认识的事件类型吃掉整批。** 适配器遇到第一个未知 `type` 就 `bail!` 掉整个信封,
而 host 用 `unwrap_or_default()` 把它变成空列表,判成 ping,回 `ok:true, processed:0`。
5 个 `Confirm Payment` 加末尾一个 `{"type":"click"}` → `decisions: []`,stderr 空,审计零行。

两个独立触发源,而**第二个不需要攻击者**:一个诚实的扩展新增了一种事件类型,旧 host 就把
含新类型的每一批全部静默停判。这是个 fail-open 的向前兼容陷阱。

**(b) `AGENTGUARD_RULES` 指向 `rules: []` = 批准一切。** rc=0,stderr 一个字都没有,
付款/转账/永久删除/安装全部 `ALLOW`。而这个 host —— 不像 CLI、本地 API 和网关 ——
从来没有在任何地方报出 `rules_loaded`,所以下游没有任何东西能发现。

**(c) 规则回落路径是 CWD 相对的。** 最后一跳是
`PathBuf::from("crates/guard-schema/rules/p0_rules.yaml")`。在发布二进制上(编译期的
`CARGO_MANIFEST_DIR` 已不存在)这让生效的规则集成了进程工作目录的函数 —— 而工作目录是
Chrome 选的。能在那个目录下建出一棵子树的人就换掉了策略,不需要提权。

**(d) `AGENTGUARD_*` 指向不存在的文件 → 静默停用那一整层。** 而"文件存在但解析失败"
**有**警告 —— 也就是说警告恰好覆盖了较难发生的那一种,漏掉了打错路径。讽刺的是
`known_apps_path` 上方的注释正好写了这件事:"It is loaded anyway because *not* loading it
silently disabled the allow-list entirely" —— env 分支把它又引了回来。

**(e) 四个零字节终止进程。** `len = 0` → `read_message` 返回 `Err` → `?` 抛出主循环。
畸形帧**之后**的每个事件都不再被判,而且协议层错误连一条错误响应都发不出去 ——
因为 `HostResponse.error` 只包住了 payload 那一段。相关的不对称:截断的 4 字节长度前缀被当成
**干净的流结束**,而截断的 body 是硬错误 —— host 分不清"扩展正常关闭"和"扩展被中途切断"。

**(f) 审计库默认落在世界可写的 `/tmp` 的可预测名字上。** 预置一个符号链接就把整条审计
(含完整 `event_json`,里面有带 session token 的 URL)重定向到攻击者选定且可读的位置;
预置一个目录或垃圾字节让 host 起不来 —— 方向上 fail-closed,但因为 sticky 位,受害者
**自己删不掉**攻击者创建的那个条目,需要 root。一个无特权本地进程就能永久关掉守卫。

这一条现在有 15 个测试,包括每一条帧解析错误分支、"送进 K 个事件必须得到 K 个结论"、
以及"0 条规则必须拒绝启动"。

### 6. 确认闸门可以被任意网页批准,而且批准不绑定到人看到的那次请求

文档把这里的威胁模型写反了:"只绑 127.0.0.1 —— 一个能远程批准动作的端口就是把闸门送给
网络"。绑 127.0.0.1 挡的是**网络**,挡不住**浏览器里的页面** —— 而页面正是本产品的威胁
模型主体。

三个缺陷串成一条完整绕过:

* **无认证、无 Origin 校验。** 一个隐藏的自动提交 HTML form 发出的逐字节合法
  `POST /approve`(简单请求,不触发预检)批准掉了一次 `delete_file`,文件真的被删了。
  `GET /pending` 同样无凭据可读,泄漏待确认命令的全文和判据。
* **批准不带请求 id。** `ConfirmRequest` 有 `id`、`/pending` 也返回了 —— 只是没人核对。
  配合"超时按拒绝",一个读得慢一点的操作员就够了:屏幕显示 `confirm-1`(`echo harmless`),
  它超时消失,`confirm-2`(`delete important.txt`)挂上来,操作员在显示着第一条的界面上
  点了批准,被删的是第二条的目标。**人以为自己在批准 A,系统执行的是 B。**
* **`require_confirm` 短路掉 `Block`。** `judge()` 在 `match decision.action` **之前**就为
  `require_confirm` 早退,而 p0_rules 里 CRIT-001..005 **全部**是 `block` + `require_confirm`。
  于是每一条 Critical 的 block 规则都变成"可批准"。

修法:启动时生成的 bearer 令牌(只打到 stderr)+ 拒绝任何带跨站标记的请求 + 批准必须带上
`/pending` 给出的 id;而 `Block` 移到 `require_confirm` 之前 —— block 的意思就是 block,
把已经判定不可以的动作拿去问人,只是把判决权交还给最想要它的那一方。

## 三、判决被悄悄降级

### 7. 一个不可见字符让 `FW-BREAKOUT` 整条静默

归一化器的不可见字符集是 `anomaly::is_invisible` 的**真子集**,而还有第三个集合两边都没有。
插一个这样的字符,三类越界全部绕过,**而且连 Low 的文本异常告警都不产生** —— 事件是完全
干净的,不是"没那么响"。

`U+200E`/`U+200F` 最尖锐:`docs/text-anomalies.md` **刻意**把它们排除在 `invisible_text`
之外("每个阿拉伯语和希伯来语界面里都有"),而归一化器里也没有 —— **两处刻意的排除组合
成了一个洞**。穷举全部 1,114,112 个码位表明绕过集合不是几个生僻字符,而是那九个硬编码之外
的**每一个** default-ignorable 格式字符。

同一个函数里第二个独立绕过:实体解码只认 `&lt;` `&gt;` `&#124;` `&verbar;` 四个固定串,
标准数字形式 `&#60;` `&#x3c;` `&#91;` 直接走过。解码这件事本来就是因为"预期会收到转义
文本"才存在的,四条的清单是那个缺陷的不完整版。

修法:按**属性**剥离(default-ignorable + 组合记号),而不是按枚举;字符引用做通用解码。

### 8. 文本异常的闩锁被一个常驻的类吃掉其余类

`worst_anomaly()` 取最高排名的那一类再看是否已闩,从不看同一事件里的其他类。于是每个屏幕上
都有的一个零宽空格,让 `bidi_override`、`homoglyph`、`glitch_token` 在**整个会话**里不可
报告。一个带 Trojan-Source 覆写**和**西里尔同形异义 "Confirm payment" 的屏幕,引擎一句话
都没说;而同样的载荷去掉那个零宽空格,两条都报。

这和 `docs/text-anomalies.md` 记为已修的那个形状("一条 finding 不能抹掉另一条")是同一个,
只是这次是通过闩锁而不是通过合并。

### 9. `PRIV-XAPP` 对信用卡号/社保号/病历号从不生效

污点标记这条路用 `contract.tier_for_key`,而那个函数自己的文档就写着它"在不安全的方向上是
错的";fail-closed 的 `flow_tier_for_key` 当时只用在了 flow 那条路上。默认 `high_keys` 只有
七项 —— `payment_info` 在里面而 `credit_card_number` 不在,只是命名的偶然。

在 `Booking` 里填一张信用卡号,再在 `RandomSMSApp` 里填同一个键 → `Allow`,没有告警,
审计里没有 finding。而 `docs/information-flow.md` 点名的正是这三个键。

**这一条的修法我走错了一次,值得记下来。** 我先把两条路一起改成 fail-closed —— 结果
`insurance_op_001`(一个刻意合规的基线场景,存在的理由就是"守卫必须保持安静")立刻多出一条
`PRIV-OP:Block` 误报。两条路的问题不一样:

* 跨应用支点是**信息流**判决 —— 数据已经被收集、正流向第二个应用,证明不了就不能放行,
  fail-closed 是对的;
* `PRIV-OP` 问的是"智能体请求了一个 HIGH 档的键吗" —— 对未分类的键,答案是"不知道"而不是
  "是"。契约自己的文档就写着这一点:"论文的模型只有两档,一个未列出的字段不是过度收集的
  证据"。

真正的缺陷不在函数选择,而在**那张表只有七项**。补上那三个键,复核点名的三个键现在得到
确认提示,而未知的键不制造噪声。

### 10. 智能体自己签发"用户批准过这次记忆保存"

`approved = matches!(action, Allow) || metadata["user_approved"] == "true"`。这是同一个形状
**第三次**出现(前两次:`sink_clearance`,以及 `declassify` 上的 `approved`/`approved_by`):
**一个授权,从它所授权的那条通道里读出来。**

后果是完整的:`has_saved` 报告这个键在"用户控制的"记忆里 → `decide_memory_read` 返回
`Allow` 而不是 `PRIV-MEM-READ` → 同时 `score_memory_use` 把这个轴打成 1.0。智能体既关掉了
针对幻觉/过期记忆的检查,又给自己打了满分 —— **而那次写本身是被 Block 的**。

修法和 `apply_pending_declassify` 同一个形状:留一个待定,只有 `process_gated` 里
`ApproveOnce` 那一支能兑现它。

而修掉引擎之后,**三个评测场景和 leaderboard 的合成事件立刻变红** —— 因为它们都用
`user_approved: "true"` 来表达"用户批准过",也就是评测集在**测量一条现在已经关掉的绕过
路径**。场景格式因此新增了一个逐事件的 `confirm: approve`,走真的闸门。

顺带发现:`memory_pair_correct_use_001` 没写 `kind`,默认成了 `attack`,而它"通过"只是因为
那次本该被批准的保存被拦了下来 —— 一次偶然的通过。现在标成 `benign`。

## 四、脱敏:识别不到,或者识别到了没遮

### 12. 句尾一个句号,PAN 就明文进签名审计并流向公网

`scan_digit_runs` 把 `.` 同时当作左右边界的排除条件,只认 `' '`/`'-'` 两种分隔符、
只认 ASCII 数字。于是这些**自然文本**里的卡号一个都识别不出来:

```text
found    "Saved card 4242424242424242"     -> ["payment_card"]
MISSED   "Saved card 4242424242424242."    -> []      句尾句号
MISSED   "Card ending 4242424242424242. Thank you." -> []
MISSED   "4242.4242.4242.4242"             -> []
MISSED   NBSP / 零宽 / 软连字符 分隔        -> []
MISSED   全角身份证号                       -> []
found    "Saved card 4242424242424242,"    -> ["payment_card"]   逗号可以,句号不行
```

最刺眼的是最后两行的对比 —— 那个差别没有任何理由。

后果是两条,都完整:`verified_fields` 为空 → `redact_event_for_audit` 返回 `None` →
**完整 PAN 原样写进 `AuditRecord::event_json`**(哈希链内、签名内、可导出);
同时 `confidentiality()` 为 `None` → 标签停在 Public → `data_flow` 到公网 sink 判 `Allow`
而不是 `FLOW-CONF/Block`。复核跑的九个变体里八个被放行到公网 sink。

而其中软连字符、点分隔、全角数字、句尾句号**连一条补偿性的文本异常告警都没有**。

### 13. "已核验但没被遮蔽":审计行报告已脱敏,存下的是完整 IBAN

识别器和遮蔽器是两个独立实现,各自对"一段值从哪到哪"有一套猜法。`scan_iban` 的分组路径把
连续 alnum token 拼起来、完全不看中间是什么;遮蔽器只认连续 token。于是逗号/斜杠/换行/点/
NBSP 分组的 IBAN 被判 `verified: true`(调用方据此认为该字段已送去遮蔽),而遮蔽器一个字符
都不改。

这正是模块文档说上一轮已经修掉的失败模式,换了一种分隔符又复现了一次 —— 因为两个独立实现
在猜同一件事。

修法是让它们共用 `normalise_for_scan`(带回原文的索引映射)和 `RUN_SEPARATORS`,并把
**"识别到的一定被遮到"钉成一条测试性质**,而不是钉几个例子。

### 14. 显示路径的三类豁免都是无边界后缀匹配

`Total 4242424242424242` 原文进日志。货币豁免用 `trimmed.ends_with(c)` 且没有任何词边界
检查(而同一个函数里 bookkeeping 分支**有**),`CURRENCY_PREFIXES` 里又有 `rp`,于是任何
以 rp 结尾的词都豁免一个 16 位 PAN。复核穷举出 24 个货币前缀、16 个 bookkeeping 前缀、
11 个单位后缀,全部命中 —— 包括 `Total`/`Subtotal`/`Grand total`(结账屏最常见的词)、
`Size`/`Count`/`Limit`(最常见的字段名)。

给货币和单位加词边界修掉了大部分,但 `Total` 修不掉 —— `"total"` 就在那张表里,而那里
确实是一个完整的词。真正的判据是号码本身:**一笔总额是一串数字,一个 PAN 是一串同时满足
Luhn 和发行商前缀的数字。** 所以校验和胜过一切豁免,而豁免继续保护
`timestamp_ms=1786508766171` 和 `evidence_ref` 的可读性。

### 15. 脱敏保留了信息量最大的那一段

* **SSN**:`•••-••-{serial}` 完整保留 4 位 serial,遮掉的 area+group 恰恰是**可枚举**的
  部分(约 7.1 万候选,知道出生州只剩几百)。也就是遮蔽把唯一不可枚举的四位留在了日志里。
  现在反过来。
* **身份证**:保留前 4 位(省市行政区划码 —— "在哪里登记的")和末 2 位(性别位 + 校验位,
  而校验位是其余 17 位的函数,等于白送一个约束)。现在都不留。
* **长度**:`•` 的数量是"一个字符一个",**精确暴露原值长度** —— 而长度对小空间的值是很强
  的约束。`scan_api_secrets` 一开始就避开了这一点(它的注释写着"一个 secret 的长度是关于
  这个 secret 的信息"),其他类没跟上。现在固定四个。

### 16. 32% 的数字表格产出"已核验"的假卡号

`card_group_shape` 被文档描述成"防止长数字表变成一串 verified 卡号",实测没有做到:
一排 4 位分组里每个起点都产出一个候选窗口,每窗口约 2.36%,20 组一行有 17 个窗口 →
`1-(1-0.0236)^17 = 32%`,与实测的 32.2% 吻合。是设计的必然结果。

而 `verified: true` 会(a)让 `redact_event_for_audit` 改写该字段,(b)把 taint 抬到 High
→ 下一次 egress 被 `FLOW-CONF` **阻断**。也就是误报会变成阻断,不只是噪声。

我第一次的修法(数候选个数)只把 32% 降到 24% —— 因为 20 组的一行里往往**恰好只有一个**
窗口通过。分组数才是"这是不是一张表"的直接证据:真实卡号最多五组。

### 17. `classify_field`:空标签被判成隐私陷阱

`label_match` 是 `norm.contains(&p) || p.contains(norm)`,而 `p.contains("")` 恒真。
于是**任何空标签或纯空白标签**命中 `trap_labels` 的第一项,单字符标签命中任何含该字符的
pattern。而 `classify_field` 是 `guard-vision` 对每一个观察到的表单控件调用的,AX 树里
无标签节点非常常见 —— 每个都被记成一次隐私陷阱观测,直接污染 TR 维度评分。

顺带:`normalize` 只做 `trim().to_lowercase()`,没有全角折叠,于是 CJK 界面常见的全角标签
直接落到 `"unknown"`。

## 五、文档说的是假话

`docs/safe-shell.md` 开头那段警告写着"没有路径模型、没有 realpath 归约、没有 `..` 检查,
而且 `find <project> -delete` 和 `find / -delete` 判决相同"。**四句全部与代码相反** ——
`check_paths` 就是路径模型,而 `b0_四种删除必须分开` 这个测试模块存在的唯一理由就是断言
那两条命令不同。

复核把这一条单列为缺陷,理由是对的:部署方用这份文档决定"能依赖什么"。低报保证会让人白装
一层 OS 沙箱(无害),但**完全没写天花板机制**是有害的 —— 网关的 `ceiling_authorises` 会
把 `Ask` 变成免确认执行,而读文档的人不可能知道声明 `scope.paths` 会**减少**人工确认。

这一轮里三个可达的绕过(操作数携带整条命令、`--flag=PATH` 隐藏写目标、悬空符号链接),
最后一步全都是这一条。文档已重写。

## 六、`guard-shell` 的路径模型:证明可以被伪造、隐藏、跳过、掀翻

元字符筛子本身**忠实实现了它声称的那张清单**,三条核心承诺都成立(先于白名单、`argv()` 在
Deny 时为 `None`、`shell_quote` 在 36 条语料上逐条回读正确)。绕过点全在路径模型:它把
"能不能归约成一条落在天花板内的路径"当成安全证明。

| 手法 | 实测 |
|---|---|
| **伪造** | `sh -c "rm -rf /"` 里那条命令被归约成 `<cwd>/rm -rf`,判成"在写授权内" → `Deny` 降成 `Ask` → 被天花板预授权成直接执行。文件真的被删,一次都没问人。审计记的路径是 `<cwd>/rm -rf <目录>` —— 一个永远不会被碰的路径。不是 `sh` 特有的,`python3 -c` 走同一条路 |
| **隐藏** | `cp --target-directory=/etc/cron.d SRC` 的写目标从判决里整个消失(`looks_like_path` 对任何 `-` 开头的操作数返回 false),只剩来源被判,而来源在天花板内 |
| **跳过(读侧)** | 三步检查里第一步要求 `resolved` 是 `Some`,第二三步只对写生效。于是"归约失败 + Read"三步全跳过 = 干净的 `Allow`,而加一个通配符就让归约失败:`~/.ssh/*`、`~root/.ssh/id_rsa`、`/home/*/.ssh/id_rsa`。这两个构造在真实 shell 里确实读得到私钥 |
| **跳过(意图)** | `target`(argv[1])不进意图推断,所以 `sudo rm -rf X` 的 `rm` 不可见 → 判成 Read → 越界检查不跑。`timeout 5 rm …` 反而正确,因为那时 `rm` 落在 `args` 里 —— 这一格恰好证明差别的来源 |
| **掀翻** | 悬空符号链接:`canonicalize` 对整条路径失败 → 退回词法处理 → 判在天花板内,而写它会顺着链接把天花板外那个文件**创建出来**。目标已存在的链接被正确解开 —— 所以不是"没处理",是**只处理了一半**,而漏掉的那一半正好是可种植的那一半 |

另外两条:`&` 的 URL 豁免只做前缀匹配,于是 `https://ok.everything/x& rm -rf ~` 得到 `Allow`
(把 `;` 换成 `&`,而文档自己的例子里 `;` 是被拒的);策略里的大写条目静默失效,而四个集合里
唯一做了归一化的是唯一**授予豁免**的那个。

修法过程中我自己引进了两个缺陷,都被测试抓住:把 `target` 加进意图 haystack 让一个 1 MB
操作数要被所有关键词各扫一遍(微秒 → 1.77 秒);而"归约不出来的读判 Ask"让 URL 变成误报 ——
后者暴露出一个更根本的分类错误:**URL 压根不该产生 path claim**,而假装这一层能对 URL 说话,
正是伪造包含性证明的同一种毛病。

### 五轮下来的一个规律

五个独立复核,五次都在我"写完修复 + 写完测试 + 跑完变异测试"之后还找到东西。而这一轮最值得
记的不是某一条缺陷,是**三处"两个刻意的正确决定组合成一个洞"**:

* `docs/text-anomalies.md` 刻意不把 `U+200E` 算作 `invisible_text`(理由正当:每个阿拉伯语
  界面里都有),而归一化器刻意只列九个码位(理由正当:线性、无分配)—— 组合起来,一个
  不可见字符让整个越界检测静默;
* `tier_for_key` 刻意把未列出的键当 Low(理由正当:论文模型只有两档),而 `high_keys` 刻意
  只列七项(理由正当:那是论文的列表)—— 组合起来,信用卡号的跨应用支点从不触发;
* `logsafe` 刻意豁免 `total` 让金额可读(理由正当),而 `CURRENCY_PREFIXES` 刻意包含短前缀
  `rp`(理由正当:印尼卢比)—— 组合起来,结账屏上的卡号原文进日志。

三处都不是"某个人写错了"。每一个决定单独看都有据可依,而洞出现在**它们之间**。这类缺陷
不会被"审查这个函数"找到,只会被"拿一个真实输入端到端跑一遍"找到 —— 这也是这一轮四份报告
都被要求跑出证据而不是读出结论的原因。
