# AGD-017 有限远程 MCP 产品接线与联合验收

日期：2026-09-15。状态：AGD-017 按开发计划的限定范围完成。生产 CLI 同时接入一个本地 stdio 服务和一个明确为 MCP 2025-06-18 的远程 HTTPS 测试服务，登记、逐次批准、来源和持久恢复已接通；33 项联合实操及原本地 21 项回归通过。F13 仍暂缓未验收，完整 M1、32 项计划和发布均未完成。

## 实际行为

宿主通过原有 `--mcp-service-config` 配置服务。版本 1 配置增加 `remote_services`，原 `services` 保持兼容；两类合计最多 4 个，服务 ID 和名称空间不能冲突。仍要求受控隔离后端、持久审计及可信会话绑定。手工登记清单不能创建网络派发入口。

远程配置提供 `service_id`、`namespace`、准确 HTTPS `url`、固定 IPv4 `address`、`ca_der_path`、`issuer`、Base64url Ed25519 `issuer_public_key` 和 `credentials_path`。默认使用公网地址规则；仅自有测试可显式设置 `loopback_test: true`，此时主机限于准确 `localhost` 或 `mcp.localhost`，地址必须为 `127.0.0.1`。任务计划的主机规则没有放宽，联合夹具使用合法的 `mcp.localhost` 授权。

凭据文件只接受 `discovery_token` 与 `call_token`：前者精确包含 `mcp:discover`，后者精确包含 `mcp:discover mcp:call`。全部配置、签名、受众、范围和时间先验证，再开始任何服务发现。CA 和凭据必须由当前用户持有，位于任务授权目录之外，拒绝符号链接、硬链接、特殊文件和超限；凭据不得对组或其它用户开放权限。读取后固定在宿主内存中，更新文件不会悄悄替换当前调用身份。

实际初始化与清单进入登记。宿主展示 URL、固定地址、CA／签发公钥摘要和范围，**连接配置摘要不代表远端程序代码摘要**，明确保留 `remote_code_attested=false`。首次认可只允许发布工具；每次调用仍绑定完整参数、连接身份、调用凭据摘要、工具代次、会话及来源，独立批准后才建立调用连接。启动时的发现只使用发现令牌。

远程动作使用网络事件判决，核查真实目标主机、网络预算和硬拒绝规则；规则拒绝不会变成待批准。既有计划的预算超限行为仍由宿主契约决定，本轮没有将默认告警策略改为硬阻断。参数及输出与本地服务共用 JSON Schema 校验，不能借参数添加网络目标。

批准后的初始化、通知、清单和调用共享 30 秒总时限。真实调用前再次比对完整清单，变化即撤销旧认可，不发送工具调用；此前初始化仍可能产生副作用，因此保留未知边界。实际 connect 和每次 TLS 写入继续与撤权共用派发锁。

整个下游 JSON 先进入来源检测，再加入宿主回执；下游伪造 `_meta.agentguard` 只能作为数据保存。传到下一工具的实际内容保留来源，隔离副本的变化仍需独立预览和批准才回写宿主。

已派发后断连、超时、取消或无效返回均记未知、暂停、不重发。关闭本地通道不能证明远端停止。真实崩溃重启使用原持久执行日志，把没有终态的同一动作恢复为未知，不尝试重放或清理远端资源。开始审计失败时零远程请求，并禁止后续动作。

## 联合实操与独立核账

最终固定候选为 `.artifacts/m2-remote-product-2026-09-15/candidate-03/agentguard-mcp`，SHA-256 为 `0e0a33d77ea01c90f499b0a5d672b91e1218b612879d81b7a735b6c72ecf6d28`。最终 `runtime-05` 和本地回归均使用该副本，不与测试后重新链接的默认目标混用。

复用既有 Node 22 Docker 镜像及冻结的官方 Filesystem 2026.8.31 包；未新增镜像或卷。远程端为自有 Node HTTPS 独立实现，服务端实际核验签名、受众、期限和范围。联合过程实际完成：本地工具读取合成文件 → 用其真实返回值作为参数，经批准写入远端文件 → 远程工具通过 SSE 读回 → 将其返回值写入本地隔离副本 → 独立预览批准后宿主原件读回。

最终 33 项检查包括：五种坏令牌配置零请求、仅发现权限启动、未认可不公开和不派发、完整批准及独立拒绝、两端文件往返、下游元数据隔离、断连后已写入效果的独立批准读回、错误输出定义、重定向拒绝、暂停与迟到批准、清单变化、真实 SIGKILL 重启、真实 30 秒总时限及开始审计失败。实测总时限为 **30,067 ms**。远端在本地暂停之后继续完成的负例也已实证，未写成“远端停止成功”。

独立 Python 核账重新读取实际文件和服务端流水，而非仅信任检查名：51 个经服务端验签的请求、8 条效果记录与报告一致；完整 17 个公开工具定义、清单及连接身份摘要重算一致；输出来源摘要与持久记录一致。联合执行／登记／来源审计分别 **65／12／11 条**，旧本地回归分别 **38／11／6 条**，共 **143 条**全部逐项验链；审计中不含已检查的合成正文、路径或令牌原文。

这些是脚本对自有合成任务的批准实操，范围不含原生人工批准、模型自主完成任务、物理远端或公网生产接入。宿主能约束自己的发送及通道，不能证明远端程序身份或控制已发生的远端副作用。

## 测试与保留失败

全仓 60 组共 **1385 项通过、14 项忽略**，桌面库 **122 项通过、9 项忽略**；真实 TCP/TLS **10/10**、原本地产品回归 **21/21** 通过。严格 Clippy、格式、能力矩阵与根／macOS／Windows 三套依赖检查通过。127 个既有保留文件及准确 010 App 的 90 个文件逐项一致，App 严格签名通过；本次没有构建或替换 App。

保留以下原始失败及修复依据：

- `gateway-02.log`：新预算测试把网络次数设为零又配置主机，违反原计划规则；改为允许一次、第二次按预算拒绝，没有放宽规则。
- `runtime-01`：夹具使用非法单标签计划主机 `localhost`，启动被拒；该轮宽泛捕获误记的一项令牌检查无效，不计通过。最终改用 `mcp.localhost` 和准确错误码；测试证书增加对应 SAN，证书名称错误负例保留。
- `runtime-02`：本地读取成功，远程写入卡住，服务端只有发现请求、没有副作用。根因为派发锁内再次调用取同一锁的取消回调。`lock-regression-before.log` 真实复现旧代码失败；修复为锁内仅检查期限与令牌，撤权仍由原派发锁原子核查，锁外检查取消。10 项真实 TLS 测试及最终联合实操通过，没有移除权限检查。
- `runtime-03` 为修复后 28 项通过，`runtime-04` 增补令牌和真实超时后 33 项通过；最终 `runtime-05` 明确将本地实际返回值传给远端，并再次 33 项通过。各轮报告独立保存。

## 原任务覆盖与接续

| 原验收要求 | 证据与边界 |
| --- | --- |
| 一个本地 stdio 与一个明确协议远程服务 | 官方 Filesystem 与自有 MCP 2025-06-18 Node HTTPS 联合生产 CLI 实操通过。 |
| 启动隔离 | [包冻结与隔离启动记录](agd-017-service-isolation-2026-09-15.zh.md)，本轮旧本地 21 项回归。远程服务本身不宣称受本机容器隔离。 |
| 令牌受众、范围 | 传输验签及本轮五种坏配置零请求；发现令牌与调用令牌分离，服务端独立核查。 |
| SSRF | 固定地址、专用 CA、准确名称、地址拒绝集合、不解析 DNS／代理、不跟随重定向；测试模式严格限 127.0.0.1。 |
| 消息大小、超时、断连 | [传输边界](agd-017-remote-transport-2026-09-15.zh.md)及 10 项 TLS 回归，本轮真实 30 秒、已写入断连读回和崩溃恢复。 |
| 不支持特性明确拒绝 | 保持有界 JSON／SSE、无会话流；分页、订阅、旧 SSE、资源／媒体、服务端请求、压缩及 OAuth 自动发现等不支持，不静默降级。 |
