## 本批交付

活动页新增“本应用的受控任务”记录来源。用户选择本应用保存的任务，分别查看任务网关和专用浏览器通道，按告警、已阻断、未知或执行记录筛选。展开动作后，只显示日志中实际存在的判决、开始、终态及追加序号；不补画缺失阶段，不把工具返回等同于业务成功。

| 证据 | 页面结果 |
|---|---|
| 有前序阶段，终态明确拒绝且未派发 | 已阻断，仅限该动作 |
| 有判决／命中，但尚无终态 | 告警；无命中且可执行判决仍为未知 |
| 已开始但未返回，或重启后只有未知恢复回执 | 结果未知 |
| 工具返回成功且已派发 | 执行记录，业务效果未核对 |
| 取消、超时或失败，且终态明确未派发 | 执行记录，未派发 |
| 只有孤立终态，没有判决或开始记录 | 结果未知，不能据此宣称阻断 |

既有“本机桌面观察”仍独立分类；其中的 Block 或用户拒绝不冒充执行阻断。规则编号可以跳到知识库对应手法资料，但仅是编号相同的参考关联；没有核对实际策略与目录规则版本相同，也没有据此识别攻击阶段。七个资料阶段的发生状态、12 个未运行场景及 18 条覆盖登记保持原样。

## 读取与安全边界

`AuditStore::verified_snapshot` 在同一只读事务中核对完整哈希链、记录数量和头摘要，再按追加顺序返回快照。读取不争抢网关写入所有权、不补写崩溃恢复、不迁移或修复数据库。开始／终态的批准摘要及所有阶段的动作、任务、策略、目标、来源与工具绑定必须一致；矛盾、重复、乱序和不支持的结构拒绝展示。

宿主命令只接收规范 UUID，从应用数据目录的 `local-agent-sessions` 读取固定 `audit.db` 和 `browser-audit.db`；前端不能指定路径、密钥或 URL。检查当前用户所有权、目录权限、符号链接、文件硬链接及读取前后的目录／文件身份。任务子目录必须仅当前用户可访问；数据库可沿用旧有 0644，但不能被其他用户写入。受管网关原本清空环境，日志是无正文的明文摘要；读取不尝试桌面审计密钥，也不触发钥匙串提示。

单通道缺文件显示“尚无记录”；损坏、矛盾、权限错误或超限显示“不可用”，不把读取失败说成历史为空，也不隐藏另一通道有效数据。切换任务会清除旧内容，迟到的响应不能覆盖新选择。所有正文以文本节点呈现，没有外部导航或执行入口。

- 每份日志上限 8192 条、记录字段合计 16 MiB；超限整份不可用，不返回截断的完整性证明。
- 最多枚举 4096 个目录条目，显示最近 256 个规范任务目录并明确提示截断；目录修改时间仅供选择，动作顺序以日志追加序号为准。
- 页面每个通道每次显示 50 个匹配动作，支持继续加载；分页不减少后端验链范围。

哈希链只证明所读快照内部一致，**未验证独立签名归属，不防管理员整体重写或截去日志尾部**。文件身份检查也不是针对同用户／管理员任意并发换库的完整防御。来源摘要不等于已验证原文，执行摘要不等于已核对业务效果。

## 保留失败与证据位置
