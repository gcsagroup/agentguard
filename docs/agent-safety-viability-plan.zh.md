# Agent 安全卫士：可行性与可用性推进方案

日期：2026-09-07。目标：用户能日常使用、能看清保护范围、故障时不偷偷执行、恢复后不重复提交的 Agent 安全卫士。

## 产品选择

先把本机 macOS + Codex 的受控任务做成可靠入口，复用现有 Rust 网关与判决引擎，逐项接入浏览器和工具能力。现有桌面观测、浏览器扩展和受控执行分别提供证据，不能把“观察到风险”显示成“已经阻止”。受保护浏览器目前是执行路径验证模块，后续应接入既有桌面工作区，避免形成两个长期维护的产品界面。

首个可用闭环是：用户启动会话并给出站点范围 → Agent 连接 → 正常任务继续 → 需要确认的请求在执行前暂停 → 用户核对并批准或拒绝 → 核实实际业务结果 → 断连时暂停，重新连接时不重放旧动作。

不能把通用 GUI Agent 的全部动作都纳入当前保护主张。第三方客户端如果另有终端、文件或其他浏览器工具，仍可绕过合作式网关。本机同一用户的恶意进程也可能读取凭据。真正要约束这类对手，必须增加经过验证的独立身份/系统隔离；在条件满足前，界面必须显示实际覆盖范围。

## 四个必须同时满足的标准

| 标准 | 可验证的判据 |
| --- | --- |
| 安全 | 未批准请求不触达目标；Agent 操作权限不能批准；断连、超时、崩溃和重连不恢复旧批准；结果未知不自动重试 |
| 可用 | 代表性正常任务确实完成；人工确认对应业务动作；不依赖用户翻找 Agent 内部日志；故障原因和恢复入口清楚 |
| 可恢复 | Agent 客户端退出后，用户持有的会话和页面仍可保留；连接失效期间网页请求暂停；新连接不继承旧待确认项 |
| 可维护 | 日常回归无需模型账号；真实客户端验收单独运行并保留版本、耗时与业务计数；升级依赖必须复验 |

“高可用”不等于遇到故障默认放行，也不等于宣称 99.9% 在线率。当前没有长期运行统计，不作可用率承诺。关键请求宁可明确失败；正常工作应通过限定权限、良好兼容性和可恢复会话减少中断。

## 阶段 → 进入下一阶段的条件

1. **独立会话与真实客户端闭环（有限本地验收已通过）**：人持有会话、操作令牌与批准令牌分开；Agent 独占连接和心跳；控制页可看到连接状态与接入配置。验证真实 Codex 的批准、拒绝、断连、再次连接；服务器计数与页面状态同时吻合。
2. **减少误拦截与提高任务完成率（Codex 有限代码任务已验证）**：用户确认首批以 Codex 本地代码工作为主。9 月 8 日冻结源码上的 50 项操作从 36/50 提高到 50/50；五个独立真实 Codex 任务完成查代码、改文档、改代码和跑测试。见 [代码任务验收](codex-normal-work-acceptance-2026-09-08.zh.md)。这些操作级与小任务结果不替代至少 50 个完整日常任务、完成率不低于 95% 的目标，该目标仍待验收。后续浏览器任务仍需单独建立站点/方法/路径/参数规则，不能只靠 HTTP 方法或模型说“安全”免确认。
3. **接入现有桌面工作区与网关（本地配置入口已验证，完整会话管理待接入）**：9 月 8 日已在 macOS 主动防护页加入工作区、只读/读写模式、本次任务、接入命令及确认通道入口；当前准确测试 App 已实际操作，桌面生成配置也完成两项真实 Codex 任务。见 [桌面接入验收](desktop-codex-setup-acceptance-2026-09-08.zh.md)。当前仍需手动运行命令、获取确认凭据，未达到免查日志的完整闭环。后续目标是：一个会话入口展示健康状态、当前客户端、保护范围、待确认项、失败恢复方式和可导出的脱敏证据。沿用既有判决和确认语义；浏览器原型不自行扩展成第二套通用安全引擎。需要当前准确 App 身份的真实运行与权限复验。
4. **可用性与故障压力验收（本机循环已通过，故障覆盖未齐）**：至少 30 分钟持续使用与 100 次任务/重连循环，记录失败率、确认次数、执行器耗时和连接恢复耗时；注入客户端崩溃、服务崩溃、网络断开、系统休眠及大响应。模型服务延迟、人工确认时间和执行器开销分别统计，不能互相替代。9 月 8 日本机合成验收已完成 30 分钟、100 次循环，50 次批准对应 50 次提交，40 次拒绝与 10 次断连取消均未提交；系统休眠、长时间网络故障和真实业务仍待测。
5. **补齐不可绕过的执行边界**：在可取得条件的平台上验证独立身份、子进程/文件/网络隔离；Linux 复用 guard-jail 已支持能力并以实际内核验收为准；macOS 先确认权限和 entitlement 条件。未经验证，产品保持“只保护通过指定入口执行的任务”说明。
6. **有限试点与发布**：完成明确站点兼容、安装/升级/卸载、隐私与持久审计、签名与发布材料后，再评估对外发布。部署与发布沿用用户确认流程，不因本地测试通过自动执行。

## 当前工程边界

- 浏览器所有直接 HTTP(S) 出口走拒绝代理；通过检查后才由执行器转发。已修复调试连接崩溃导致暂停请求泄漏的问题。
- 独立会话只恢复客户端连接与已有页面；会话服务自身崩溃后须新建会话。不会自动恢复批准或自动重放未知结果请求。
- 控制页是本地受控原型入口，尚未集成进正式桌面工作区；连接配置仅在本次会话有效，不修改用户全局配置。
- Rust 网关已补齐有界输出、命令超时和客户端断连清理，同一操作员计划传给路径检查与会话引擎；真实 Codex 完成授权范围内写读及越界拒绝。见 [网关可用性验收](gateway-availability-acceptance-2026-09-08.zh.md)。
- 查询参数、重定向、上传和实时通信限制仍影响复杂站点使用；当前合成页面结果不能代表真实站点兼容率。
- 当前不声明系统级隔离、长期可用率、跨平台一致性或生产发布完成。
