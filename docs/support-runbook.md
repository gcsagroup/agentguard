# 上线支持手册

## 发布前

- 六端必须各有公开支持入口、时区/值班表、责任人和升级链；商店页、应用内链接与隐私页一致。
- 准备签名/安装失败、权限未授予、观测不可用、误报/漏报、确认队列、审计恢复和安全上报的经审查回复模板。
- 支持人员只收集解决问题必需的版本、渠道、错误代码和已脱敏日志；不要求用户发送密码、签名密钥、会话令牌、完整屏幕或不相关文件。

## 受理和升级

1. 用工单 ID 记录接收时间、平台/版本/渠道、现象、影响和用户同意的诊断材料。
2. 先区分使用问题、已知限制、产品缺陷、安全/隐私事件和商店/签名故障。
3. 可能影响保护语义、多用户、签名/更新链或个人数据的问题立即转 [事故响应](incident-response.md)；支持人员不自行降低严重性。
4. 回复用户时只陈述已验证事实、可恢复步骤和下次更新时间；不承诺未批准版本或虚构根因。

## 指标与发布反馈

按渠道聚合工单量、首次响应/解决时间、重复问题、升级严重性与用户退出。Beta 和 5/25/100 每一阶段扩量前，Operations 必须把支持摘要加入健康决策。产品与支持文档的修复也要经评审、版本化并留存变更日志。
