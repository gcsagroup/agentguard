## 已完成的恢复与密钥专项

使用全新合成工作区、合成 Ed25519 密钥和同一既有 Docker 镜像，四个 CLI 进程串行运行。没有改动用户资料或现有授权。

| 场景 | 实际结果 |
| --- | --- |
| 待批准记忆写入时 SIGKILL | 已批准的版本 1 保留；未批准的新正文未写入；重启后完整来源、标签及批准引用保持一致 |
| 重启后旧治理批准 | 旧撤销预览返回 409，没有新增版本 |
| 同时配置记忆与委托 | 操作者仍可核对记忆历史；模型只得到签名委托入口，不能绕回普通 `memory_write` |
| 更换主体公钥 | 旧宿主正常结束后换公钥并重开；新会话、新授权、正确序号的消息使用旧私钥签名仍被拒绝 |
| 新密钥正常性 | 对上面**同一条消息**仅更换为新私钥签名，实际读取成功；排除了旧会话校验提前拒绝的假通过 |
| 移除主体 | 同时移除指向该主体的委托权限；新宿主拒绝其消息及再次委托，父主体仍可读取原合成文件 |

**撤钥的生效条件是先停止旧宿主，再修改宿主配置并重新启动。** 当前配置在启动时加载，没有运行中自动重载主体公钥的能力。界面停止委托分支是另一项控制，不能替代主体密钥撤销；已经完成的外部操作也不会因撤钥而撤回。记忆签名密钥与委托主体密钥分别管理，本项没有实施历史记忆换钥迁移。

独立核对器只读真实 SQLite 和公钥：核对 **49 条执行审计、2 条记忆审计、17 次签名结果、5 条成功消息及 4 条拒绝消息**。替换撤销旧钥签名、隐藏 SIGKILL、删去正常读取、恢复已移除主体四类篡改报告均被拒绝。

初次测试夹具仅声明记忆操作，却调用了隔离文件读取；网关按现有任务范围规则附加说明，使精确正文断言失败。已在夹具中预先声明文件执行步骤，并保持只读目录和委托文件权限限制，随后重跑通过。失败报告 `recovery-01/` 原样保留，没有改产品规则或放宽结果断言。
