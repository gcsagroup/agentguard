# 固定 App 024：原 Safari PR 的误报复测

日期：2026-09-16。源码基线 `483c6ad19a7ec944fbc470db9a0e9cbce443bbbe` 加本批补丁。固定 App 已同路径更新为 Ver 2.1（024），名称、Bundle ID、工作区及组织签名保持；两项权限在更新及普通重启后均保留。

## 原因与修正

用户截图中的 `CRIT-005` 将页面里的安装文字解释成“Agent 即将安装软件”。此前 018 已将可信桌面观察中的这类命中改为普通记录，022／023 补做过合成正文验证。这次在准确 023 中真正打开[原 GitHub PR](https://github.com/gcsagroup/aegis-browser/pull/7)：审计 795 的安装文字确实为 `Info / LogOnly`，但紧接着 796 又以 `OVL-010 / Critical / Block` 弹窗，说明原页面问题还没有完整解决。该失败及选择暂停的签名回执保留。

第二条误报来自窗口树与屏幕 OCR 的差异。当前 macOS 桥将整屏缩为 640×360，增强对比度后做快速 OCR，最多取 24 行；辅助功能读取的是窗口树。漏读、折叠或屏幕外文字、遮挡及窗口切换都会造成不一致，不能据此证明“用户看不见的隐藏指令”。本次弹窗中的 OCR 也出现明显乱码。这里是代码和实际提示的证据，不宣称已经准确测量各因素的贡献。

024 保留差异检测及审计，在可信桌面观察入口把基础 `OVL-009`／`OVL-010` 作为 `Info / LogOnly` 线索。活动记录用三语说明证据不足，继续显示真实发生日期、秒和时区；旧高风险记录保持原判决，不追溯改写。没有禁用辅助功能、录屏或清除权限，没有增加域名白名单。

判决顺序同时修正：先匹配独立风险，再补普通观察摘要。不能先选中较长的差异标记后直接降级，否则会盖过同帧明确注入或付款文字。普通执行入口仍保留原确认要求，事件字段不能自报观察绕过；受控附加规则包、情报和其它独立风险继续收紧判决。原 OCR 分辨率和识别质量没有在本批提升，因此也不能宣称已证明任意隐藏文字可见性。
