# macOS Codex 工作区接入验收

日期：2026-09-08。结论：本地配置入口、范围判决、真实 Codex 小任务已通过；完整桌面会话管理尚未完成，不具备系统隔离或发布资格。

## 本轮完成

在“主动防护 → 智能体工具网关 → 配置接入”加入项目工作区、授权模式、本次任务、启动命令和确认通道入口。其他 MCP 客户端的通用配置保留在折叠区；设置和帮助原有入口仍能到达同一向导。

默认“只读与搜索”，独立策略直接拒绝命令执行、写入和删除。“读写与测试”需要明确选择，并保留现有危险动作判决。生成前检查当前 App 封装内的网关，任务范围配置保存在应用独立目录，文件权限为 0600、每次目录为 0700；不改用户项目文件和 Codex 全局配置。

修改输入立即清除界面的旧命令，在途异步结果不能覆盖新的工作区。生成配置、确认通道连接、客户端实际执行分别说明，界面不以握手或复制动作宣称任务已受保护。

## 实际发现与修复

真实网关测试首先发现：声明 `scope.paths.read` 后，外部普通文件仍被允许读取。原因是路径范围检查只处理写入意图。本轮让已声明的范围同时约束读写，外部普通文件返回 `SHELL-PATH-OUTSIDE`；未声明范围的旧客户端仍保留普通读取行为，凭据敏感路径仍拒绝。原拷贝回归需要显式声明来源的读取权限，不能继续依赖旧宽松行为。

只限制写入路径不足以建立只读模式，因此只读策略额外拒绝 `run_terminal` 与 `write_file`。真实测试验证普通命令、写入和删除都被拒绝，目标文件没有产生，原 README 仍存在。

原生 WebView 在跳转时隐藏向导会使可访问性树短暂丢失后续控件。调整为保留向导、滚动并聚焦确认端口，重新构建后验证控件与焦点正常。

测试脚本曾把文件内容参数写成 `content`，导致读写测试失败；已改为真实工具要求的 `contents`，并断言拒绝规则，避免把参数错误算成安全拦截。

## 录屏权限申请补充验证（9 月 8 日）

用户反馈当前测试包只出现辅助功能，屏幕录制列表没有 AgentGuard。本轮补充录屏用途说明，以 ScreenCaptureKit 发起权限申请；申请前激活当前应用，等待系统处理完成后再打开设置，避免立即跳转打断申请。申请只枚举可共享内容，不创建录制流，也不保存屏幕像素；连续点击不会重复发起尚未完成的申请。

已重新构建同一路径的 `AgentGuard Test.app` 并完成本地临时签名检查。系统 TCC 日志确认收到当前 `com.agentguard.desktop.macos.acceptance` 的屏幕录制请求。实际操作中，产品仍显示权限未开启，因此不能判定录屏授权通过。自动操作工具明确拒绝访问 `com.apple.UserNotificationCenter`（系统授权对话框），最终弹窗是否可见及用户是否允许仍需桌面人工确认；此限制不证明系统一定弹出了提示。

验证记录保存在 `eval/ui-preview/out/permission-build.log`、`permission-sign.log`、`permission-adapter-test.log` 和 `permission-desktop-test.log`。临时签名变化可能使旧权限记录不再适用于当前包；没有启用桌面观察，也没有修改系统授权开关或其他应用的权限。
