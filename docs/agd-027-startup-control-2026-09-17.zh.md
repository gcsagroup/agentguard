# AGD-027：最小进程的首次启动对照

日期：2026-09-17。源码基线 `485efe4f299debfe4b22978ed44280859971c7bc`。**本机在现有签名条件下，即使约 52 KB、没有业务初始化的程序，首次进入 `main` 前也超过原 100 ms 预算。** 该结果缩小排查范围，不是产品修复或网关性能验收通过。

## 对照对象与冻结方法

本机 macOS 26.6.2（25G83）、arm64、Mac17,7、128 GiB。最初检查的 `guard-cli` 确实链接录屏／视觉框架，但它不是性能计时对象；准确 `agentguard-mcp` 只有 Security、CoreFoundation、libiconv 和 libSystem，已按实际候选纠正方向，没有据此修改适配器或产品构建。

准备两种相同 C 程序：最小版只链接 libSystem；依赖对照版增加与真实网关相同的另外三个直接依赖。程序只报告入口、读取合成 `PING`、返回 `PONG` 并退出，不包含 Rust、SQLite、规则加载或其他业务。直接依赖由实际 Mach-O 列表核对，不能把直接列表相同说成全部间接加载和初始化完全相同。

两者均使用既有组织证书 `7C33B517942161311A087CE893D2F1CE9B204B44`，严格签名及实际叶证书 SHA-1 核对通过；没有降为临时签名。该身份是 Apple Distribution，不是 Developer ID Application，也没有公证证明。新 CLI 对照仅存在本批证据目录，没有新增 `.app`、更改日常入口或系统安全策略。

每组在执行任何测量前冻结候选摘要、源码、运行器及六轮顺序。首组记录宿主收到入口标记的时间；第二组新程序在 `main` 第一项操作读取 `CLOCK_MONOTONIC`，父进程也使用同一系统时钟，并反转两种候选的首次顺序。各自首次样本均保留，无预热，无动态加载器日志或调试器采样。

## 实际结果

首组两份文件均为 51,936 字节。宿主观察到最小版首次 **531.283 ms**、依赖对照版首次 **420.611 ms**；随后四次重复为 2.139～3.989 ms。由于仅有宿主时间，该组单独不能区分入口延迟和日志接收延迟。

第二组两份文件均为 52,000 字节，父子时钟对齐后的结果如下：

| 顺序／对照 | 子进程实际入口 | 宿主收到入口标记 | 完成合成应答 |
| --- | ---: | ---: | ---: |
| 1／网关依赖首次 | 590.524 ms | 590.610 ms | 590.745 ms |
| 2／最小版首次 | 434.349 ms | 434.405 ms | 434.487 ms |
| 3／最小版重复 | 2.955 ms | 2.986 ms | 3.037 ms |
| 4／网关依赖重复 | 4.171 ms | 4.203 ms | 4.254 ms |
| 5／网关依赖重复 | 4.302 ms | 4.340 ms | 4.409 ms |
| 6／最小版重复 | 2.284 ms | 2.308 ms | 2.356 ms |

两个首次的入口到宿主接收仅为 0.086／0.056 ms，不能用父进程接收日志慢来解释本组数百毫秒差距。两组共 12 次应答均正确并退出 0。全部计时结束后，分别向两组最小版输入 `INVALID`，均退出 2 且不返回 `PONG`。

这表明在本机／本次签名与启动条件下，**业务初始化并非出现该级别首次等待的必要条件**。它不证明 Security 框架导致延迟，不确定 XProtect、签名验证、调度等各自占比，也不保证换成正式签名后满足 100 ms。两组首次结果随顺序及候选变化，不能据此宣布稳定的框架性能收益。
