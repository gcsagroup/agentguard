日期：2026-09-09。原 `17d1…` 基线结论：**三路各 30 次正式读取全部完成，失败为零；隔离网关的 1 KiB 读取 p95 为 334.37 ms，当时主要产品成本是每次小操作的固定开销。** 这是已经读过的小文件操作微基准，不能替代 50 个完整用户任务、长期稳定性或发布性能结论。最终 `2dcb…` 候选的独立复测见文末，不沿用旧候选数值。

## 固定输入与测量口径

- 候选：`17d1af9c56859d45c561a8b3f2fcfdd383981874026d423cd17f738f63b0dc44`，执行的是保存的冻结副本。
- 隔离镜像：`sha256:7de5789da80158e418d22bf911ea3829aa1abdeb2338dd556dc99b13c89d8490`，Docker VM 在测量前已经运行。
- 输入：同一份 1,024 字节合成 ASCII 文件，计时前先读一次。各路预热 5 次单列，正式 30 次。每次完整核对内容；失败保留在计划分母，延迟统计保留已完成的失败尝试，不因失败而缩小样本。
- 顺序：直接宿主读取 → 原生网关 → 隔离网关。本轮不是随机交叉实验，也不代表磁盘或 Docker Desktop 冷启动。
- 两条网关路径均开启各自的持久审计；隔离路径使用授权范围外的独立控制文件，原生路径不使用已禁止的 `--control-file`。没有批准操作、模型调用、人工等待或外部业务请求。
- 延迟：提交读取至完整正文收到；启动与预热不混入正式读取。p50／p95 采用 nearest-rank。
- 启动：`spawn` 前至 `initialize` 和 `gateway/stats` 都返回；隔离模式同时核对控制文件已经建立。每路只测一次启动，**不报告启动 p95**。
- 内存：从网关启动到正式采样结束，对网关 PID 每约 20 ms 读取 RSS，并在结束前补采。这里报告的是**观察到的采样峰值**，可能遗漏短时尖峰；不包含 Docker CLI、容器进程或 VM 内存。

环境：Apple M5 Max、18 个 CPU、128 GiB 内存、macOS Darwin 25.6.0 / arm64、Node v22.23.2、Docker Engine 29.5.3。宿主一分钟负载从约 6.03 变为 11.47，存在并行工作，因此这些数值是本机当时条件下的基线，不是空闲实验室保证。

## 简短观察与 M1 待冻结预算建议

原生网关的小文件读取保持毫秒级；隔离路径每个工具调用都会创建并销毁受限容器，约 0.27～0.33 秒的固定成本会在大量小调用时累积。这是结合当前调用方式和结果的判断；本轮没有分别测量 Docker CLI、Python 启动、传输和审计各自耗时，不能把全部差值归因于某一个组件。

建议先把下面数值作为**同一 1 KiB 夹具的 M1 回归预算草案**，在 AGD-013 冻结候选与代表性任务集时确认；它们不是对所有工具、所有设备或完整任务的 SLA。

| 项目 | 建议预算草案 | 适用范围 |
| --- | --- | --- |
| 正常结果 | 正式 30/30，正文完全一致 | 不剔除失败；安全测试另列 |
| 原生 read_file p95 | ≤10 ms | 同一夹具，持久审计开启 |
| 隔离 read_file p95 | ≤500 ms | 同一夹具，当前每调用新建容器方式 |
| 网关启动 | 原生 ≤100 ms；隔离 ≤2,000 ms | Docker VM 已运行，不包含 VM 冷启动 |
| 网关 RSS 采样峰值 | 每路 ≤32 MiB | 当前夹具与 30 次操作；仍不包含容器／VM |

进入完整编码任务验收时，需要另外预算大文件、搜索、解释器／编译任务和长期会话。后续如优化重复容器启动，可评估受保护会话内的执行复用，但必须重新验证权限、停止、污染残留和凭据边界；本轮不为性能数字放松隔离，也不启动这项额外开发。
