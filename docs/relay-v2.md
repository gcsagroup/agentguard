# Android 桌面中继 v2

2026-09-16。本协议用于 Debug 开发候选；Release 仍关闭中继，正式 A1–A4、真机与商店验收未完成。它验证事件与判决的来源，不是第三方应用的执行前拦截器。

## 配对和密钥

手机使用原有 Android Keystore P-256 设备密钥。桌面注册表必须登记 `android-companion`、`key_algorithm: ecdsa-p256` 及手机公钥。桌面另用 `guard-cli relay-keygen --key 私有目录/response-key.json` 显式创建响应密钥；命令只打印 SEC1 未压缩公钥，已有文件只读取，不换钥或覆盖。API 通过 `--relay-signing-key` 加载它。Unix 拒绝符号链接、非普通文件、超限文件和组／其他用户可读的私钥；非 Unix 不声明同等权限位检查，需由用户限制目录 ACL。

将从可信桌面核对的公钥、地址与令牌输入手机，保存后再启用。网络响应不能提供或更换信任公钥；更换地址或公钥必须重新输入令牌。旧 `relay_enabled`、旧 URL 和成功时间不自动迁移。保存配对先同步关闭旧启用状态，再写入新令牌及公钥；写入失败保持关闭。

默认地址固定为 `http://127.0.0.1:8788/v2/events`，通过 `adb reverse` 使用。只允许字面的 `127.0.0.1` 使用 HTTP，其余目标必须为系统信任的 HTTPS，不允许账号、查询、片段、其它路径或自动重定向。API 本身不终止 TLS，远端部署还需要独立的 HTTPS 入口；本轮没有验证此部署。签名不提供保密性，不能代替 TLS。请求与响应绑定、nonce 和时间限制的设计参考 [RFC 9421](https://www.rfc-editor.org/rfc/rfc9421.html)；这里是固定仓库协议，不是 RFC 9421 兼容实现。

## 请求与响应

请求只使用 `POST /v2/events`。除强 bearer 外，要求原有适配器请求签名三个头，并额外发送随机 32 字节挑战 `X-AgentGuard-Relay-Nonce`（64 位小写十六进制）。重复、缺失或无效的认证头会被拒绝。请求体上限 256 KiB，未登记、无效、过期或重放签名返回 403；验签失败不能推进适配器序号或改动会话。每份已认证信封使用其自己的会话标识，避免沿用第一份信封的会话。请求去重使用现有进程内缓存及时间窗口；不声明跨桌面服务重启的持久去重，窗口内旧请求在服务重启后仍可能再次被处理。

成功响应使用独立桌面 P-256 密钥对以下字节作 SHA-256/ECDSA 签名：

1. 原始域标签 `AGENTGUARD-RELAY-RESPONSE-v2`。
2. 依次追加 `POST`、`/v2/events`、nonce 的 32 字节、原始请求体 SHA-256 的 32 字节、十进制 `200`、十进制毫秒时间戳和完整原始响应体。
3. 第 2 步每个字段前放 4 字节大端长度；字符串使用 UTF-8，不重新序列化响应 JSON。

响应头为 `X-AgentGuard-Relay-Version: 2`、`X-AgentGuard-Relay-Key-Id`（SEC1 公钥 SHA-256）、`X-AgentGuard-Relay-Timestamp` 和 `X-AgentGuard-Relay-Signature`（DER 签名十六进制）。响应体至多 1 MiB。没配置响应密钥返回 503；签名出错或响应超限返回失败，客户端不会改用 v1。

手机按固定公钥验证完整响应后才解析判决，并核对 `ok`、设备身份和判决数量。只接受 200、单值签名头、与本请求相符的签名、两分钟内的系统时间及请求发出后十秒内的响应。每个挑战只能消费一次，错误响应也不能复用。连接与读取超时分别为三秒；十秒是接受响应的期限，不宣称 Java 底层阻塞写入一定在十秒内结束。

手机仅用一个发送线程、最多 32 个待发送请求；超限或排队超过十秒的请求报错，不自动补发。停止或更换会话、关闭或修改配对后，旧响应不能更新成功状态或弹出新通知。会话结束事件仍可排队送出，但不会把已结束的手机会话重新标成连接成功。旧 `/v1/events` 的“未认证调查只能增加风险”保持兼容。

## 验证与剩余条件

共享夹具 `eval/fixtures/relay_response_v2.json` 来自真实 Rust HTTP 服务的响应，私钥已删除。Rust 和 Kotlin 独立构造消息并验证相同签名；夹具不会由测试自动重写。HTTP 回归覆盖错误公钥、正文／请求／nonce 替换、缺失与重复头、过期、重放、超限、截断、断连和重定向。相关记录见[本轮验证](agd-032-android-relay-v2-2026-09-16.zh.md)。

原正式 A1–A4 要求不变；Debug 模拟器、JVM 和本机 API 证据不能替代 Release 真机验收。证书、正式候选、API 35+ 真机／OEM、远端 HTTPS 和独立复核仍是各自的条件。无权限的本机恶意进程、同 UID／root 可改配置或进程内存等情况，不能靠该协议完整解决。
