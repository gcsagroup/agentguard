# AGD-012 统一宿主浏览器接入

日期：2026-09-10。范围：macOS 本地候选代码与真实 Chromium／合成本机业务服务；原生桌面整体验收由统一候选单独记录。

## 已实现的路径

宿主网关创建浏览器进程并保留其生命周期。文件工具和浏览器使用同一个宿主会话编号、暂停／停止状态与撤权代次。恢复会创建新会话编号，旧请求不能继承批准。MCP 只新增 `browser_status`、`browser_navigate`、`browser_read`、`browser_click`、`browser_fill`；没有脚本执行或批准工具。

浏览器捕获请求后，经独立执行连接交给 Rust 宿主。该连接令牌没有批准权限，所在端口与批准控制端口不同。所有 HTTP 请求都要求独立人工确认，包括 GET／HEAD。宿主冻结最终 URL、方法、规范化请求头、完整正文、页面标识、会话、期限和随机值；请求正文上限为 16 KiB，仅支持 UTF-8 JSON、表单编码或纯文本。Cookie 使用当前浏览器捕获值，响应重复 `Set-Cookie` 保留给浏览器。

执行顺序是持久保存判决 → 人工确认 → 复核会话与单次绑定 → 持久保存开始 → Rust 实际连接与发送 → 持久保存结果。暂停与首次发送共用一把同步锁，发送和读取有总期限。开始记录失败时不会建立目标连接；发送后无法确认结果或终态记录失败时，浏览器与文件工具共用的会话立即暂停，并禁止从该未知状态恢复重试。

DOM 操作与 HTTP 子请求分别保存回执。`isError` 是明确布尔值，`_meta.agentguard` 含动作结果、派发状态、会话和摘要。点击的成功只表示控件操作已发起；返回值明确不声称业务提交成功。HTTP 状态与实际业务结果必须继续核对。网页内容与请求来源仍标为未知，不能提升授权。

浏览器审计数据库与文件工具审计数据库分开保存，均使用既有带完整性校验的执行日志和同一个会话编号。只保存编号、状态、范围和内容摘要，不保存请求正文、Cookie 或批准随机值；重启后未完成动作按未知处理，不自动重放。

## 启动与依赖

网关须同时获得以下显式参数，缺少任何一项都拒绝启用浏览器：

```text
--browser-runtime <绝对路径/cli.mjs>
--browser-node <绝对路径/node>
--browser-playwright <绝对路径/playwright包目录>
--browser-browsers <绝对路径/Playwright缓存目录>
--browser-origin http://127.0.0.1:<已授权业务端口>
--browser-audit-db <任务工作区之外的独立审计文件>
--browser-file <任务工作区之外的独立执行连接文件>
```

`--browser-origin` 可重复，最多八个准确站点。控制端口不能作为业务目的地。`--browser-headless` 只用于无窗口验收。仍须提供既有工作区隔离、宿主批准文件与文件审计参数。桌面负责依赖发现及这些参数的生成；运行时不调用 npm 猜测依赖位置。

统一模式由 Rust 经 `sandbox-exec` 启动 Node，清空继承环境，只设置本次私有 HOME／临时目录、明确 Node 路径、Playwright 包与缓存。专用进程只允许向独立执行端口建立 TCP 连接；HTTP 业务连接由宿主建立。Chromium 必需的本地 SingletonSocket 有窄范围例外。用户 HOME 和本次控制目录默认禁止读取和写入，只读放行所需程序／依赖／浏览器资源与单个执行连接文件，本次私有目录可写。

批准与浏览器执行两个 HTTP 入口都使用有界控制连接层：固定 IPv4 回环监听，拒绝分帧歧义，每条连接只处理一次请求，限制头、正文、响应、工作线程及读写总时长。不完整或超大请求不会在拒绝时按攻击者声明的长度排空正文。

## 验证入口

```text
cargo test -p guard-gateway --lib browser_bridge
node --test apps/protected-browser/host-integration.test.mjs
node --test apps/protected-browser/host-resolver-probe.test.mjs
```

第一项使用真实本机 TCP 与真实 SQLite 主键冲突，验证执行开始前存储失败零连接、发送后终态存储失败变为未知、全局暂停和页面取消零发送。第二项启动实际网关与沙箱内 Chromium，核对批准／拒绝、Cookie、表单业务状态、旧批准重放、暂停恢复新会话和未知结果后的恢复拒绝。系统解析专项使用同一个生产 `BrowserActor` 启动器及完整沙箱配置运行独立合成 Node 探针；无沙箱 `getaddrinfo` 正对照可解析 IANA 示例域名，受限进程同入口失败，同时检查直接 TCP／UDP、私有文件和继承环境。这个专项不访问示例域名的 HTTP 服务，不代替 Chromium 页面的整体验收。

旧独立浏览器模式的回归命令保留在 [浏览器说明](../apps/protected-browser/README.md)。统一会话的 B01–B10 正常业务任务由独立验收脚本记录；开发测试不能代替冻结候选的完整任务分母和原生界面操作。

## 当前边界

- 本版仅支持明确登记的 `http://127.0.0.1:<port>`，不支持公网 HTTP／HTTPS、域名目标、重定向、WebSocket、文件上传与后台 Worker 请求。
- 出口限制覆盖这组受宿主管理的 Node／Chromium 进程，不接管用户其它浏览器或其它程序；用户 HOME 之外的全盘文件隔离没有完成。
- 系统解析专项证明本机这版 Node 的 `getaddrinfo` 正反对照及直接 UDP／TCP负例；不据单个 DNS 测试声称所有系统守护进程接口都已穷尽验证。
- MCP 客户端结束会关闭本次浏览器与临时资料。需要继续工作时，由宿主新建会话并重新授权；截图或先前页面正文不等于旧页面仍在运行。
- 旧 `node cli.mjs --serve` 独立模式继续保留原边界；它没有自动获得统一宿主的持久审计或 macOS 出口限制。生产发布、其它平台及更广网站兼容性不在本次源代码验证结论内。
