## 2. 负责人安排与复审

主任务负责保留基线、冻结接口、集成 Docker 执行器／控制文件／网关入口、统一测试和最终验收判定。三名 subagent 分别负责后端与真实副作用测试、公共契约与持久审计、知识库与桌面／浏览器适配；共享接口先冻结，独占文件分工，完成后交叉审查。

本轮实际发现并修复了四类问题：

1. macOS 临时目录的 `/private/var`、`/var` 和 Data 卷别名不一致，使正常工作区无法启动。现只允许已知系统别名映射到同一副本，用户链接不能借此扩大授权。
2. 独立批准凭据不能经客户端日志流转。隔离模式现在强制使用授权外的 `0600` 新连接文件，拒绝已有文件、链接父目录和授权内路径；强制退出的旧令牌失效。
3. 单纯隔离执行无法阻止复制阶段把 `Library/Keychains`、`.netrc` 等已知敏感源带入副本。现在按源逻辑路径在读取前拒绝，并确认失败后没有留下快照。
4. 结构化文件工具曾只拒绝末端链接，快照内父目录被替换后会改变实际读写落点。真实复现证明四种文件工具均受影响；已改为逐级不跟随链接并持有父目录句柄，正常嵌套文件操作继续可用。脚本仍能在授权快照内按自身逻辑操作文件，不能把参数绑定称为脚本全部副作用的逐项批准。

修复前报告原样保留，不覆盖失败证据。源码检查、后端功能验证、桌面页面桩、真实网关调用和正式 App 证据分别登记。

## 5. M1 未通过的具体原因

- 缺少快照差异展示、原文件摘要冲突检查和宿主受批准回写。
- 缺少统一的桌面工作区选择、隔离会话启动、结果查看、停止／恢复，以及浏览器和审计同一会话接线。
- 默认断网已验证；联网凭据代理、模型数据出口及客户端／其他 MCP 原生旁路尚未闭合。
- 没有完成预先列出的 50 个完整任务、100 次循环与 30 分钟运行、真实休眠／网络中断、准确签名 App 身份和完整联合验收。

这些是开发计划原有门槛。本轮的操作次数、容器启动和页面桩不会替代它们。下一阶段仍是完成 AGD-006/008/009/011/012 并汇入 AGD-013；M1 未通过前不进入 M2，正式发布保持 **No-Go**。
