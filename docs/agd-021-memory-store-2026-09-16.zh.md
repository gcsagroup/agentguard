# AGD-021：受控持久记忆存储

日期：2026-09-16。状态：AGD-021 已完成，本批实际验收宿主为 macOS arm64。前置 AGD-020 的联合验收已完成；F13 仍按用户要求暂缓，完整原 M1 与发布不通过。

## 目标与实现边界

交付一种可实际写入、关闭、重开和独立验证的持久存储。每个版本保存正文及摘要、完整来源对象、完整性／保密标签、有效期、版本链和批准引用。记忆数据不能成为授权指令；保存、过期、撤销或恢复均不清除标签。

本批复用 `guard-privacy` 的标签格和 `guard-audit` 的 SQLite、逐记录 Ed25519 签名及外部链头见证。现有内存标签表不充当磁盘存储。第一个存储宿主为经过文件锁核验的 macOS／Linux；其它平台暂不提供该接口。网关记忆读写、文档型 RAG 和原生入口分别属于 AGD-022、026，本批不提前记为已接入。

## 冻结的数据和授权约定

1. 存储绑定一个宿主给定的作用域，键是有界标识；每次变更追加新版本，包含上一版本的完整摘要。最新版本过期、隔离或撤销时不回退读取旧版本。
2. 来源必须非空，可以明确为未知。未知来源保留不可信／高保密标签；文件、浏览器和工具返回不得自报为可信。新版本至少继承来源及同键历史的限制，恢复不会洗掉标签。
3. 存储写入者是可信宿主。宿主先通过独立控制面认证批准，再传入绑定完整草稿的 `ApprovalRecord`；此数据结构本身不是认证凭据。存储再次核对会话、工具、目标、参数、时间与单次批准，持久拒绝已消费的批准或动作。
4. 正文写入专用记忆库，不进入普通活动日志。签名密钥和外部链头由宿主持有，不能挂载给隔离任务；核验使用调用方固定的公钥，不能信任库内自带公钥。
5. 生产加密须使用明确 SQLCipher 口令并验证实际能力；合成验收可以显式选择明文。签名提供完整性，不能宣称加密；文件密钥也不提供抵抗已攻陷宿主账户的保证。

## 持久化与故障处理

同一私有目录和数据库只允许一个本存储写入者。读取、版本核对、签名核验和写入决策在一致的数据库事务内完成；重新打开已有库先只读验证，不迁移或补签损坏内容。

数据库提交成功后，原子落盘数据库外的见证；只有两者都成功才回报成功。见证更新失败时，该句柄停止读写并报告结果未确认；再次打开也拒绝头部不一致，不能重试旧批准。显式恢复只允许将仍在完整签名链上的旧见证推进到当前头，不重放写入；缺失见证、删尾或伪造签名不能通过恢复。

所有入口检查条目数、正文／来源大小和总恢复数据量，超限拒绝完整读取，不省略历史来凑成功。实际数据库、WAL、见证、锁和目录须是预期私有文件，链接或身份替换不作为普通恢复。

当前上限为单正文 64 KiB、单草稿 256 KiB、64 个完整来源对象、4,096 个历史版本和 16 MiB 记录数据；库元数据另限 64 项／8 KiB，禁止额外普通决策回执。来源图须自包含且无环。来源随同键历史保留，达到上限即拒绝追加，不截断来源。

读取时核对完整历史，复杂度随版本数增长；本批没有长期大库性能结论。时间由可信宿主提供，拒绝早于最后提交的时钟，但没有持久记录每次读取时间。初次创建中途失败保留原件，不能当作新库自动覆盖；本批显式恢复只处理已有有效见证落后于已提交数据库的情况。

## 已执行的实际操作

验收程序链接真实 `MemoryStore`，不使用模拟磁盘。最终保留目录为 `.artifacts/m3-memory-2026-09-16/process-02/`，准确测试程序及 195 个构建输入保存在 `frozen-02/`。四个独立进程依次创建并写入、重开逐字段读取、追加撤销版本、再次重开确认不可检索；随后直接用 SQLite 把撤销改成有效，第五次打开被拒绝。库、宿主见证、公钥和报告保留；只使用合成内容及合成密钥，私钥不提交仓库。批准明确为宿主合成夹具，不冒充原生人工点击。

独立核对器 [verify-memory-store.py](../scripts/acceptance/verify-memory-store.py) 只读数据库，以 Node 内建密码库验证三条 Ed25519 签名，逐字段核对两版正文、来源、标签、期限、版本前驱和批准引用，并独立重建完整动作摘要。它对篡改后的实际正文重新计算摘要再验签，不直接信任数据库中的旧摘要。重复进程回执、替换见证和伪造程序摘要三个核对器负例均被拒绝。

真实数据库测试另覆盖：拒绝／过期／替换批准零写入；旧批准、随机值和版本重放；改正文、空签名、修改普通批准字段、跨库搬运、错误公钥、重算整链和有效签名前缀删尾；过期、隔离、撤销不回落旧版；恢复不能降低标签；重复写入者、链接、宽松权限、缺失见证及句柄存活期间文件替换。SQL 触发器中止与签名失败使事务回滚；提交后故意见证写入失败使句柄停止，显式恢复只推进见证，写入次数保持不变，旧批准仍不能重放。

SQLCipher 构建实际写入加密数据库，核对文件头及正文不为明文、错误口令拒绝、正确口令读回完整内容。空口令和不具备 SQLCipher 能力的请求均不能静默降为明文。显式传入 `None` 的合成存储仍为明文，不宣称默认加密。

## 原始失败与修复

- 首次编译的三处类型错误保留于 `check-01.log`；修正字节／摘要接口及读取方法后重新编译。
- 首轮数据库测试因临时目录为宽松权限，15 项被私有目录检查拒绝。只将合成夹具设为 `0700`，保留宽松目录必须失败的负例，未降低产品约束。
- 全仓首次回归在三语能力矩阵处失败：新增测试后矩阵尚未生成。更新生成文件后复跑，原日志 `workspace-01.log` 保留。
- 复核发现库元数据未在验签读取前限制大小，新增负例首先失败，保留 `metadata-before-01.log`。现在元数据和额外决策回执在读取正文及验签前检查；修复后重新测试，最终程序及跨进程证据另存第二批，不覆盖首批。

## 复现入口

在仓库根执行，所有输出使用新的证据目录，避免覆盖已保留的数据库：

```sh
DEVELOPER_DIR=/Library/Developer/CommandLineTools scripts/bootstrap-rust.sh -- cargo test -p guard-audit -p guard-privacy
DEVELOPER_DIR=/Library/Developer/CommandLineTools scripts/bootstrap-rust.sh -- cargo test -p guard-audit --no-default-features --features sqlcipher
DEVELOPER_DIR=/Library/Developer/CommandLineTools scripts/bootstrap-rust.sh -- cargo test --workspace
python3 scripts/acceptance/verify-memory-store.py .artifacts/m3-memory-2026-09-16/process-02 --frozen .artifacts/m3-memory-2026-09-16/frozen-02 --node node
```

保留实际跨进程原件时，对本次构建产生的 `guard-audit` 测试程序先复制归档，再设置 `AGD_MEMORY_ACCEPTANCE_OUT` 为尚不存在的输出目录，执行 `--exact 'store::memory::tests::真实独立进程重启读取撤销并拒绝磁盘篡改' --nocapture`。父测试显式调用被标为 ignored 的子步骤，因此普通测试运行不会直接启动一个缺少目录参数的孤立子步骤。
