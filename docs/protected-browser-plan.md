# 受保护浏览器任务：实施与验收方案

日期：2026-09-07。状态：首版本地工程原型，不能作为系统隔离或生产发布结论。

本轮首版已实现并完成本地验收，结果见[验收记录](protected-browser-acceptance-2026-09-07.md)。新增用户持有会话、独立 Agent 连接、断连暂停与重连；真实 Codex 与独立控制页已完成有限联合验收。整体产品以 [Agent 安全卫士可行性与可用性方案](agent-safety-viability-plan.zh.md) 为推进依据，后续阶段仍按进入条件推进。

## 目标与取舍

把“发现风险”变成可核对的请求控制：专用 Chromium 中，授权站点的普通浏览可继续，非只读请求和带查询参数的请求先暂停；独立控制页批准的只是正在等待的那条请求。使用本地无害业务服务器记录实际收到的请求，不靠弹窗或 PASS 数字推断保护成功。

现有 Chromium 扩展及邮件防护工作保持独立。首版复用扩展作为额外的 DOM 阻断层，由浏览器执行器控制请求；不恢复旧 Native Messaging 原型，不改变扩展的 block-only 语义。扩展拒绝的动作不能由控制页越权放行。

## 步骤 → 验证

1. 专用临时浏览器、准确的站点授权、有限 MCP 工具 → 实际导航、读取、点击、填写；拒绝任意脚本执行及授权外导航。
2. 暂停真实请求、独立人工确认、内存任务记录 → 拒绝/超时后服务器计数为零；批准后原始请求恰好一次。
3. 生命周期与旁路 → 页面跳转、停止任务、控制连接失效、请求重复、重定向、WebSocket、Service Worker、iframe、弹出窗口测试。
4. 可见控制页与无害演示 → 真浏览器点击完成批准/拒绝，截图检查，小屏幕检查。
5. 固定版本的回归入口与 CI → 单命令运行；失败退出非零；缺浏览器明确失败；保存机器报告和截图。

## 首版边界

- 执行器拥有自己的浏览器，不接管用户已打开的 Chrome，不复制 Cookie 或个人配置；独立配置不是系统沙箱。
- 使用固定 Playwright/Chromium 测试运行时。正式 Chrome/Edge 的安装策略及商店渠道仍单独验收。
- 网页内容与 HTTP 方法不代表真实业务意图；授权站点上的无查询 GET/HEAD 也可能存在副作用或通过路径传数据。本站点授权必须由人给出，不能声称通用付款审核或完整 DLP。
- 为保证请求可核对，首版不支持上传文件/二进制/大正文、WebSocket、Service Worker 和自动 HTTP 重定向；遇到这些明确拒绝。非 HTTP 出口、WebRTC 和进程直连没有系统隔离保证。
- 人工批准只授权提交这条已捕获的请求；拿到 HTTP 响应不等于远端业务成功。网络错误时结果未知，不自动重试。
- 任务、批准和正文仅在内存；任务结束清空待确认，临时浏览器资料销毁。本轮不提供加密持久审计。
- 控制页与 Agent 的执行入口分开。MCP 不提供批准工具、令牌或控制页地址。若 Agent 仍能使用其他本机工具，它可能绕过本执行器。

## 后续阶段与进入条件

1. 指定真实 MCP 客户端：代表性正常任务与对抗任务对比，测耗时、误阻断和其他工具旁路；本地 stdio 测试不能替代客户端接入。
2. 浏览器扩展正式通信：持久任务服务、扩展来源校验、协议版本、断连恢复、统一审计。通过后才添加 Native Messaging 权限。
3. macOS 系统边界：先确认 Endpoint Security entitlement，再实现最小文件/进程控制；验证委托进程与独立浏览器出口。未获得条件不以用户态 Hook 冒充系统边界。
4. 少量真实站点适配与发布：分别验收授权/登录、正常业务、安装升级；不得使用真实付款测试代替本地固件。
