# Browser pre-execution blocking (first GA)

[简体中文](浏览器执行前阻断.md) | [繁體中文](浏览器执行前阻断.zh-TW.md) | [English](浏览器执行前阻断.en.md)

> Conclusion: the first GA uses two **block-only** control paths on Chrome / Edge. Matching page-DOM actions are synchronously stopped; matching network requests are hard-blocked by browser static DNR. There is no in-page allow, continue, replay, or temporary-exception path.

## Two independent control paths

| Path | Current handling | Release boundary |
|---|---|---|
| Payment or transfer CTA and privacy-trap personal-data submission in an HTTP(S) frame where the browser permits extension injection | The isolated content script, injected at `document_start`, synchronously calls `preventDefault()` during window capture and stops propagation; it may render an information notice | It **cannot be released in the page**, and the original action is not replayed |
| Non-read-only request to a payment-shaped URL | The GA manifest enables static DNR ruleset `payment_shape_block` by default; the browser blocks at the network layer | No confirmation, page verdict, scope exception, or one-shot release |

The paths are independent. A DOM miss does not imply a network release: any request matching static DNR is still blocked at the network layer. Conversely, a DNR miss cannot replay an action already stopped by the DOM gate.

## In-page notice is not authorization UI

The information notice exists in an environment ordinary page DOM can influence. A hostile page can delete, cover, imitate, or alter its visible effect. Therefore:

- the notice only explains what was blocked and the capability boundary; it neither represents nor collects authorization;
- there is no “Allow once,” Continue, or Retry button, and page clicks create no authorization token;
- page-script synthetic events, `postMessage`, legacy decision/scope messages, and timeout waits cannot release the action;
- failure to display the notice does not change the completed block.

If a user understands the risk and still decides to continue, the only supported flow is through the browser-owned, trusted extension-management surface: `chrome://extensions` in Chrome or `edge://extensions` in Edge. The user must disable or remove AgentGuard there and then independently repeat the original action. The first GA has no site exception, action exception, or temporary pause button.

## Page messages are not a trust root

The legacy MAIN-world `guard-page.js` and public `window.postMessage` request/decision/scope channel have been removed. GA content scripts neither consume nor publish those public verdict messages, and static DNR has no page-writable exception. Ordinary page context and its information notice are not authorization roots.

## Exact static-DNR support surface

Rules file: `apps/extension-chromium/rules/payment-shape-block.json`.

A request is blocked only when all of these conditions hold:

1. The URL scheme is HTTP or HTTPS.
2. The request method is not GET or HEAD.
3. At least one of these URL shapes matches:
   - a **path component** starts with one of these ASCII payment markers at the documented character boundary: `pay`, `payment`, `checkout`, `charge`, `transfer`, `remit`, `purchase`, `orderconfirm` / `order-confirm` / `order_confirm`, or `confirmorder` / `confirm-order` / `confirm_order`; the path rules also explicitly accept percent-encoded bytes for core markers and `%2F` path separators;
   - the query key is `op`, `action`, or `operation`, and its value explicitly equals one of those payment markers at the documented boundary.
4. The browser classifies the request as one of the following resource types.

| Network API / behavior | DNR resource type | Current claim |
|---|---|---|
| `fetch()` | `xmlhttprequest` | Supported |
| `XMLHttpRequest` | `xmlhttprequest` | Supported |
| `navigator.sendBeacon()` | `ping` | Supported |
| Top-level HTML form navigation | `main_frame` | Supported |
| Iframe HTML form navigation | `sub_frame` | Supported |

Marker matching is case-insensitive. A marker must be followed by the end of the path/value or a non-ASCII-letter/digit/underscore character. For example, `/pay-now`, `/%70ay`, `/p%61y`, `/api%2Fpay`, and `/api?op=pay` match, while `/prepay`, `/payment_status`, and `/api/search?next=/pay` do not. The rules ship in the Chrome / Edge GA ZIP and are enabled by default; they do not depend on page code or a Native host.

## Explicitly unsupported or unclaimed

- GET/HEAD, even when the path is `/pay`;
- requests where payment intent exists only in the body; DNR does not inspect bodies;
- site-specific aliases, unlisted keywords, encoded/double-encoded/obfuscated forms not explicitly listed, and arbitrary query keys other than `op` / `action` / `operation` or unlisted values;
- WebSocket, WebTransport, and unlisted resource types;
- pages or schemes where the browser does not inject the content script, direct `form.submit()`, or script paths that emit no observed event. Automation covers the declared ordinary child-frame path, but that does not claim injection into every special frame;
- integrity, visibility, or authenticity of the in-page notice; it is only a page-influenceable information layer;
- native apps outside the browser, and first-GA support for Firefox or Safari.

## GA package and Native Messaging boundary

- The first GA ships only the shared Chromium ZIP for Chrome / Edge.
- The Firefox manifest and related source remain a future prototype. The release script rejects `--firefox`; Firefox is not packaged, submitted, or used as a first-GA acceptance gate.
- The GA manifest has no `nativeMessaging`. The store ZIP contains no Native host and claims no Native verdict, dynamic-host blocking, or local audit-chain capability.

## Automated verification

- `apps/extension-chromium/scripts/gate.test.mjs`: dangerous-action classification and pure DNR logic boundaries.
- `apps/extension-chromium/scripts/content-event.test.mjs`: real content-script event wiring remains block-only and never replays the original action.
- `apps/extension-chromium/scripts/manifests.test.mjs`: no Native Messaging in the GA manifest, static rules enabled by default, and Firefox excluded from the GA package.
- `apps/extension-chromium/scripts/package-store.test.sh`: Chrome / Edge ZIP contents and `--firefox` rejection.
- `eval/e2e-extension/run.mjs`: DOM non-execution, legacy-message non-release, DNR block-before-server, and negative non-blocking behavior in a Chromium environment.

Offline checks are necessary but insufficient. Chrome and Edge store candidates still require separate evidence for installation, upgrade, permission prompts, and real-browser behavior.
