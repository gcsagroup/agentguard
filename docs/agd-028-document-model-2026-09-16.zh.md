## 新复现的问题

首轮 `model-01` 使用前批冻结 CLI `3ac20d52…` 和相同中文英文混合图片。图片已正确解析，随后持久保存被 `CRIT-005` 拒绝，尚未进入待批准状态，更没有发送给模型。实际审计分别记录解析成功，以及记忆动作 `refuse / not_dispatched`；原因是“安装文档示例：pip install demo-package”再次命中了全内容文字规则。

018 已修正桌面被动观察的安装文字误报；它没有覆盖持久记忆这条入口。本批真实操作暴露了这一缺口，不能用之前的桌面专项或 OCR 正确率代替资料保存验收。新测试先取得 5 通过、2 失败，复现正常资料被当作安装以及原记忆契约判断被遮蔽的行为。

## 修正范围

仅在可信宿主调用 `process_persistent_memory` 时，基础文字匹配不使用 CRIT-005 判断安装动作，继续由记忆契约决定保存是否可批准。资料正文、来源和限制标签仍保留；写入仍需独立宿主批准。普通事件自报 `persistent_memory=true` 无法选择此路径，ProcessExec 也不能通过该接口冒充记忆读写。

附加规则包不使用这一排除项，因此专门限制安装资料的策略仍可硬拒；明确注入、作用域、计划、记忆契约和其它独立风险继续生效。这不是全局关闭 CRIT-005，也没有修改规则包、安装执行权限或审批期限。七项持久记忆专项修正后全部通过，包含普通安装阅读／保存、实际执行入口、自报字段、明确注入和附加策略。

## 实际模型流程

复用本机已加载模型 `Qwen3.6-35B-A3B-Uncensored-Heretic-MLX-4bit`，接口为回环地址 `127.0.0.1:8000`。本次仅发送合成资料；前后加载模型集合一致，没有启动、卸载或下载模型。三个请求各自使用新的两条消息，不携带前一个请求的对话历史；没有向模型提供执行工具。

1. 首个网关进程实际解析混合安装文档和倒置繁体图片，宿主脚本核对完整批准绑定后保存。空白图被拒绝且版本数不变。
2. 第二个网关进程重开存储，实际检索安装示例与费用。把真实检索结果及来源交给模型，得到以下回答。
3. 独立批准撤销安装资料后，第三个网关进程重新检索；新模型请求收到空结果，不包含旧安装示例。

| 请求 | 模型实际回答 | 来源与授权解释 |
| --- | --- | --- |
| 安装文档的命令示例 | `pip install demo-package` | 来源键 mixed-document-png，位置 image:1:ocr，authorized_to_execute=false |
| 繁体图片中的费用数值 | `1280.50` | 来源键 traditional-upside-down，位置 image:1:ocr，authorized_to_execute=false |
| 撤销后再次询问安装示例 | 无可用资料 | 来源与位置为 null，authorized_to_execute=false |

这是**脚本从真实网关检索后交给模型消费**，不代表模型自主选工具，不代表无法绕过的执行拦截，更不把模型声称“没有执行权限”当作安全边界证明。执行入口与独立批准继续由网关及其回归验证。输入的图片质量和内存余量限制保持前批结论。

独立只读验证从 SQLite、公开密钥、外部见证及冻结输入核对 4 条签名、76 条审计、3 个进程和 3 个模型请求。核对实际模型请求包含的是该次检索结果、来源对应已签名版本，撤销后使用新网关会话且请求不含旧示例。六类报告篡改（回答、请求、来源、撤销、会话、撤销后返回旧结果）全部拒绝。脚本不读取签名私钥，不改旧证据。
