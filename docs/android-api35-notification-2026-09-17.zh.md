# Android API 35：补授权后的持续通知与兼容性复验

日期：2026-09-17。源码基线 `174d9ab8f5ff861ce3e53c191ff3256f1238e861` 加本批补丁。Android Debug 递增为 **1.1.0-dev.11（1000011）**，包名及 APK 路径保持。固定 macOS App 024 没有构建，91 个文件及模式与原清单一致。

## 实际发现与修正

本机已有 API 35 镜像，本批使用固定对照模拟器 `AgentGuard_API35`（Pixel 7、arm64、Android 15），原 `AgentGuard_API26` 保留且未启动。先安装原 dev.10：拒绝通知权限后，观察会话能运行并正确显示“守护不完整”；在系统设置补授权限、返回 App 后，界面变为“守护中”，但系统没有持续守护通知。系统记录显示此前通知被拒绝，补授权后没有重新投递。

根因是通知只在开始会话时发送，权限回调与 `onResume()` 只更新界面状态。本批在这两个授权入口补发当前会话通知，沿用原有“会话正在运行且观察器已绑定”的检查；不创建会话、不恢复结束的会话、不重放历史风险。

新回归在旧产品代码上稳定得到 **2 通过、1 失败**，失败项正是补授权后通知仍不存在。测试同时要求已停止或观察器已解绑时不产生通知。首次使用手工 Activity 夹具运行完整测试，后续两项 Compose 测试发生空闲等待失败；保留线程和失败日志后终止该轮，不能计作完整测试。改用项目已有的 Compose 规则管理窗口后，旧产品代码仍是同一项失败，最终产品代码的完整两套测试通过，没有放宽等待期限或原断言。

## 验收工具对辅助功能的影响

首次使用默认 `uiautomator dump` 读取界面，系统停用其他辅助服务；日志在 02:40:15.300 注册 flags=0 的 UI 自动化服务，02:40:15.305 AgentGuard 因 `unbound` 安全结束会话。这是验收工具的干扰，原会话及日志保留，产品的观察器失效处理保持。

后续读取使用独立、无桌面入口的临时 Instrumentation 包，调用公开的 `FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES`，不重启被测 App。该标志允许 UI 自动化期间保留其他辅助服务，见 [Android 官方说明](https://developer.android.com/reference/android/app/UiAutomation#FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES)。读取器只安装在本轮自建模拟器，源码、Manifest、APK 和操作脚本保存在本批证据目录，结束前已卸载。未改变正式验收脚本或放宽产品权限。
