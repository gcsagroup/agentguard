# AGD-003：会话、动作、批准与执行回执契约

日期：2026-09-09。契约版本：1。对应开发任务：AGD-003；网关接线属于 AGD-006/009 的首轮实现。

## 已实现的对象

公共类型位于 [execution.rs](../crates/guard-schema/src/execution.rs)，不改变原有 `GuardEvent`、`Decision` 和 Agent 身份证明语义。

| 对象 | 用途 | 校验与边界 |
| --- | --- | --- |
| `SessionContract` | 保存宿主主体、授权范围、策略版本、覆盖类型、状态和期限 | 复用 `TaskScope::validate`；调用 `validate_active_at` 检查状态和期限。反序列化的客户端范围不能成为宿主授权。 |
| `ActionSpec` → `ActionSnapshot` | 将会话、动作、请求、工具服务／名称／版本、最终目标、完整参数、策略版本、期限、随机值和来源冻结为只读快照 | 构造及反序列化均验证。缺失关键字段、空标识符、无效时间、非对象参数、畸形随机值、重复来源和未知顶层字段拒绝。 |
| `ApprovalBinding` | 绑定一份完整动作快照与独立批准编号、随机值及期限 | 替换正文、目标、工具版本、策略、会话或请求均不匹配；批准不能延长动作期限。校验方法不认证批准者，也不消费随机值。 |
| `ApprovalRecord` | 记录控制面批准或拒绝的主体与时间 | 是审计数据，不能把客户端提交的 `approved` 或 `actor_id` 当作执行凭据。 |
| `SourceObject` | 区分观测到的来源和来源未知 | 记录读取入口、内容摘要、解析器版本和父来源；没有 `trusted: true` 权限提升字段。来源真实性由读取入口保证。 |
| `ExecutionReceipt` | 区分判决、动作是否发出、终态、副作用与证据 | 必须显式调用 `validate`；已发出动作不能记作未执行拒绝，未知结果不能断言副作用已经核实。 |

标识符使用一个经过校验的 `ValidatedId`，避免多套重复格式逻辑；其类型只保证格式，不证明身份。`Sha256Digest` 只检查摘要编码，实际摘要必须由可信入口计算。

## 结果语义

| `outcome` | 含义 | 副作用解释 |
| --- | --- | --- |
| `success` | 工具明确完成 | 不等于业务目标已经独立验收，也不必然表示发生写入。 |
| `refused` | 守卫拒绝，动作未发出 | 不允许同时填写开始时间或已观测副作用。 |
| `cancelled` | 用户停止、断连等取消原因 | 可以发生在发出前或发出后；发出后的部分副作用必须保留。 |
| `timed_out` | 等待批准或执行超时 | 发出前超时不执行；发出后超时不能推断没有副作用。 |
| `failed` | 执行器或工具明确报错 | 结合 `dispatch_state` 区分启动失败与发出后失败；后者可能已经部分写入或发送，不能当作策略拒绝。 |
| `unknown` | 动作已发出，但最终结果无法确认 | 副作用记未知；不得自动重试原动作。 |

`started_at_ms` 表示执行请求发出的观测时间，`completed_at_ms` 表示本条回执的记录时间；未知回执不声称外部操作已经结束。崩溃前后日志恢复和持久审计接线属于 AGD-010，数据结构本身不能证明它已完成。

## 不可变批准的最小调用顺序

1. 宿主取得授权范围和真实加载的策略版本，解析工具参数并确定执行后端。
2. 从最终 `ToolCall` 构造 `ActionSnapshot`，完整写入正文必须参与绑定，不能只绑定路径与字节数。
3. 对 `canonical_bytes()` 计算 SHA-256，生成独立批准编号和安全随机值，并向控制面展示目标、正文／差异及执行位置。
4. 控制面认证操作员后回传编号、动作摘要、批准随机值与选择。网关核对完整绑定、期限和单次状态，再执行同一份动作。
5. 执行前重新核对当前策略和实际目标；执行后分别记录判决与真实回执。结果不明时保留未知。

规范字节使用固定域 `agentguard.execution.action.v1` 和递归排序的 JSON；字符串、数组顺序及数字表示保持原样。这是当前 Rust JSON 契约，不是通用 RFC 8785 实现。跨语言签名实现必须使用相同版本及测试向量。

完整动作快照含正文，可能包括敏感内容。它用于内存中的执行与批准，不得直接当成长期审计日志；AGD-010 必须另行脱敏，并保存摘要与受控证据引用。

## 网关接线与未完成范围

网关新增宿主会话启动入口，客户端只能连接宿主已选的任务，重复连接不重置预算；结束后的会话需要宿主重新启动。批准使用进程安全随机数生成的会话／动作／请求／批准编号及随机值，确认协议 2 要求回传动作摘要和批准随机值。旧的只带编号批准不能放行新的绑定请求。

绑定不能单独保证文件对象、链接、解释器加载的脚本或外部服务永不变化。原生模式仍是合作式网关；最终路径复核不能消除全部检查与执行竞态。隔离模式绑定执行后端的私有工作区快照，宿主原目录回写尚需独立的差异批准和冲突检测。不能据此宣布 AGD-006/009 全部完成。

批准认证与单次状态当前仍属于活跃网关进程；持久恢复、凭据隔离、桌面统一状态机和真实客户端完整链路分别依赖后续任务。类型中可写的覆盖值不会创建 Docker、内核或系统权限边界。
