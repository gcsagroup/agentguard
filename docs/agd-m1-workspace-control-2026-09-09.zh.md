# M1 续作：差异回写与宿主会话

日期：2026-09-09。本轮承接首轮隔离工具试点，已实现完整差异复核、单次批准回写、放弃差异，以及暂停、恢复、停止。冻结网关候选通过 50 个完整本地文件任务、100 次会话循环、50 项独立安全负例和 30 分钟连续运行。**差异回写与会话后端专项通过；新版 App 原生补验尚未完成。完整 M1 尚未通过，发布仍为 No-Go。**

## 用户可以怎样使用

先按[隔离工具试点](agd-007-snapshot-pilot-2026-09-09.zh.md)为具体工作区启动网关，保留 stdio 客户端连接。计划、审计数据库和本次控制连接文件都必须位于授权工作区之外。桌面在“主动防护”的工具网关区域提供“选择连接文件”；通过系统文件选择器导入本次连接，无需读取日志或复制令牌。

连接后会显示真实会话状态、授权工作区、隔离副本位置、是否支持回写及不能回写的原因。任务继续通过 MCP 在副本内处理文件；宿主原目录只有在操作者核对并批准差异后才会改变。

1. 选择一个可回写工作区，点击预览差异。
2. 核对原目录、每项创建／修改／删除、完整前后文本、字节数、权限和恢复目录。二进制只展示摘要与大小，不声称用户已经逐字审阅。
3. 勾选已核对后应用；不接受的初稿可以“放弃本次差异”，继续让任务修改副本，再生成新预览。
4. 查看整体结果与每个文件的结果。成功回写后可以继续同一工作区的下一轮处理；旧批准不能再用。
5. 暂停会撤销当前批准并取消正在运行的工具。恢复维持原授权与副本，但更换会话 ID。停止永久结束本实例；stdio 断开也不能恢复旧实例。

当前仍需宿主先启动网关，再由桌面载入连接文件；桌面选择项目并直接启动完整 Agent 的流程没有因此完成。第三方客户端在恢复后还需携带新的会话标识，不能把专用验收客户端的成功扩展到所有客户端。

## 首版回写范围

支持既有目录内的普通文件新增、修改和删除。单文件最多 256 KiB，一次差异的前后正文合计最多 1 MiB、100 项变更；起始回写基线最多 16 MiB 正文、20,000 个对象。超过上限时明确拒绝，不截断显示后批准，也不静默跳过文件。

需要输出子目录的任务，应在启动前准备相应目录。新建／删除目录、目录权限改变、链接变化、特殊文件、未支持的扩展属性或 ACL 不在本版回写范围。隔离工具本身可以在副本内创建目录，但这不等于该目录变化可以回写。

副本初始权限会收紧到 0600／0700。回写同时保留宿主与副本起始权限：任务没有修改副本权限时，保留宿主原模式；任务确实改了权限时，差异展示目标模式。宿主被用户编辑、对象身份改变、同名文件并发创建或批准后副本继续变化，都会使旧预览失效或得到明确冲突。

回写前逐文件重用原有路径硬拒绝策略。脚本即使能在副本中生成敏感文件，也不能通过独立批准绕过宿主敏感路径或显式拒绝策略。

## 批准与取消如何绑定

操作者 HTTP 接口与 MCP 分离，必须通过独立 Bearer 认证及来源检查。MCP 没有预览、回写、放弃差异或恢复宿主会话的方法。连接文件由 Rust 控制面读取，令牌和批准随机值不进入 WebView。

预览携带完整执行契约：会话、请求、动作、策略版本、工具版本、最终宿主根、工作区 ID、完整差异、恢复目录、期限和随机值。桌面 Rust 独立验证规范字节的 SHA-256，以及外层字段与契约内容逐值一致，才保存一次可提交批准。

预览与每个操作者请求还绑定宿主收到请求时的取消代次。暂停、停止和断连立即改变取消代次，旧预览和旧排队请求不能吸收新代次继续执行。恢复也必须匹配原取消代次，较早的恢复不能清除后来发出的暂停。

| 接口 | 作用 |
| --- | --- |
| `GET /workspace/status` | 读取实例、会话、覆盖、工作区、待复核摘要及最近结果 |
| `POST /workspace/preview` | 以 `workspace_id` 创建完整预览 |
| `POST /workspace/apply` | 用 `review_id`、`review_sha256`、`review_nonce` 单次应用 |
| `POST /workspace/discard` | 用同样三项绑定放弃差异，保持任务会话继续 |
| `POST /workspace/pause` | 立即撤权，取消批准和执行，再记录暂停状态 |
| `POST /workspace/resume` | 仅从仍连接且无未知结果的暂停状态恢复同一授权 |
| `POST /workspace/stop` | 永久停止本次实例的执行授权 |

操作者请求队列和工作线程有上限。预览／回写等排队动作若超时且尚未开始，就不执行；已经开始却未取得答复时返回未知，桌面禁止自动重复回写，改为读取最新状态。暂停／停止在入队前立即撤权，即使后续排队超时或审计失败，撤权仍有效；恢复则必须先完成必要审计。

恢复后的 MCP `tools/call` 必须在 `params._meta.agentguard_session_id` 中携带新 ID，缺失或旧值均拒绝。该 ID 只是非秘密的状态绑定，不能增加授权。

## 结果、原件和故障

回写前保存持久开始记录，再执行文件操作，最后保存脱敏回执。放弃差异保存拒绝终态，不能出现执行开始或文件修改。审计写入失败后禁止新动作；进程崩溃留下的已开始动作恢复为未知，不自动重试。

原件保存在授权根外、同一文件系统中的随机 0700 恢复目录。逐项移动和发布使用排他操作，不覆盖并发新占用的目标名。恢复清单记录原路径、原件和待发布文件的对应关系及每项阶段，方便人工核对。

多文件回写不是事务。`applied` 表示全部文件经最终核对；`conflict` 表示没有已确认完成项；`partial` 表示部分已完成；`unknown` 表示文件操作或持久化状态无法确认。部分或未知结果会锁定当前会话，阻止其所有工作区的新动作与恢复，已完成项不自动回滚。

同用户进程持有的旧文件描述符、硬链接并发写入和主动目录改名没有完整内核比较交换保证。保留原件、反复校验和明确未知状态是本版的处理方式，不构成对所有宿主并发写入者的完全隔离。详细机制及平台证据见[回写引擎报告](agd-009-writeback-engine.zh.md)。
