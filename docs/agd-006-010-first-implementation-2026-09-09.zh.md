## 独立控制连接文件

隔离模式强制使用授权目录之外的 `--control-file` 与 `--audit-db`。批准令牌只写入新建的 `0600` 控制文件，不再打印到客户端日志；创建时使用固定父目录句柄和不跟随链接的独占打开，已有文件不会被覆盖。正常退出只清理仍匹配本实例文件身份的连接文件；崩溃遗留文件中的令牌随原进程失效，后续实例不能自动覆盖它。

独立连接文件当前只允许配合隔离工具模式使用。原生模式保留旧的操作员日志入口，不能保证任意原生脚本读不到宿主同一用户的批准凭据。桌面直接选择此连接文件并启动完整隔离会话尚待产品接线；不能把 CLI 已有的控制文件声称为桌面流程已经全部完成。

规则、shell 策略与计划在启动时各读取一次；同一份字节用于解析和版本摘要，避免正常编辑文件使审计中的策略版本与实际内存策略错配。

判决保存为独立的 `GatewayDecision` 记录，分类限于执行、拒绝、需要确认；规则标识只原样保留限定格式的内置标识，自定义或包含正文的标识保存摘要，即使借用内置前缀也不能原样写入。规则说明、完整正文、路径和批准凭据不进入这条记录。等待批准时进程结束，重启不会恢复该批准，也不会将判决记录当作执行开始；只有真实开始记录缺少终态时才恢复为未知。

## 故障与结果语义

真实 SQLite 故障测试通过插入冲突主键使实际持久事务失败：

1. 判决记录提交失败时，未创建待批准请求，目标文件没有创建，后续动作继续被拒绝。
2. 开始记录提交失败时，目标文件没有创建，后续动作继续被拒绝。
3. 工具已经写入而终态记录提交失败时，文件只含一次预期正文；返回 `unknown`，禁止下一动作，不重试第一次写入。
4. 网关进程在命令已启动后被强制结束，下次打开相同日志只新增一条恢复为 `unknown` 的回执，没有重发原命令。

这些证据覆盖事务错误与进程崩溃路径，不等同于已经测试所有磁盘耗尽、断电、文件系统损坏或远程服务超时组合。`failed` 与 `dispatched` 联合使用：工具无法启动属于失败且未发出，工具发出后报错可能已产生部分副作用；守卫拒绝与工具报错保持区分。
