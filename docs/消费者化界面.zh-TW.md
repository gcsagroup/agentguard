# 消費者化介面（E16）：不許把裸術語丟給使用者

產品是給人用的。這一輪改造前，介面上的真實文案是：「最近偵測：`invisible_injection, prompt_injection` · 頁面標題」、
「觸發規則：INTEL-DOMAIN」、「轉發到桌面端（Native Messaging）」、「權限引導（TCC）」，任務下拉裡是
`book_hotel`，確認彈層標題「執行前攔截」而且整層硬編碼中文。這些詞對寫程式碼的人是精確的，對使用者是雜訊。

## 改成了什麼

**1. 人話詞典是單一真相源**（`apps/extension-chromium/guard-strings.js`）。
每個 finding 種類、每個攔截規則 ID、每種執行前門，都映射成「人話標題 + 一句解釋（+ 兩個按鈕各自的後果）」，
三語齊全（en / 簡體 / 繁體）。popup 和頁內確認層都從這裡取詞。技術標識（`INTEL-DOMAIN`、`payment_cta`）
只出現在可展開的「為什麼被攔？」詳情裡，給除錯和回饋留門。

**這不是文案約定，是被測試釘住的性質**（`apps/extension-chromium/scripts/strings.test.mjs`）：

- content.js 原始碼裡每個 `kind:` 字面值，詞典必須有三語詞條（新增偵測忘配人話 → 測試變紅）；
- guard-schema `events.rs` 裡每個 `*_RULE_ID` 常數，詞典必須有三語詞條；
- guard-gate 會阻斷的每個 kind，必須有確認層文案（標題/正文/允許後果/取消後果）；
- 三個語言包鍵集合一致，中文包不許有未翻譯的英文殘留。

**2. 確認彈層（產品最重要的 10 秒）**：標題是「這一步要付款了」這樣的人話；兩個按鈕各自寫明後果；
「先不要」是視覺主按鈕 + 預設焦點 + Esc（安全的選擇最順手）；「允許這一次」做成紅字次按鈕；
語言跟隨 popup 設定（此前整層硬編碼中文）。

**3. popup 資訊架構**：第一眼是「正在守護這個頁面 · 今日：發現 X 項 · 攔截 Y 次」；最近列表人話化 + 相對時間；
攔截名單第一行是「已知的惡意網站」這樣的人話，規則 ID 收進詳情；語言/桌面端連線收進「設定」；
空狀態從「暫無偵測記錄」改成解釋性的「一切正常……遇到風險動作時會先攔下來問你」。

**4. 桌面殼子分層**：模擬注入、AX/SCK 探測輪詢、企業策略、決策原始日誌收進預設摺疊的「開發者面板」；
任務下拉給人話名（「訂飯店」，value 仍是 profile id）；「Phase 2」副標題、「TCC」「重載 Threat Intel」
「Critical Confirm」等術語全部人話化；補齊了 zh 包裡的英文殘留（如 Optional PII）。

## E17：安裝引導、無障礙、通知人話化

**引導頁**（`onboarding.html`，首次安裝自動開啟，升級不打擾）：三張卡講清它保護什麼，
一個互動示範讓使用者先見一次確認彈層——示範用的是**真渲染器 + 真詞典**（guard-modal.js /
guard-strings.js），不是截圖，詞典改了示範自動跟上；結尾交代 popup 在哪、桌面端連線是可選的、
「發現預設留在本機」。

**彈層共用渲染器**（`guard-modal.js`，從 content.js 抽出，內容腳本與引導頁示範共用）：
role=alertdialog + aria-modal + 反射的 ariaLabel/ariaDescription（不用被禁的字串屬性 API）；
開啟焦點落「先不要」，Tab/Shift+Tab 鎖在彈層內循環，Esc=先不要，關閉後焦點還原到觸發元素；
深色模式自帶完整色板（彈層浮在任意網頁上，不能借頁面的顏色）。

**通知**：標題走三語詞表；正文第一眼是規則的人話名（如「付款/轉帳確認」），引擎訊息跟在
後面，技術 ID 收進末尾括號——不再以 `[CRIT-001] …` 開頭。popup 的宿主判決記錄同樣人話化。

## E18：複審補漏

- **徽章生命週期**：開啟 popup 即清除徽章（看過了就不該繼續掛著）；Critical 暫停徽章「‖」例外，
  暫停沒解除提醒不消失。此前「!」一旦點亮永遠掛著，使用者沒有任何辦法消掉。
- **殼子詞表完整性測試**（`eval/shells-i18n.test.mjs`，進 `make check-shells`）：鍵三語一致、
  index.html 的 data-i18n / main.js 的 t("...") 引用的鍵都存在、`action.*` 動態鍵四個取值齊、
  中文無英文殘留。`t(缺鍵)` 會把 key 名渲染到介面上（E16 前 macOS 真發生過），不報錯不崩潰，
  只有這類測試或肉眼能看見。已變異驗證（刪掉 guard.task 詞條 → 兩條測試變紅）。
- **桌面時間線人話化**：第一眼是「已攔截/提醒/已放行/已記錄」而不是引擎列舉 `Block`；
  rule_id 移進 meta 行。
- **popup 可重開引導頁**（設定 → 查看功能介紹），給錯過首次安裝引導的人留門。
- **STORE.md 重寫**：舊文案還在說「只有桌面端能阻斷」（E2 之前的狀態），且權限表漏了
  declarativeNetRequest 與 notifications 的用途說明（商店過審阻斷項）。

## 視覺冒煙：`make ui-preview`

邏輯測試釘不住「使用者實際看到什麼」，所以有一個真渲染 harness（`eval/ui-preview/`）：
無頭 Chromium 渲染確認彈層（付款攔截 / 越界）與 popup（有資料 / 空 / 英文 / 設定態），
截圖落在 `eval/ui-preview/out/`（gitignore，改 UI 後跑一遍肉眼對比），同時做行為斷言：
「先不要」真的擋住頁面處理器、「允許這一次」真的重放動作、popup **可見**文字無裸術語
（`innerText` 尊重可見性——details 摺疊時技術標識必須不可見，展開後必須可見）。
斷言經變異驗證：讓 popup 洩漏一個裸 kind，兩條斷言立刻變紅。

它是**開發工具，不進 release-gate**：門禁必須在最小容器可重現，這個需要 playwright + Chromium。
真機驗收（`acceptance-runbook.md`）才是發佈證據。

## 邊界（不假裝）

- 詞典的覆蓋率測試靠**原始碼字面值擷取**（正規表示式找 `kind: "..."` / `*_RULE_ID = "..."`），不是型別系統。
  動態拼出來的 kind 它看不見——目前儲存庫裡沒有，新增時擷取正規表示式要跟著看一眼。
- popup 的「今日發現/攔截」計數來自最近列表緩衝（有筆數上限），是「今天介面上看到的」，不是稽核庫統計。
- 桌面殼子的判決日誌（開發者面板裡）仍顯示原始 `action [RULE-ID] message`——那是給開發者的，刻意保留。
- 三語文案的**品質**（翻譯地道與否）測試保證不了，測試只保證「有、齊、是中文/非裸術語」。
