# 生产事故响应手册

## 分级

- **Sev-0**：大范围安全/隐私损害、供应链或签名遭破坏、无法停止的错误高风险操作。立即停止所有扩量，启动事故指挥和法务/隐私路线。
- **Sev-1**：核心保护或审计在多个用户/渠道不可用、更新/回滚断裂、可扩大的绕过。立即冻结扩量并在值班目标时间内缓解。
- **Sev-2**：局部功能退化或显著支持影响，有安全替代路径。限制扩量，排定修复与候选验证。
- **Sev-3**：轻微、不影响保护语义的问题，进入常规队列。

## 响应流程

1. **受理**：记录 UTC 时间、发现源、候选/commit/artifact-set、渠道、影响范围；不在工单中放凭据或未脱敏 PII。
2. **指挥**：Sev-0/1 指定单一 Incident Commander，同时指定技术、运维、安全、隐私/法务和客户沟通责任人。
3. **遏制**：暂停商店/更新、停止 5/25/100 扩量，必要时关闭服务端功能开关；不删除现场或覆盖证据。
4. **缓解/回滚**：只使用已验证、可定位的产物；变更要有双人复核、影响检查和完整审计。
5. **恢复**：重跑相关 RC 门禁、渠道 smoke 和回归；不继承被事故中断的 Beta/扩量时钟。
6. **复盘**：Sev-0/1 在时间线、根因、控制缺口、客户/合规通知和跟进项完整前不关单。

## 恢复门槛

Incident Commander、Release、Security 和 Operations 必须明确同意恢复；涉及个人数据或商店声明时还必须有 Privacy/Legal。恢复不使旧 `--ga` 日志重新生效，必须在新候选上重新收集受影响证据。
