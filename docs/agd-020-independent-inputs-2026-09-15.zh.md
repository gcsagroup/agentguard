## 保留失败与范围限制

首轮 `inputs-01` 的 52 个功能用例执行后，系统 Python 触发未接受 Xcode 许可，证据导出中断；未改变许可或开发工具全局选择。`inputs-02`、`inputs-03` 改用现有命令行工具后，SQLite 3.51.0 在连接成功后的备份步骤报 `unable to open database file`。同一份源日志以本机已有 SQLite 3.53.4 备份成功；运行器改为显式 `--python` 并记录 Python／SQLite 版本，`inputs-04` 重新执行完整 52 项及全部证据导出后通过。前三轮没有升级为完整通过，原日志和原始审计仍保留。

独立核对初轮错误地直接使用 `/private/var` 路径计算网关目标摘要，第二轮误写登记事件名；按实际路径别名合同核对父目录确为同一对象，并使用真实 `approved` 事件后通过。原始核对失败日志保留，没有放宽拒绝、来源绑定或副作用断言。

当前没有可直接签发批准的 LLM 裁判入口；本批实测的是资料与 MCP 返回伪造裁判结果的权限边界。真实裁判模型是否被操纵、是否错误评价资料，尚未验收，不能用此结果声称模型抗注入。知识库阶段仍为未知，原 12 个知识场景的未运行登记未改写。

哈希链仅证明所读快照内部一致，未核验签名归属，也不保证抵抗管理员整体重写。所有批准为本轮合成操作者脚本，没有扩大为原生人工、模型自主、其它客户端或发布验收。
