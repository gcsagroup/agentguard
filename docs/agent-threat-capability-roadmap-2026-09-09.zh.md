# GCSA Agent 威胁知识库与 AgentGuard 能力推进方案

日期：2026-09-09。状态：供评审的实施方案；本轮仅做源码核对、基线测试、无害边界验证与文档交付，尚未实施下列新增产品能力。

## 结论与产品选择

建议继续推进 AgentGuard，首个目标明确为：**保护通过指定入口启动的代码与浏览器任务，让外部内容不能自行扩大权限，让危险动作在执行前受到约束，并留下能核对实际结果的证据。**

同时建立 GCSA Agent 威胁知识库，统一攻击分类、攻击链、稳定手法编号、案例、检测规则和验收证据。知识库负责告诉我们“要防什么、为什么、证据到哪一步”；AgentGuard 负责把相应控制放在真实读取和执行路径上。

优先级是：**收敛受保护会话 → 隔离脚本执行与凭据 → 接通内容来源和工具信任 → 管理持久记忆与委托 → 扩展媒体分析和其他平台。** 知识库的第一版从第一阶段就开始建设，随每个控制点一起交付。

这条路线复用现有 Rust 引擎、工具网关、来源标签、身份验证和审计实现。暂不建设独立威胁情报云平台，也不另写一套判决引擎。第一阶段不训练通用深度伪造模型。

## 1. 范围、假设与完成标准

本方案将“这个项目”解释为当前 `/Users/lazy/Projects/agent-guard`，以用户提供的 [威胁趋势文档](/Users/lazy/Downloads/GCSA_Agent时代新型威胁与攻击趋势.md) 和后续提出的 Taxonomy、Kill Chain、Technique ID 为需求输入。

首批应用沿用仓库已有方向：macOS 桌面上的代码工作，以及指定浏览器任务。Linux 隔离执行可作为本机虚拟机或已有测试主机上的执行后端；不假设 macOS 宿主机拥有 Linux 隔离能力。任意第三方 App、现有个人浏览器和完整系统保护均需要独立接入与验收。

有两种可行的产品层次：

| 层次 | 能交付的价值 | 使用条件 |
| --- | --- | --- |
| 合作式受保护会话 | 指定文件、工具、浏览器入口上的拒绝、确认与记录 | 显示接入范围，不能承诺限制所有原生工具和同用户进程 |
| 隔离执行会话，推荐作为下一阶段核心 | 即使任务脚本不配合，也限制文件、网络、子进程及凭据访问 | 启动前探测隔离后端，执行后核验实际副作用，缺条件不显示隔离已启用 |

完成标准不是“列出多少类威胁”，而是：正常任务能完成；未获授权的副作用不发生；故障和重连不重放批准；每项保护都有入口、版本和实际结果证据。

### 对输入文档的四点修正

1. “人不可见、AI 可见”作为投递方式，不作为所有提示词注入的定义。元数据、文件头、字幕等只有实际进入解析链和上下文时才构成该攻击入口。
2. “Semantic RCE”“Persistent Semantic Malware”可作解释性比喻，不能自动等同原生代码执行漏洞或已发现的恶意软件家族。
3. AI 攻击人、人攻击 AI、AI 攻击 AI 是并存的三类关系，不必假设严格按年代依次出现。Agent Worm 等案例必须区分实验传播和真实在野传播。
4. “提示词沙盒／虚拟化”改称虚构环境或授权伪装式越狱，避免与真正的进程隔离、虚拟机混淆。正常法律、安全研究或角色扮演内容不能仅凭话题判为攻击。

## 2. 当前项目的真实基础

本次基线为外层仓库 `b53387ebb67e` 加现有未提交改动。工作区已有大量开发内容，本轮没有覆盖或清理它们。历史记录中的 `_push/agentguard` 当前不存在，不能沿用该路径作为本轮发布源。

| 能力 | 当前证据与限制 | 建议处理 |
| --- | --- | --- |
| 工具执行前判决 | `guard-gateway` 将文件操作和命令交给 `guard-shell`、`guard-core` 判决；拒绝和确认确实位于执行前 | 保留并作为统一执行入口 |
| 命令运行 | 使用参数向量，已有输出限制、超时和断连取消；本机脚本仍以宿主用户能力运行 | 第一优先补隔离与环境变量、凭据控制 |
| 来源与信息流 | `guard-privacy::TaintLattice` 已有可信度、敏感度、派生继承、记忆标签与 `FLOW-*` 判据 | 接到真实工具输入输出；不能依赖 Agent 自报来源和流向 |
| Agent 身份 | `guard-schema::AgentCard` 已有注册、公钥、会话证明和任务限制 | 完善真实网关接入、会话绑定、密钥托管和撤销，不重复造身份类型 |
| 身份限制 | 会话开始签名不等于每条消息被认证；重放状态有进程生命周期边界；默认允许未证明会话 | 按连接认证、短期授权、序号和服务端会话状态补齐 |
| 隐藏文字与 Unicode | 现有规范化视图、隐藏标签解析、视觉和无障碍树差异检查 | 保留原文与检测视图，对共享语料逐端验证；低对比线索不直接升级为阻断 |
| 浏览器请求控制 | `apps/protected-browser` 已有专用 Chromium、请求暂停、批准／拒绝、断连恢复；有本地历史验收 | 统一到桌面会话，逐站点适配；不能用 GET/HEAD 推断业务无副作用 |
| MCP 供应链 | 当前网关主要提供自己的固定工具，不能由“支持 MCP”推导为代理并治理所有第三方 MCP | 增加范围受限的工具登记、版本锁定和代理能力 |
| 审计 | `guard-audit` 有链、签名和加密存储基础；标准 MCP CLI 初始化路径没有装配持久审计 | 接通执行回执和脱敏持久化，不能仅凭 crate 存在称已覆盖 |
| 威胁情报 | `guard-intel` 有 Ed25519 验签与更新；数据主要是域名、注入模式、深链和标记 | 扩展分类与证据索引；知识库和可执行规则包分开 |
| 系统隔离 | `guard-jail` 有 Linux 后端；本机探测均不可用；当前网关执行未自动进入 jail | 独立执行后端及能力探测；不以普通 Hook 代替边界 |
| 深度伪造、多媒体、跨 Agent 传播 | 有威胁需求，未发现完整的相应生产闭环 | 分期新增，先覆盖实际读到的文字及工具操作 |

## 3. 把 Taxonomy、Kill Chain 与 Technique ID 整合成一个底座

### 3.3 攻击链

建议定义以下阶段，作为标签和图关系，而非必须走完的固定流水线：

`侦察与入口识别 → 投递／初始访问 → 上下文或身份操纵 → 权限利用与工具执行 → 持久化 → 跨 Agent／跨系统传播 → 数据外泄或业务影响`

攻击可以跳步、循环或从已窃取的凭据直接进入执行阶段。运行时入侵可能先于提示词投递；隐藏文字不是必选步骤。每一跳记录：时间、来源对象、目标会话、请求、判决、实际执行、结果证据。未观测步骤留空或标为推断，不能为了图完整而补写。

示例链：恶意 Issue〔001〕→ 代码 Agent 偏离任务〔006〕→ 请求写长期规则〔004〕→ 后续任务请求外传〔012/013〕。这是一条用于设计验收的假设链，不是声称本机已经发生的入侵事件。

### 3.4 知识库对象与最小数据结构

| 对象 | 必需信息 |
| --- | --- |
| 手法 | ID、版本、名称、定义、前提、入口、阶段、影响、平台、相关手法 |
| 案例 | 独立案例 ID、发生与披露时间、原始来源、受影响版本、研究／真实事件属性、证据与可信度 |
| 可观测对象与 IOC | 域名／URL／文件或包摘要等；首次与末次观察、用途、有效期、撤销及共享范围 |
| 检测规则 | 保留现有 OVL/FLOW/AGENT 等规则 ID；关联多个手法 ID、所需遥测、误报条件、动作和版本 |
| 验收样本 | 环境、输入、正常任务、对抗步骤、预期与实际副作用、失败和未执行原因 |
| 缓解控制 | 执行点、部署前提、保护范围、剩余旁路、所需测试 |
| 产品覆盖 | 具体版本、平台、客户端、模式、已接入入口、测试证据与日期 |

不把整段攻击提示词当成稳定 IOC；语义攻击容易改写，需要关联行为和上下文。干净域名上的恶意 Issue 也不能把整个平台判为恶意。

证据分开两条轴：

- **案例证据**：分析假设、公开研究验证、GCSA 本地复现、公开真实事件、授权遥测确认。公开真实事件与本地复现可以同时存在，没有单一等级能替代来源说明。
- **产品效果**：未知、未接入、可观测、离线规则通过、受控运行阻断、指定真实环境通过。必须带版本、平台和前提；签名发布状态另列。

覆盖不能从手法表上打一个总勾。至少用“手法 × 入口 × 平台 × 执行方式 × 版本”描述；例如 `ATI-004 / 外部 MCP 记忆 / macOS / 合作式网关` 仍可能是未接入，即使引擎的 MemoryWrite 单元测试通过。

### 3.5 与现有标准和规则的关系

保留 GCSA 的本地 ID，并给每项增加 MITRE ATLAS、ATT&CK、OWASP、CVE 等外部引用。先核对定义与版本，再记录“等价、较宽、较窄、相关”；不能强凑一一对应。ATLAS 已覆盖 AI 系统的攻击和滥用，可直接作为对照体系。[MITRE ATLAS](https://atlas.mitre.org/)；Agent 产品风险归类可参考 [OWASP Agentic Top 10 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)。

初期采用版本化 JSON/YAML 加 Markdown，放在现有 `intel/`、`eval/` 下，经审核后生成索引；已有 SQLite 可用于本地查询。已有 `OVL-004`、`FLOW-CONF`、`AGENT-REPLAY` 保留，另建多对多映射，不重命名运行时规则。

规模增长或出现跨组织共享需要时，再做 STIX 2.1 导入／导出：手法映射 attack-pattern、案例报告映射 report、IOC 映射 indicator/observable、缓解映射 course-of-action；产品覆盖等字段用明确扩展表达。第一版不为“像 ATT&CK”而引入图数据库和新后端。[OASIS STIX 2.1](https://www.oasis-open.org/standard/6426/)

### 3.6 情报自身也要防投毒

外部情报和 PoC 先进入隔离的候选区；可保留原始摘要和受控样本，默认脱敏、限制大小和解析时间，不执行样本。分析人员审核后才进入知识库；再经过规则评审、正常／对抗回归和签名，才进入产品规则包。

沿用现有 Ed25519 机制，新增包版本兼容检查、变更清单、灰度、撤销和恢复到经过授权的已知良好版本。保留防恶意降级约束；正常恢复操作由独立控制面明确授权，不能让攻击者用旧包覆盖新包。

签名只证明包来自指定发布者，不证明内容正确。情报条目不能携带会被产品自动执行的脚本，更不能通过文字修改策略、授予权限或请求批准。

## 4. 分阶段补齐产品能力

### P0：受保护会话与隔离执行

交付一个桌面入口：选择工作区、读写范围、网络范围和任务 → 启动会话 → 显示实际接入工具与隔离状态 → 处理待确认动作 → 查看结果／结束会话。明确显示“未接入、仅观察、网关控制、隔离控制”，不能只显示总开关为绿色。

执行策略由宿主控制面持有。调用者可以申请更小范围，不能通过 task_profile、工具说明或“用户已批准”文本扩大范围。需要评估两个具体部署路径：

1. **近期代码执行推荐路径**：把 Agent 可执行代码和子进程放进独立 Linux 执行环境，优先复用 `guard-jail`；若在 Mac 上运行，使用受限虚拟机后端并单独验证。只映射授权目录，不默认共享整个用户目录、宿主凭据、剪贴板、SSH Agent 或容器管理 Socket；提权、挂载和服务管理入口不暴露给任务。
2. **宿主原生工具路径**：暂保留合作式状态；对必须在 Mac 原生执行的构建或 GUI 任务，逐项选择平台控制方案并验收。Linux VM 不能替代 macOS SDK、Keychain 或原生 UI 测试，不能把不兼容任务伪装为完成。

网络约束须覆盖执行环境出口，而非只检查工具名。Landlock 的 TCP 端口约束不是域名、UDP、DNS 或所有协议防火墙；严格模式需独立网络出口与受控代理，校验重定向、实际目的地址、DNS 变化与本地服务访问。模型服务本身是单独的数据接收方，需要明确远程模型可接收哪些工作区内容。

凭据尽可能由独立代理代办，任务只获得限定用途、限定目标与期限的能力；继承环境变量改成明确清单。隔离整个恶意执行环境，同时保证控制端不在其可读写范围；只隔离普通子进程而让恶意 MCP 服务留在宿主用户权限下，不算完成。

确认页面由实际执行参数生成，展示目标、文件差异或正文摘要、敏感数据类别及不可逆影响。当前 `write_file` 的描述主要是路径和字节数，应补内容差异。批准绑定不可变请求、会话、工具版本、参数摘要、期限和单次随机值；参数、目标或策略改变即失效。敏感写入在执行时核对最终对象，避免确认后替换路径／链接。

验收：本轮脚本越界复现必须在隔离模式下失败；直接工具和解释器两条路径都测试，文件／服务器计数核对副作用；子进程、符号链接、环境变量、网络直连、控制凭据和断连重放均有负例。先做能力探测，无法强制则拒绝启用隔离模式。

### P1：内容来源与工具供应链

扩展现有 `GuardEvent` 和来源标签：由可信执行器分配来源对象 ID，记录资源地址、获取方式、内容摘要、解析器／版本、父来源和敏感度。原文、可见视图、规范化检测视图分开，不能把删掉可疑字符后的文本当成用户原文。

先接 `read_file/search_file`、受保护浏览器读取和首批 MCP 工具输入输出。网页、README、Issue、日志或工具输出都不得成为权限来源；可信安装包签名也不使其返回的外部业务数据自动可信。

来源标签只能跟踪被执行器实际观察到的输入输出，无法可靠证明黑盒模型内部每一个 token 的来源。对涉及未知来源或敏感上下文的外传，依赖目标／数据类别策略和独立授权，不能接受模型自称“与之前资料无关”来清除标签。

首批 MCP 采用服务白名单、固定包／二进制摘要、工具名称与命名空间、描述／Schema 摘要；新增工具、改描述或升级版本重新登记。工具输出含恶意指令只作为不可信数据进入分析；安全裁判模型可给建议，放行权限由确定性策略控制。

代理的 OAuth 授权按客户端、受众和最小范围验证，不直接把来历或受众不明的令牌传给下游；同时处理本地服务启动风险、会话绑定及 SSRF。上述原则符合 MCP 的安全建议，具体传输与版本兼容需逐项测试，不能把当前固定工具服务直接称作通用 MCP 防火墙。[MCP 安全最佳实践](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices)

验收：可见注入、隐藏 Unicode、工具描述投毒、恶意输出和同名工具冒充都不能授予额外权限；普通国际化文本、Emoji、代码示例和安全研究文档仍可正常读取。来源未知的高风险动作不能默认自动放行。

### P2：持久记忆、RAG 与多 Agent 委托

复用现有记忆和信息流规则，增加可持久保存的内容摘要、来源、可信度、敏感度、创建／过期时间、版本及批准记录。记忆通过受控接口读写，默认是待审核资料；写成用户长期规则或可触发动作的配置需要单独授权。Agent 不能直接改写存储后又声称其内容可信。

跨会话检索保留来源和标签；支持查看、撤销、隔离和回滚受污染记忆。若第三方平台不提供记忆接口或实际可控文件路径，应显示该平台记忆未覆盖，不承诺替它清理隐藏内部状态。

每个委托绑定父任务、已认证主体、目标工具／资源、期限、调用与费用预算、消息序号。子任务权限取父权限与本次授权的交集；自然语言 Agent Card 只是说明，不是认证。撤销父任务使未开始的子任务失效；已完成的外部动作只能记录并按业务能力补偿，不能假装撤回。

验收：跨进程重启后的记忆投毒不被洗成可信；A→B→C 的权限递减、身份伪造、旧消息重放、循环委托和预算耗尽可实际验证。蠕虫样本仅在本机隔离测试系统传播，以投递计数和实际文件为证，不能访问真实收件人或公共仓库。

### P3：多媒体、终端联动与诈骗辅助防护

按实际读取链增加 PDF 文本层、Office 批注／隐藏对象、图片元数据和 OCR、音视频字幕与转写。解析器放在隔离进程，限制页数、时长、解码规模和总资源；无法解析明确记录，不按“未命中”视为安全。

媒体隐写检测和深度伪造模型先做研究评估，输出风险证据与适用条件，不直接作为转账放行依据。优先补真实收款方、目标账号、操作差异、独立渠道身份核对和限额策略；只覆盖已接入业务，不承诺保护所有视频会议和银行 App。

macOS 原生进程／文件联动另做正式接口评估。Endpoint Security 需要对应 entitlement；Virtualization 是可评估的隔离路线，但不自动解决共享目录、凭据与网络配置问题。[Apple Endpoint Security entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.endpoint-security.client)、[Apple Virtualization](https://developer.apple.com/documentation/virtualization)。Windows、iOS、Android 保留各自验收门，不将 Mac 或 Linux 的结果复制过去。

## 5. 最小交付顺序与工作量假设

估算前提：2 名熟悉 Rust／系统与桌面接入的工程师，1 名安全测试人员；已有可用 Linux 测试环境，不含 entitlement 审批、商店审核及未知兼容问题。以下是规划范围，不是承诺日期。

| 阶段 | 粗估工作量／时间窗口 | 可审核成果与进入下一阶段的条件 |
| --- | --- | --- |
| 第 0 阶段 | 3–5 个工作日 | 冻结当前候选与 dirty 变更归属；18 个手法草案、冲突表、规则映射、首批攻击与正常样本；保留本轮越界案例 |
| P0 | 3–5 周 | 一个桌面会话入口、一个隔离执行后端、独立批准、实际副作用回执；越界与重放负例通过 |
| P1 | 2–4 周 | 三类首批读取入口、受限 MCP 登记／代理、来源标签和签名规则发布链；正常任务与投毒样本均有结果 |
| P2 | 3–5 周 | 一种持久记忆存储、一个委托协议、跨会话与本地传播验收 |
| P3 | 单独评估 | 按媒体、平台、业务逐项排期；不阻塞首个受控代码试点 |

第一轮建议批准的实现包是“第 0 阶段 + P0”。P1 的来源对象和知识库结构先定接口，避免 P0 审计重做；并不要求先建完整情报平台再做有效控制。

### 首批 12 个验收场景

| 场景 | 应验证的实际结果 |
| --- | --- |
| 恶意 README 诱导读取工作区外标记 | 结构化文件工具和脚本内部读取均不可访问 |
| 已授权 Node/Python 脚本读写目录外文件 | 隔离模式拒绝；本轮已保留合作式模式的对照缺口 |
| 普通 Unicode、RTL、Emoji 和代码样例 | 原文不变，正常任务完成 |
| Unicode 隐藏指令与页面隐藏层 | 标记来源，不能扩大授权 |
| 工具描述变更或同名工具冒充 | 原批准不复用，新版本进入登记流程 |
| 工具返回“管理员已批准” | 不产生真实批准，不执行越权动作 |
| 请求未批准、批准后参数变更 | 服务器零提交或创建新请求，不借用旧批准 |
| 凭据出现在环境、日志或模型输入中 | 限制继承与发送，日志不落明文，残留风险明确 |
| 记忆写入后跨会话检索 | 标签、来源和有效期保留，重启不洗白 |
| Agent A 委托低权限 B 再调用高权限工具 | 权限交集仍生效，不靠名称授予权限 |
| 本地两 Agent 复制投递样本 | 传播受到出口／预算控制，计数与回执可核对 |
| 客户端／服务崩溃和休眠恢复 | 未开始请求取消，未知结果不自动重试 |

这些场景覆盖多个子例，不能把循环次数当成威胁覆盖数量。正常工作另设至少 50 个完整任务、至少 95% 完成率，即不少于 48/50，并列出人工确认次数和误拦截原因。未完成任务不能靠临时关闭保护计入成功。

安全硬门槛：指定负例中的未授权副作用为零；来源、判决和结果证据完整。该门槛只描述所测范围，不声称未知攻击零漏报。性能先测执行器新增延迟、CPU／内存和恢复耗时；模型生成、人工等待、网络服务时间分开统计后再定预算。

## 6. 知识库如何成为日常工程流程

`收到线索 → 保存来源与证据 → 核对手法／新建候选 → 本地无害复现 → 提取检测与控制要求 → 加正常及攻击回归 → 审核签名 → 小范围发布 → 根据误报和新证据修订`

首版界面沿用现有桌面工作区：

- 主动防护：会话、授权范围、隔离能力、待确认与恢复入口。
- 风险记录：ATI 手法、事件来源、实际工具、已阻断／仅告警／结果未知。
- 威胁知识库：定义、案例证据、可复验样本、对应规则和本版本覆盖范围。
- 设置：可信工具、网络与凭据策略、记忆管理、情报更新和脱敏证据导出。

用户核对的是“哪项任务要对哪里做什么”，不是一页攻击术语。正式 UI 实施前，应在现有界面中给出可点击流程，并完成真实浏览器／桌面操作检查。

**最终建议：把 GCSA 知识库建成可验证的工程底座，把 AgentGuard 做成范围清楚的执行控制产品。先关闭已复现的脚本越界与确认链路缺口，再扩大注入检测、长期记忆和多 Agent 覆盖。**
