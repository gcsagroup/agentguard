# AGD-028：固定 App 的媒体预览与原生保存

日期：2026-09-16。固定 App 为 **Ver 2.1（021）**。本批完成原任务要求的小范围接入：宿主显式配置的文档网关可以在固定 App 中展示正文、来源和解析缺口，操作员核对后批准或拒绝保存，重开后仍可读取原记录。音视频只列独立工作量估算。本项不扩大为所有媒体可检测、内置模型表单已启用记忆或发布通过。

## 用户可见的变化

在“主动防护”导入宿主生成的连接文件后，资料保存请求首先显示完整提取正文、来源文件、本次提取范围、未覆盖内容和空白位置。部分 PDF 明确显示“仅部分内容可读取”及 `page:2`，不会因为第一页有结果就把整份文件记为安全。OCR 始终提示可能漏字、误读；原始记录、解析依据及完整动作绑定仍可展开核对。

历史版本和隔离／恢复／撤销预览使用相同的可读展示。正文只通过文本节点呈现，未知结构保留完整原值并提示无法判断。换请求、到期、断连和重新接入均不能沿用上一条批准勾选。资料保存确认不批准其中出现的命令。

## 原生操作与误报修正

通过 Computer Use 操作准确 021 App；使用合成工作区、真实 CLI 和既有离线解析镜像，没有用户业务资料。脚本发起调用和读回结果，**批准／拒绝由 App 提交**，不是用户亲自操作，也不是模型自主调用。

| 操作 | 可见结果与实际存储 |
| --- | --- |
| 保存含 `pip install demo-package` 的图片 | 展示正文与 `image:1:ocr`；核对后新增 1 条记忆，不触发安装软件的 CRIT-005 拒绝 |
| 拒绝倒置繁体图片 | 拒绝无需勾选批准；调用未派发保存，条目总数保持 1 |
| 保存部分 PDF | 展示第一页正文及第二页空白缺口；批准后条目总数为 2 |
| 关闭、重开网关并重新接入 | App 显示准确两条记录；安装示例、来源、版本及解析限制保持 |
| 空白图片 | 返回无可保存正文，不新增记录；已保存安装资料仍能被检索 |
| 同包重启 App | 021 页脚正确；辅助功能、屏幕录制均继续显示已授权，未重置或重新绑定权限 |

首轮 `native-03` 虽完成保存流程，但安装资料的确认说明还附带 `FW-TEXT-ANOMALY oversized_token ×2181`。定位发现，`judge_memory` 把完整压缩参数作为检测文本，结构字段拼出了 2,181 字符的词元，实际正文最长词元只有 19；原门槛为 2,048。新增对照修正前失败，保留失败记录。

修正仅改变记忆判决的文本视图：已知资料的内层 JSON 展开，字段间保留空白；正文、来源及其他字段全部继续参与检测。未知格式仍保留原值，批准摘要、原始草稿和存储字节不变，没有提升异常阈值。实际超长正文、超长来源字段和明确注入仍被检测。固定 App 接入新冻结 CLI 后，`native-04` 重新完成整套操作；三份普通资料的确认只显示必要的 PRIV-004，附带误报消失。

最终独立读回验证 **3 条签名存储记录、48 条执行审计、2 次批准、1 次拒绝、2 个网关进程及 213 项冻结 CLI 输入**。对改正文、来源、动作目标、拒绝计数和重开会话的五类副本均拒绝；原数据库未改写。首轮证据与最终证据分别保留，不能混用候选身份。
