# AGD-023：经认证主体与权限递减的委托契约

日期：2026-09-16。状态：已完成下述当前隔离文件委托范围。基线 `e56695d`，F13 继续暂缓未验收。

## 目标与取舍

完成一个真实网关委托协议，绑定经认证的主体、父子会话、目标、权限、期限和消息序号。子权限必须为父授权、本次请求和接收主体宿主上限的交集，旧消息不能跨主体、会话或重启复用。源代码存在、单元测试和签名成功均不能代替真实执行后的文件与审计核对。

首个执行接入复用隔离工作区的结构化文件读取、写入和删除工具。权限列出具体文件，不使用隐式通配授权；任意 shell、浏览器、第三方 MCP 与记忆工具不通过这个协议自动获得权限，后续扩展须另有可执行的目标约束。启用委托的 MCP 连接仅发布和接受签名委托入口，拒绝普通工具调用，避免代理绕过子权限。独立宿主控制面仍需自己的私有凭据，委托签名不提供批准权。

宿主配置钉住主体公钥和权限上限，主体的签名由隔离任务之外的宿主代理完成。网关持有单独的授权签名密钥并签发短期委托；每条操作消息另由实际发送主体签名，授权对象本身不充当可转用的 Bearer 凭据。主体名称和自然语言 Agent Card 不提供认证能力。

新网关进程生成新会话身份，不恢复旧委托；序号按每个子会话严格递增，验证失败不能跳过或推进序号。通过认证的操作在派发前消费序号，拒绝或结果未知也不允许重放。跨重启继续任务需重新授权，不能用内存重放窗口宣称旧授权可安全恢复。

深度、分支原子预算、调用／输出／可测费用限制和父撤销联动属于 AGD-024；本项仅设置实现所需的有界消息和表容量，不把这些容量上限冒充预算治理。原生入口归 AGD-026。

## 步骤与完成标准

1. 契约与签名：固定版本域、字段和大小限制；篡改每个绑定字段、伪造主体、弱／公开夹具密钥及签名格式均拒绝。
2. 权限交集：A→B→C 不能扩大文件或操作权限，接收主体上限也参与交集；目标或会话替换无效。
3. 网关接线：必须经过原有工具登记、路径检查、来源、独立批准与持久审计；签名密钥／配置不进入隔离工作区。
4. 真实实操：复用同一个已有 Docker 镜像，核对获准文件操作、越权零副作用、重放零额外操作、等待期间过期和跨进程旧授权拒绝。
5. 文档与回归：保留首败与原 127 文件；更新计划、CHANGELOG、证据索引并提交。固定 015 App 本批不重建。

## 使用约定

在原隔离 CLI 启动参数上添加 `--delegation-config /绝对路径/宿主控制/delegation.json`。必须同时配置 `--isolation-image`、`--audit-db` 和 `--control-file`。配置和授权私钥均为宿主所有的普通单链接文件，权限为 0600；私钥父目录为 0700，配置、密钥、审计和控制文件不得相互覆盖或位于任务读写目录内。

配置字段如下；公钥和私钥都必须由宿主生成，不能使用仓库公开夹具密钥：

| 字段 | 含义 |
| --- | --- |
| `version` | 固定为 1 |
| `authority_id`、`public_key`、`signing_key` | 宿主授权器标识、公钥小写十六进制、私钥文件绝对路径；私钥文件为 32 字节小写十六进制 |
| `root_subject_id`、`target_id` | 起始认证主体、此次委托树的固定目标标识 |
| `lifetime_ms` | 根授权有效期，1～3,600,000 毫秒 |
| `principals` | 最多 32 个不重复主体；每项包含 `subject_id`、独立 `public_key` 和 `permissions` |
| `permissions` | 四个必填有序列表：`read_files`、`write_files`、`delete_files`、`delegate_to`；空列表即无权限 |

文件列表为具体 POSIX 绝对路径，总计最多 64 项；拒绝 `..`、重复分隔符、反斜线、控制字符和重复项。不同操作独立，写入不隐含读取或删除。macOS 的 `/private/var` 会在现有执行器中映射为 `/var`；配置和签名消息建议统一使用执行器的规范路径。授权器还会按真正父工作区目录过滤文件上限。

`gateway/stats` 返回宿主公钥及当前 `root_grant`。客户端先验签，再由隔离任务外、持有对应主体私钥的宿主代理签署每条 `delegation_send` 消息。消息由 `message`、`command`、`signature` 组成；头部包含版本、宿主／子会话、授权 ID／摘要、主体、目标、从 1 开始的严格连续序号、签发／过期时间及操作摘要。单条消息最多有效 120 秒，且不得超过授权期限。序列化使用递归 UTF-8 键排序 JSON；授权、操作、消息分别使用 `agentguard.delegation.grant.v1\0`、`agentguard.delegation.operation.v1\0`、`agentguard.delegation.message.v1\0` 域前缀。

`command.operation` 支持 `delegate`、`read_file`、`write_file`、`delete_file`。委托命令列出接收主体、请求权限和期限；其它命令列出具体文件，写入另含最多 64 KiB 正文。子授权回执包含宿主签名，但调用时仍需子主体自己的消息签名。端到端可运行示例见[验收程序](../scripts/acceptance/agd-delegation.mjs)，它为每条消息启动独立宿主签名进程，不向任务传入私钥。

原会话的路径事前授权可以满足普通文件操作的确认要求；命中明确 `require_confirm` 规则时仍需独立 HTTP 批准。批准绑定完整动作、实际签名主体／会话和消息摘要。验收仅对自有 `output.txt`、`late.txt`、`hardlink.txt` 追加确认规则，不能由此宣称默认策略对所有写入都逐次询问。宿主回写仍需独立全文预览与批准。
