# AGD-017 本地服务的产品调用与恢复

日期：2026-09-15。状态：本地 stdio 产品路由已实现并通过真实 CLI／Docker 实操。AGD-017 仍进行中，远程测试服务、JSON／SSE、令牌和 SSRF 验收尚未完成；原 32 项计划不变，F13 暂缓未验收。

## 实际可用的入口

`agentguard-mcp --mcp-service-config <宿主配置文件绝对路径>` 加载最多 4 个本地 Node 服务。必须同时配置既有隔离镜像、执行审计数据库和独立宿主控制文件；服务配置和恢复索引也必须位于任务授权目录之外。没有此参数时，既有工具入口保持原行为。当前支持已验证的 Linux／macOS 宿主，不开放原生非隔离第三方程序。

配置格式如下。服务包须预先准备好，启动器不执行安装命令，不下载镜像：

```json
{
  "version": 1,
  "services": [{
    "service_id": "official-filesystem",
    "namespace": "filesystem",
    "package_path": "/绝对路径/服务包",
    "package_id": "official-filesystem",
    "package_version": "2026.8.31",
    "entrypoint": "node_modules/@modelcontextprotocol/server-filesystem/dist/index.js",
    "arguments": ["/绝对路径/已授权工作区"]
  }]
}
```

首次启动会冻结包并真实发现清单。发现沿用授权副本的目标路径，但这些路径全部挂载空只读目录；初始化代码不能借发现阶段读写任务数据。发现完成、Schema 可执行且精确容器已经清理后，清单进入独立登记复核。配置本身不代替认可；认可后的工具才出现在 `tools/list`，例如 `mcp__filesystem__write_file`。

模型请求必须携带当前宿主会话绑定。第三方工具的参数只作为数据，不能指定宿主命令、镜像、挂载、服务包或批准凭据；手工提交一份同名清单并认可，也不能创建实际派发来源。服务的 `readOnlyHint` 不减免运行批准。

## 一次批准对应一个进程

实际调用依次完成：核对宿主状态、真实配置和当前登记 → 校验参数 → 准备运行身份 → 引擎判决及持久判决记录 → 独立动作批准 → 持久开始记录及恢复索引 → 实际启动 → 再次握手并完整比较清单 → 发送工具调用 → 校验返回 → 关闭并核实容器 → 来源检测和持久终态。

批准绑定完整参数、包与执行摘要、实际挂载范围、预分配容器／服务会话、工具登记代次、宿主会话、策略版本、来源及期限。批准展示参数原文的 JSON 转义形式和授权工作区；包括服务初始化阶段可能产生的副本修改。执行事件按一次 `ProcessExec` 进入现有计划预算，关键动作的硬拒绝不会转成可批准。

准备阶段不启动下游进程。未批准或准备后包字节改变时，不进入实际启动；一次准备只能启动一次。实际 `spawn` 以及每次非阻塞管道写入都在撤权共用锁内重新核对当前许可和工具登记，锁不会覆盖等待响应。暂停、停止或登记撤销后，旧许可不能继续派发。

工作区执行器被借用至服务退出，主处理循环也等待容器清理后才处理预览和回写。服务只能修改授权副本；宿主原件仍需要独立预览和回写批准。工具返回成功仅表示收到符合协议和输出定义的成功响应，业务效果仍以实际读回和工作区差异核对。

## 失败、内容与重启

未启动的拒绝明确记为未派发；一旦启动服务，初始化就可能有副作用。之后超时、断连、清单变化、返回结构错误或清理不能确认，保留结果未知，不自动重试。清理未知时冻结包保留，启动器和共享副本拒绝新动作。

服务的完整返回 JSON，包括文本、结构化内容和下游 `_meta`，在添加宿主回执前进入 AGD-015 内容检测及来源记录。下游元数据保存在宿主回执的 `downstream_metadata` 数据区，没有指令或批准权，不能覆盖实际结果与来源。执行日志继续只保存身份和摘要，不保存工具正文、参数正文或批准凭据。

审计数据库旁增加 `.mcp-runs.jsonl` 私有恢复索引。索引持有独占写锁，要求当前用户所有、非链接、单硬链接和私有权限；创建及记录同步到磁盘，限制为 1 MiB。发现进程和有数据进程都在启动前登记精确随机容器名、服务会话和镜像，终态记录核实清理。

重启发现未结束记录时，先查询原精确容器；存在则同时核对容器名、镜像及宿主设置的会话标签，之后才删除并再次确认不存在。记录 `recovered_unknown`，不重放工具调用。索引损坏、写入失败、身份不匹配或清理未知时，不启用新服务。中断留下的冻结包和旧工作区副本不自动删除，保留给恢复核对；该索引不是新的完整审计链，也不代替执行日志的未知终态。

## 首批明确限制

- MCP 固定为 2025-06-18，本地 stdio、串行调用、最多 30 秒；请求、返回及诊断字节上限沿用传输组件。分页、后台订阅、服务端请求、图像／音频及资源型结果仍明确拒绝。
- 参数与成功的结构化结果使用 `jsonschema 0.51.0` 校验。关闭库的文件／HTTP 获取特性，并安装拒绝全部外部获取的实现。首批接受内联非递归 Schema；引用、资源身份、自定义词汇及未支持方言拒绝，不静默跳过。Schema、输入和输出还有深度／节点上限，正则编译大小和回溯次数受限。
- 支持声明的 Draft 7、2019-09、2020-12；未声明时使用该库默认的 2020-12。未知格式和无效 Schema 拒绝。官方 Filesystem 的全部 14 项定义完成编译；实际调用覆盖 `write_file` 和 `read_text_file`，其余工具不计为已调用验收。
- 本次交付是源码和 CLI 后端，不包含桌面服务配置界面，也没有打包或替换准确 Ver 1.0（010）App。

## 验证与失败记录

```sh
scripts/bootstrap-rust.sh -- cargo build -p guard-gateway --bin agentguard-mcp
node scripts/acceptance/agd-mcp-proxy.mjs \
  --out /绝对路径/全新验收输出 \
  --package /绝对路径/已准备的官方Filesystem包
```
