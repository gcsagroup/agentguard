## 1. 目标、假设与完成标准

目标是判断 Linux 后端在本机是否真实可用，并给网关一个可以落地的最小执行协议。测试只使用临时工作区、合成秘密标记和本地 TCP/UDP 接收器。

假设：宿主控制进程与 Docker daemon 可信；攻击内容运行在指定新容器内；宿主操作凭据、批准凭据、SSH Agent、Keychain、浏览器资料和 Docker Socket 不传入容器。宿主已经失陷、Docker VM／内核逃逸，以及容器外客户端原生工具旁路，均不在此次后端候选的通过范围。

完成标准：正常读写实际产生预期输出；目录外标记没有被读出或改变；子进程继承边界；网络测试接收器没有收到未授权消息；资源限制实际生效；超时清理后代；不影响既有业务容器。

### 现有 guard-jail

[追加真实内核差分验证](../eval/out/AGD-002/20260909T205531-21d81138-jail/report.json) **9/9 通过**：直接读取授权外测试标记的对照成功，Landlock 下读取／写入／符号链接／后代读取失败；同一容器的回环 TCP 对照成功，Landlock 空端口天花板下 connect 与 bind 返回权限拒绝。这里不依赖 Docker 断网导致外部连接失败来推断 Landlock 生效。

[离线 Linux 测试报告](../eval/out/AGD-002/20260909T205032-38892dec-jail/report.json)：**51 项通过、1 项忽略**；[实际探测](../eval/out/AGD-002/20260909T205032-38892dec-jail/probe.stdout) 确认选择 Landlock。9 项现有集成测试在该环境执行，授权内写入成功、授权外写入失败。

区分证据归属：系统目录写入失败可能同时来自 Docker 只读 rootfs，不能单凭这条归因 Landlock；mount namespace 实际不可用，含内部跳过的测试包装器不能算 mount namespace 内核通过。该构建使用本地 Rust 1.91.1、原 Cargo.lock、离线缓存，不是仓库钉住的 Rust 1.95.0 发布候选。

源码复核也确认：Landlock 默认允许读取 `/etc`、`/proc` 等运行时路径和目标程序所在目录；mount namespace 后端没有实现同等读天花板；Landlock 网络约束只覆盖 TCP connect/bind 端口。**建议用 Docker VM 隔离宿主数据、进程和默认网络，guard-jail 作为 Linux 内的额外收缩层。**

## 4. 给网关的最小接入协议

采用宿主控制进程创建一次性工作区快照，再把快照挂入新容器。所有文件工具与脚本执行在同一受限环境内；不要让文件工具留在宿主跟随路径、只把 run_shell 放进容器。

可信宿主输入必须固定以下内容：

| 字段 | 约束 |
| --- | --- |
| image_id | 完整本地 `sha256:` ID，启动时 `--pull never`；不可用即拒绝，无原生回退 |
| container_name | 控制面生成随机名称，不接受 Agent 自报名称，不操作其它容器 |
| argv | 参数数组；不得通过 shell 字符串拼接再次解释 |
| cwd | 必须位于容器内授权的快照路径；不能由任务名重新获得更宽路径 |
| mounts | 只挂宿主新建的私有快照；只读／可写分开，禁止 HOME、根目录、控制 Socket 等宽挂载 |
| environment | `/usr/bin/env -i` 清空镜像及宿主环境，再给固定 PATH、HOME、TMPDIR、LANG 等清单 |
| control_file | 位于任务授权之外的新绝对文件；仅宿主读取，0600，不经过 Agent stderr／stdout。已有文件拒绝覆盖，崩溃后改用新文件名 |
| limits | 墙钟、输出、进程、内存、CPU 限制由宿主固定，Agent 参数不能覆盖 |
| result | 记录真实退出码、截断、超时、取消、容器清理结果及快照路径；清理或最终结果不明时记未知 |

已实际运行的参数骨架：

```text
docker run --name <随机专用名> --pull never
  --network none --read-only --user <宿主非root uid:gid>
  --cap-drop ALL --security-opt no-new-privileges:true
  --pids-limit 32 --memory 128m --memory-swap 128m --cpus 1
  --tmpfs /tmp:rw,nosuid,nodev,noexec,size=32m
  --mount type=bind,source=<私有快照>,target=<容器授权路径>
  --workdir <容器授权路径>
  --entrypoint /usr/bin/env <完整镜像ID>
  -i PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
  HOME=/tmp TMPDIR=/tmp LANG=C.UTF-8 <程序> <参数...>
```

上面是参数数组的展示形式，不能直接用字符串替换后交给 shell。`noexec` 不会阻止解释器读取脚本，不应把它宣传为禁止执行代码。实际编译需要运行临时生成的二进制时，应在明确的任务目录运行。

宿主必须自己实施超时和取消，随后对**该随机专用容器**执行 `docker rm --force` 并核对已不存在。只杀 Docker CLI 可能留下容器。输出流也必须限长，不能通过等待无限输出耗尽宿主内存。

首次支持范围建议明确显示：**网关入口受控制；工具在断网 Linux 快照中执行；客户端原生工具仍可能旁路；结果保存在快照，未自动应用到原工作区。** 这比把整个客户端标为“隔离会话”更符合实际证据。

## 5. 快照和直接挂载的取舍

推荐快照，当前不自动回写原工作区。普通文件复制字节，切断 hardlink 的宿主共享 inode；符号链接保留为链接但不跟随复制；特殊文件、Socket、FIFO、设备以及超出大小／文件数限制的输入明确拒绝。复制时使用不跟随链接的打开方式并核对对象类型，避免复制阶段将链接目标内容带进快照。

直接把宿主目录可写挂入容器仍有两个关键问题：目录内已有 hardlink 可以改变目录外同一 inode 的文件；检查路径之后到 Docker 挂载之前，宿主可将授权根或祖先路径置换。启动前检查不是完整的并发安全边界。因此当前不建议用直接挂载关闭开发计划的链接置换门。

快照结果要真正应用回原工作区，还需要记录原文件摘要，展示创建／修改／删除的差异，独立批准，并在回写时重新核对原对象与摘要；用户编辑发生冲突时不得覆盖。这是后续会话、批准和桌面接入的交付条件，**快照内测试通过不代表回写已实现**。

M0 的固定小文件延迟、启动和网关 RSS 基线另见 [性能基线报告](agd-002-performance-baseline-2026-09-09.zh.md)。三路分别测量，容器配置上限与真实内存测量明确分开。

## 7. 复现与撤销

```bash
python3 scripts/acceptance/agd-isolation-probe.py
python3 scripts/acceptance/agd-isolation-jail.py
node scripts/acceptance/agd-isolation-gateway.mjs --binary /绝对路径/agentguard-mcp --image sha256:7de5789da80158e418d22bf911ea3829aa1abdeb2338dd556dc99b13c89d8490
node scripts/acceptance/agd-isolation-parent-link.mjs --binary /绝对路径/agentguard-mcp
```

后端 probe／jail 脚本只使用指定本地镜像；jail 脚本仅把构建用 Rust 源码和清单复制入临时目录，Cargo registry 只读挂载，保持 `--offline --locked`，不会挂载账户配置或 Cargo 凭据。每次使用新的证据目录。运行结束清理自己创建的容器和临时目录，保留报告；如控制进程遭到强制杀死，需要根据报告里的随机容器名核对残留，禁止批量清理其它项目容器。

开发阶段曾出现两次脚本问题：镜像 `rust:1.91` 实际安装 1.91.1，指定 1.91.0 会尝试工具链同步，已改为准确版本；扩展测试脚本的引号错误已修正。构建清单／锁文件不一致时保持拒绝，失败记录未改为成功。

**结论：建议采用“Docker Linux VM + 默认断网 + 私有快照”作为首个工具执行后端；目前有真实后端约束和 MCP 工具接入证据，尚不能宣称整个 Agent 客户端、完整 M1 或发布条件已经满足。**
