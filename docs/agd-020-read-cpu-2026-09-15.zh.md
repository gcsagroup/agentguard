# AGD-020：内容检测复用与开发构建优化

日期：2026-09-15。**内容与审计回归通过，性能仍未通过；AGD-020 继续实施。** 五个诊断版本均保留原始结果，最新版本本机读取 p95 为 20.72 ms，高于原 10 ms 门槛。本批没有构建或替换固定路径的 Ver 2.0（012）App。

## 改动与边界

一次捕获中，已经检测过的文本与可见文本逐字相同时，复用已有的三个检测结果；规范化视图等于原文时也不重复检测。原始字节、解码状态、每个入口和变体的摘要、完整性、64 个视图上限仍逐项生成。比较的是解码后的文本，不据此宣称原始字节相同；不按摘要命中，不跨动作缓存，不保存检测正文。

检测结果是三个布尔值的累积，重复检查相同文本不会改变结果。后续可用视图名额只会减少，因此先前同文本的检测已经覆盖后续可枚举的前缀。新增固定旧算法对照，覆盖 96 种文本、入口、完整性和视图边界组合；原有非法编码、大文件和截断检查保留。

根 workspace 的开发构建统一使用一级优化，JSON 编码与 SQLite 依赖二级优化，已有 SHA 库三级优化保留。Rust 调试断言和整数溢出检查明确开启；release 配置、两次持久提交及同步级别不变。macOS 桌面壳属于独立 workspace，不自动继承根 workspace 的构建配置；其打包网关须在下一候选中单独核对。

## 五版测量全部保留

各版均使用原脚本与冻结预算、相同 1 KiB 输入、每路预热 5 次与正式 30 次。每次检查同一已运行 Linux VM、前后无其他运行容器，复用原镜像，不新增镜像或卷。直接读取、本机网关、隔离网关共 450 个正式样本正文正确，但五版预算结果均为 5/6。

| 版本与累积修改 | 本机读取 p95 | 本机读取 p50 | 本机启动 |
| --- | --- | --- | --- |
| 01：网关一级优化 | 11.55 ms | 11.11 ms | 60.50 ms |
| 02：增加相同文本检测复用 | 12.05 ms | 10.42 ms | 66.26 ms |
| 03：增加来源、隐私、审计一级优化 | 12.01 ms | 10.00 ms | 63.19 ms |
| 04：增加 JSON 与 SQLite 二级优化 | 10.21 ms | 9.98 ms | 42.18 ms |
| 05：统一开发构建一级优化，保留上述专项优化 | 20.72 ms | 15.79 ms | 62.27 ms |

第五版冻结网关：`7d59a2e3303fe88ba4aed5698a05c0f0822c362eff34dbf41aaa87076a491342`。本机 RSS 13.31 MiB；隔离读取 p95 327.83 ms、启动 703.75 ms、RSS 13.66 MiB。启动、隔离读取和 RSS 五项均满足原预算，唯一本机读取 p95 未达标。各二进制在正式计时前已经运行功能或故障测试；启动每路仅一个样本，不称首次落地启动或 VM 冷启动。

第五版测量开始的一分钟系统负载为 10.16，前四版约为 3.16～4.23。该差异只能说明测量条件有波动，不能证明哪项修改导致变化，也不能据此删除失败。后续预先固定顺序进行六轮有／无 RSS 定时采样交替诊断，共 180 个样本；两种方式均出现长尾，未证明采样器是原因，原基准脚本保持不变。诊断中低于门槛的样本不改记正式通过。

同卷存储诊断中，每次两次强制同步的 p95 为 8.12 ms，优化 SQLite 的两次持久事务为 8.17 ms。这是定位同步成本的独立实验，不是网关验收，也不能把同步成本从正式时延中扣除。
