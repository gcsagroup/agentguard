# AGD-031：STIX 2.1 本地导入／导出（2026-09-22）

日期：2026-09-22。没有外部接收方，因此没有外发，也没有把内部提交写成外部互操作验收。

## 做了什么

`guard-intel::stix` 把知识库目录导出为本地 STIX 2.1 bundle，并可以把该 bundle 读回：

- 手法 → `attack-pattern`，完整手法放在 `x-gcsa-technique`，产品覆盖放在 `x-gcsa-coverage`
- 案例 → `report`，完整案例放在 `x-gcsa-case`；没有手法也没有 IOC 时，用 `x-gcsa-case-anchor` 保住引用
- IOC → `indicator` 加对应可观察对象，权威字段是 `x-gcsa-observable`
- 缓解 → `course-of-action`，并用 `mitigates` 连到手法
- 对象上的未知字段原样保留；`*_ref` / `*_refs` 对不上就拒绝，不静默丢掉
- bundle 标明 `x-gcsa-authorization-effect=none`、`x-gcsa-delivery=local-only`

命令只读写指定文件，不改 `intel/bundle.json`，不联网：

```text
cargo run -p guard-cli -- stix-export --out /tmp/agentguard-stix.json
cargo run -p guard-cli -- stix-import --bundle /tmp/agentguard-stix.json --out /tmp/agentguard-stix-roundtrip.json
```

## 验证

`cargo test -p guard-intel --offline --lib -- stix`：2 项通过。目录往返后手法、案例、缓解与扩展覆盖一致；补上的域名 IOC、`x-partner-note` 和 `foreign_field` 仍在；悬空 `created_by_ref` 被拒绝。`cargo clippy -p guard-intel -p guard-cli --all-targets -- -D warnings` 通过。
