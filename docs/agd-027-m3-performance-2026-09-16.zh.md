# AGD-027：读取性能定位与审计序号索引

日期：2026-09-16。状态：**修正了已复现的日志规模开销；整个性能验收仍未通过**。本项不缩减 M3 联合验收，不改变 F13 暂缓及发布 No-Go。

## 已观察到的原因

对原冻结 CLI `a250be2538a199d3a01124ba55d01213ce0333e00df92697124392ccc696d761` 做 5 秒本机采样和 1,000 次正常文件读取。主线程 4,062 个采样点中，`next_seq` 的两个调用点分别出现 265 和 260 次，合计约 12.9%；大量剩余等待落在 SQLite 提交同步调用。这是采样占比，不是精确单次耗时分账。

`next_seq` 使用 `MAX(seq)`，事件表和回执表都没有序号索引，导致每次追加扫描全部历史。独立回归在 2,048 条记录上复现 **2,047 次 FullscanStep**，修正后两张表均为 **0**，返回的下一个序号仍为 2,049。没有把运行变慢全部归因于同机编译负载。

隔离执行另用限定 Docker 包装器观察 35 次正常文件操作（5 次预热、30 次测量）；`docker run` 中位数约 200 ms，清理约 13 ms。包装器有额外启动开销，该轮不能算作原预算通过，也不能直接与没有包装器的轮次相减。第一次诊断因包装器依赖被网关清除的环境变量而未启动隔离路由，原失败报告保留；改为宿主固定日志路径后，仅补测缺失的隔离部分。

本项只构建 CLI，固定 App 仍为 020，包内网关仍保持原字节；没有重新打包或改变已授权 App 的身份。新索引 CLI 冻结在 `.artifacts/m3-performance-diagnosis-2026-09-16/frozen-indexed-01/`，SHA-256 为 `a527a5ed53395303b3311411afa5c684e19d063bf0b52ee97c6b2f25c4e1878c`。对原冻结的 211 项输入，仅 `crates/guard-audit/src/store.rs` 改变。

## 后续容器生命周期定位

同一索引候选另做一次带命令计时包装器的限定诊断，仅运行隔离读取路由；5 次预热及 30 次测量均返回正确正文。实际收集 36 个自有容器的 180 个生命周期事件，包含启动探测；其它容器记录没有纳入。正式测量容器的创建至启动中位数 95.079 ms、运行至退出 51.153 ms、退出至销毁 22.727 ms；`docker run` 命令中位数 283.597 ms，额外清理命令 17.875 ms。生命周期间隔来自同一 daemon 时钟，不把宿主与虚拟机绝对时钟相减。

本次诊断读取 p95 为 429.956 ms，但启动为 4,288.018 ms，其中首次能力探测的 `docker run` 耗时 3,111.665 ms。包装器增加进程，该轮不是原三路由预算验收，更不能选择其较低的读取值覆盖此前失败。证据位于 `.artifacts/m3-runtime-timing-2026-09-16/`，说明容器生命周期与首次启动存在开销，尚未单独解释原生持久化延迟。AGD-027 保持开发中；在它的门槛未通过时，按用户整个计划的目标继续实施已满足 AGD-020 依赖的 AGD-028，不将扩展任务记为 M3 通过。
